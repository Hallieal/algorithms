Closest Pair of Points

Use two sorted views of the same points to turn an all-pairs geometric search into O(n log n).

HardDivide & conquerGeometry

Problem

Checking every pair is easy but quadratic. The challenge is to prove that most pairs can never be the closest one.

Task

Find the minimum Euclidean distance

Given n ≥ 2 distinct points in the plane, find the minimum Euclidean distance between any two points and return one pair attaining it.

d(p,q) = √((pₓ−qₓ)² + (pᵧ−qᵧ)²)
Geometric picture
purple band = strip of width 2dred points = cross-half candidate

Core idea

Solve the two halves recursively. Once we know their best distance d, any better pair that crosses the split is forced into a narrow strip.

The divide-and-conquer reduction

Only the strip can still improve the answer

Sort points by x-coordinate and split them into left and right halves. Let d be the smaller of the two recursive answers. If a cross-half pair has distance below d, its horizontal separation is below d, so both endpoints must lie within distance d of the split line.

left answerall pairs entirely in the left half are already handled
right answerall pairs entirely in the right half are already handled
striponly cross-half pairs can still beat d
sort by x

Gives a balanced geometric split for recursion.

sort by y

Lets us scan strip candidates in vertical order without sorting again.

next 15

A packing argument makes the strip scan linear rather than quadratic.

Why at most fifteen following points?

Fix a strip point p. A point q can beat the current distance d only if it lies less than d above p. So all relevant following candidates lie in a rectangle of width 2d and height d. Divide that rectangle into eight d/2 × d/2 cells. Two points from the same recursive half cannot occupy one cell: the cell diameter is d/√2 < d, contradicting the recursive answer for that half. A cell can therefore contain at most two points — one from each half. Across eight cells there are at most sixteen points including p, so at most fifteen following candidates need to be checked. The classical analysis can sharpen this constant to seven with a tighter packing argument, but fifteen is already sufficient for the same O(n log n) running time.

Algorithm

1

Presort twice

Keep the same points ordered by x-coordinate and by y-coordinate.

2

Split by x

Divide the x-order in half and partition the y-order into the same two point sets.

3

Recurse

Find the best pair in each half and let d be the smaller distance.

4

Scan the strip

Keep strip points in y-order; for each one, test at most the next fifteen points.

I

Recursive invariant

Every call receives exactly the same subset of points in two orders — x-sorted and y-sorted — and returns the true closest pair inside that subset.

Correctness & complexity

✓

Every possible closest pair falls into one of three cases

It lies completely on the left, completely on the right, or crosses the split. The algorithm handles all three.

1

Same-half pairs

The recursive calls return the exact closest distances in the left and right halves by induction.

2

Cross-half pairs

Any cross pair closer than d must have both endpoints inside the strip, so it appears in the y-sorted strip list.

3

The strip scan is complete

The packing lemma proves that, for each strip point, every possible partner closer than d is among the next fifteen points in y-order. Therefore no improving cross pair is skipped.

Initial sortingO(n log n)

One x-sort and one y-sort.

RecursionO(n log n)

Each level performs O(n) total partition and strip work.

Extra spaceO(n)

The y-partitions, membership sets, and strip lists use linear peak storage.

Implementation

The code keeps squared distances during recursion, avoiding repeated square roots. The square root is taken only once for the final answer.

Python
from math import sqrt


def closest_pair(points):
    if len(points) < 2:
        raise ValueError("at least two points are required")

    pts = [(x, y, i) for i, (x, y) in enumerate(points)]
    px = sorted(pts, key=lambda p: (p[0], p[1], p[2]))
    py = sorted(pts, key=lambda p: (p[1], p[0], p[2]))

    def dist2(p, q):
        dx = p[0] - q[0]
        dy = p[1] - q[1]
        return dx * dx + dy * dy

    def solve(px, py):
        n = len(px)
        if n <= 3:
            best2 = float("inf")
            pair = None
            for i in range(n):
                for j in range(i + 1, n):
                    current = dist2(px[i], px[j])
                    if current < best2:
                        best2 = current
                        pair = (px[i], px[j])
            return best2, pair

        mid = n // 2
        left_x = px[:mid]
        right_x = px[mid:]
        split_x = (left_x[-1][0] + right_x[0][0]) / 2

        left_ids = {p[2] for p in left_x}
        left_y, right_y = [], []
        for p in py:
            if p[2] in left_ids:
                left_y.append(p)
            else:
                right_y.append(p)

        dl2, pair_l = solve(left_x, left_y)
        dr2, pair_r = solve(right_x, right_y)

        if dl2 <= dr2:
            best2, pair = dl2, pair_l
        else:
            best2, pair = dr2, pair_r

        strip = [
            p for p in py
            if (p[0] - split_x) ** 2 < best2
        ]

        for i in range(len(strip)):
            for j in range(i + 1, min(i + 16, len(strip))):
                dy = strip[j][1] - strip[i][1]
                if dy * dy >= best2:
                    break

                current = dist2(strip[i], strip[j])
                if current < best2:
                    best2 = current
                    pair = (strip[i], strip[j])

        return best2, pair

    best2, pair = solve(px, py)
    clean_pair = tuple((p[0], p[1]) for p in pair)
    return sqrt(best2), clean_pair


points = [
    (2, 3), (12, 30), (40, 50),
    (5, 1), (12, 10), (3, 4),
]
print(closest_pair(points))
Reading the code

Preserve both orders

left_ids

Partitions the y-sorted list into exactly the same point sets as the x-sorted split without re-sorting.

strip

Filters the already y-sorted list, so strip points automatically remain in y-order.

min(i + 16, ...)

Checks at most fifteen following points, exactly as guaranteed by the packing lemma used on this page.
