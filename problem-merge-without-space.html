Merge Without Extra Space

Separate the values that belong on each side, then restore order without allocating a merge buffer.

HardIn-place mergingPython

Problem

Ordinary merging is linear because it writes into a third array. Here that temporary output array is forbidden.

Task

Merge while keeping the two original arrays

Arrays a and b are individually sorted. Rearrange their existing elements so that a contains the smallest len(a) values and b contains the rest, with both arrays sorted. Use only constant auxiliary memory.

max(a) ≤ min(b), and each array is sorted

Core idea

Do not try to maintain full sorted order while values cross between arrays. First solve the easier problem: put the correct set of values on each side. Then sort each side in place.

Cross-boundary separation

Compare the largest candidates from a with the smallest candidates from b

Let r = min(n, m). Walk inward through the last r positions of a and the first r positions of b. For every pair, keep the smaller value on the a side and the larger value on the b side.

20 ↔ 2

2 belongs on the left side; 20 belongs on the right side.

15 ↔ 3

9 ↔ 13

Already correctly separated, so no swap is needed.

Important: after these cross-boundary exchanges the arrays are generally not internally sorted. What we have established is the stronger separation property needed for the merge: every value in a is no larger than every value in b. We then sort each side independently.

Algorithm

1

Pair the boundary values

For t = 0, …, r−1, compare a[n−1−t] with b[t].

2

Send smaller left

If the value from a is larger, swap the pair.

3

Sort a in place

Use heapsort so no auxiliary array proportional to n is created.

4

Sort b in place

Heapsort the right side as well. The separation property guarantees the concatenation is globally sorted.

I

What the cross phase guarantees

After all r pairwise compare-exchanges, the multiset in a consists of the smallest n values of the combined input, and the multiset in b consists of the remaining m values.

Correctness & complexity

Why the cross phase really separates the two sides

Read the compared suffix of a from right to left: it is non-increasing. Read the compared prefix of b from left to right: it is non-decreasing. Therefore the difference between the paired values can change sign at most once. Before that crossing, the b value is the smaller member of each pair; after it, the a value is the smaller member. Hence all minima sent to the left lie at or below the crossing boundary, while all maxima sent to the right lie at or above it. Any unpaired prefix of a is even smaller, and any unpaired suffix of b is even larger. Thus every final value in a is no larger than every final value in b.

✓

Sorting each side finishes the merge

Once the value sets are separated, no element ever needs to cross the boundary again.

1

No values are lost

The cross phase uses only swaps, so the combined multiset is unchanged.

2

The boundary is correct

The separation argument gives max(a) ≤ min(b) after the cross phase, even though each side may be internally scrambled.

3

Independent sorting is sufficient

Heapsort orders each side without changing which values it contains. Therefore a + b is the globally sorted merge.

Cross phaseO(min(n,m))

Exactly one comparison per paired boundary position.

SortingO(n log n + m log m)

Each array is heapsorted in place.

Extra spaceO(1)

Heapsort and the cross phase use only indices and swap temporaries.

Implementation

The custom heapsort matters here: Python's built-in list.sort() is excellent in practice, but it does not satisfy a strict O(1)-auxiliary-space requirement.

Python
def heap_sort(a):
    n = len(a)

    def sift_down(root, size):
        while True:
            child = 2 * root + 1
            if child >= size:
                return

            if (child + 1 < size and
                    a[child + 1] > a[child]):
                child += 1

            if a[root] >= a[child]:
                return

            a[root], a[child] = a[child], a[root]
            root = child

    for root in range(n // 2 - 1, -1, -1):
        sift_down(root, n)

    for end in range(n - 1, 0, -1):
        a[0], a[end] = a[end], a[0]
        sift_down(0, end)


def merge_without_extra_space(a, b):
    r = min(len(a), len(b))

    for t in range(r):
        i = len(a) - 1 - t
        j = t
        if a[i] > b[j]:
            a[i], b[j] = b[j], a[i]

    heap_sort(a)
    heap_sort(b)
    return a, b


a = [1, 5, 9, 10, 15, 20]
b = [2, 3, 8, 13]
print(merge_without_extra_space(a, b))
# ([1, 2, 3, 5, 8, 9], [10, 13, 15, 20])
Reading the code

Two independent responsibilities

Cross compare-exchange

Moves each pair's smaller value to a and larger value to b, establishing the correct partition of values.

heap_sort(a)

Restores internal order on the left without allocating a second array.

heap_sort(b)

Does the same on the right; the already-correct boundary then makes the whole merge sorted.
