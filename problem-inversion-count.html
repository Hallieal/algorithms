Inversion Count

Count out-of-order pairs while Merge Sort is already comparing the two sorted halves.

MediumSorting practicePython

Problem

Task

For an array a, an inversion is a pair of indices i < j with a[i] > a[j]. Count the total number of inversions.

Example
24135
Inversions: (2,1), (4,1), (4,3) → answer = 3

Key idea

The observation

Inside each half, recursive calls count all internal inversions. During the merge, suppose the next right-half value is smaller than the next left-half value. Because the left half is sorted, that right value is smaller than every remaining left value. One comparison therefore reveals a whole block of inversions at once.

The counting moment
247
remaining left half
vs
38
3 is smaller than 4, so it forms 2 inversions: (4,3) and (7,3)

Algorithm

1

Divide

Split the array into left and right halves.

2

Count recursively

Count inversions entirely inside the left half and entirely inside the right half.

3

Merge

Merge the two sorted halves exactly as in Merge Sort.

4

Count cross inversions

Whenever a right-half value is chosen before the current left-half value, add the number of left-half values that remain.

5

Combine

Return left inversions + right inversions + cross inversions.

Invariant

During a merge, the output prefix is sorted, and the inversion counter already includes every cross inversion involving an element that has been copied into that prefix.

Why it works

Correctness argument

Recursive calls count all inversion pairs whose two indices lie in the same half. The only missing pairs cross the midpoint. During merging, if left[i] ≤ right[j], then left[i] creates no inversion with any remaining right value. If right[j] < left[i], sortedness of the left half implies right[j] is smaller than every value from left[i] onward, creating exactly mid - i cross inversions. Hence every inversion is counted once and only once.

Complexity

TimeO(n log n)

The recurrence is the same as Merge Sort: two half-size calls plus linear merging.

Extra spaceO(n)

A temporary array is reused for merge operations.

Naive comparisonO(n²)

Checking every pair is unnecessary once sorted halves expose many inversions at once.

Python implementation

Python
def count_inversions(values):
    a = list(values)
    temp = [0] * len(a)

    def sort_and_count(lo, hi):
        if hi - lo <= 1:
            return 0

        mid = (lo + hi) // 2
        inversions = sort_and_count(lo, mid)
        inversions += sort_and_count(mid, hi)

        i, j, out = lo, mid, lo

        while i < mid and j < hi:
            if a[i] <= a[j]:
                temp[out] = a[i]
                i += 1
            else:
                temp[out] = a[j]
                j += 1
                inversions += mid - i
            out += 1

        while i < mid:
            temp[out] = a[i]
            i += 1
            out += 1

        while j < hi:
            temp[out] = a[j]
            j += 1
            out += 1

        a[lo:hi] = temp[lo:hi]
        return inversions

    return sort_and_count(0, len(a))


print(count_inversions([2, 4, 1, 3, 5]))  # 3
