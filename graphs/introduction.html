Introduction to Graphs

Graphs describe connections. A map of bus routes, a group of friends, and a record of who owes whom can all be drawn as graphs.

Spell checkingFind a real word requiring the fewest edits.
Social networksFind the closest doctor in your network.
Web crawlingFollow links from page to page.

Start with a real problem

Suppose you want to get from Twin Peaks to the Golden Gate Bridge by bus, with as few transfers as possible. There are several routes. Which one uses the fewest steps?

Look first at the places one step away from Twin Peaks, then those two steps away. The bridge first appears at three steps. So a three-step route is shortest; there is no need to inspect a four-step route first.

Shortest-path problem. “Shortest” does not have to mean physical distance. It can mean fewest transfers, fewest edits, fewest links, or any other quantity represented by steps in a graph.

The route map is a graph. Breadth-first search will give us a systematic way to examine it in exactly this order: one step away, then two, then three.

A graph can model who owes whom

A graph can also record debts after a poker game. If Alex owes Rama, draw an arrow from Alex to Rama. If Rama owes Adit, draw an arrow from Rama to Adit.

The people are the nodes; the arrows are the edges. Because a debt has a direction, these edges are directed.

Vertices and edges

A graph consists of vertices (or nodes) and edges. An edge joins two vertices. Vertices joined directly by an edge are adjacent, or neighbors.

Vertex: one object, such as a person, station, or web page.

Edge: one direct connection, such as a friendship or road.

Neighbors: vertices connected directly by an edge. Here u has neighbors v and w; x is not a neighbor of u.

Example: a social network

Consider a social network. Since friendship is mutual, we can begin by storing each friendship as a pair:

Python
friendships = [
    ["Alice", "Bob"],
    ["Bob", "Cynthia"],
    ["Alice", "Diana"],
    ["Bob", "Diana"],
    ["Elise", "Fred"],
    ["Diana", "Fred"],
    ["Fred", "Alice"],
]

This works, but it is awkward for questions such as “Who are Alice's friends?” Alice can occur anywhere in the list, so we have to scan it. It is more useful to store each person together with that person's neighbors.

Python
friends = {
    "Alice": ["Bob", "Diana", "Fred"],
    "Bob": ["Alice", "Cynthia", "Diana"],
    "Cynthia": ["Bob"],
    "Diana": ["Alice", "Bob", "Fred"],
    "Elise": ["Fred"],
    "Fred": ["Alice", "Diana", "Elise"],
}

print(friends["Alice"])
# ['Bob', 'Diana', 'Fred']

Now Alice's neighbors are available directly with friends["Alice"]. The dictionary maps each person to the people adjacent to that person. This is the basic idea behind an adjacency list, which we will study carefully in the representation section.

Graphs and trees

A tree is a graph, but a graph need not be a tree. A tree has no cycles and is connected. General graphs may violate either condition.

For example, Alice → Diana → Bob → Alice returns to its starting point. That is a cycle, so this social graph is not a tree.

Connected and disconnected graphs

Graphs may also be disconnected. In the picture below there are two separate pairs, plus Vicky, who has no neighbors.

A graph is connected if every vertex can be reached from every other vertex. Otherwise it is disconnected.

Directed graphs

Some relationships are one-way. Alice may follow Bob even if Bob does not follow Alice. We represent such a relation with a directed edge, drawn as an arrow.

Python
followees = {
    "Alice": ["Bob", "Cynthia"],
    "Bob": ["Cynthia"],
    "Cynthia": ["Bob"],
}

Incoming and outgoing neighbors

For an edge u → v, v is an out-neighbor of u, and u is an in-neighbor of v. A longer path does not make its endpoints neighbors; neighbors are connected by one edge.
