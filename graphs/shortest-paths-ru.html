Кратчайшие пути

BFS работает с единичными стоимостями рёбер. Для неотрицательных весов используется алгоритм Дейкстры.

Длина пути

Путь называется кратчайшим, если его суммарная стоимость минимальна. Что именно считать стоимостью, зависит от задачи.

Без весов

Все рёбра имеют одинаковую стоимость. Минимизируем число рёбер.

BFS
Неотрицательные веса

Стоимость рёбер может различаться, но отрицательных весов нет.

Dijkstra
Отрицательные веса

Более дешёвый маршрут может обнаружиться уже после решения, казавшегося окончательным.

Bellman–Ford

Для взвешенного пути P=(v₀,v₁,…,vₖ), its length is the sum of its edge weights:

length(P) = w(v₀,v₁) + w(v₁,v₂) + ··· + w(vₖ₋₁,vₖ)

BFS как случай единичных весов

Если вес каждого ребра равен 1, стоимость пути — просто число рёбер. BFS решает эту задачу за Θ(n+m) времени. При разных весах порядок обнаружения вершин уже не определяет минимальную стоимость пути.

Используйте самый простой алгоритм, подходящий к весам. Для невзвешенного графа BFS проще и быстрее алгоритма Дейкстры.

Предварительные расстояния

Алгоритм Дейкстры хранит предварительное значение d[v] для каждой вершины — длину лучшего найденного на данный момент пути до v Изначально

d[s] = 0     and     d[v] = ∞ for v ≠ s

Алгоритм также поддерживает множество S зафиксированных вершин. Как только вершина попадает в S, its distance is final.

Релаксация ребра

Пусть известен путь до u длины d[u] и существует ребро u→v веса w(u,v). Going through u даёт новый кандидат на расстояние до v.

d[u]+w(u,v)<d[v]?
d[v] ← min(d[v], d[u] + w(u,v))

Если значение улучшилось, запоминаем u как parent[v]. В итоге указатели на родителей образуют дерево кратчайших путей с корнем в источнике.

Жадный шаг Дейкстры

Среди всех незафиксированных вершин выбираем вершину с минимальным предварительным расстоянием. Фиксируем её и релаксируем все исходящие рёбра.

Алгоритм

import heapq

def dijkstra(graph, start):
    distance = {u: float("inf") for u in graph}
    parent = {start: None}
    distance[start] = 0
    heap = [(0, start)]

    while heap:
        dist_u, u = heapq.heappop(heap)

        if dist_u != distance[u]:
            continue

        for v, weight in graph[u]:
            new_dist = dist_u + weight

            if new_dist < distance[v]:
                distance[v] = new_dist
                parent[v] = u
                heapq.heappush(heap, (new_dist, v))

    return distance, parent

В Python у heapq нет операции decrease-key, поэтому при улучшении расстояния в кучу добавляется новая запись. Когда старая запись позже окажется на вершине, проверка равенства её пропустит.

Небольшой пример

Пусть источник — A, а рёбра имеют веса A–B: 6, A–C: 1, C–B: 2, B–D: 2, C–D: 7.

СтартA 0B ∞C ∞D ∞
Фиксируем AA 0B 6C 1D ∞
Фиксируем CA 0B 3C 1D 8
Фиксируем BA 0B 3C 1D 5
Фиксируем DA 0B 3C 1D 5

Ключевое обновление происходит для B: прямой путь A→B стоит 6, но после фиксации C релаксация C→B заменяет это значение на 1+2=3.

Корректность алгоритма Дейкстры

Главный инвариант:

всякий раз, когда вершина u фиксируется, d[u] равно истинному расстоянию кратчайшего пути от s до u.

Рассмотрим незафиксированную вершину v с минимальным предварительным расстоянием и предположим, что существует более короткий путь до v. В какой-то момент этот путь должен выйти из множества зафиксированных вершин. Пусть x→y — первое такое ребро. Когда x обрабатывалась, алгоритм Дейкстры уже рассмотрел путь через это ребро. Поскольку веса неотрицательны, продолжение пути из y не может уменьшить его стоимость. Значит, такой путь не может оказаться дешевле минимального предварительного расстояния, выбранного для v.

Отрицательные веса

Алгоритм Дейкстры опирается на неотрицательность весов: продолжение пути не может сделать его дешевле. При отрицательных рёбрах это рассуждение ломается. Стандартная альтернатива — алгоритм Беллмана—Форда, если отрицательные рёбра разрешены и нет достижимого отрицательного цикла, из-за которого кратчайший путь не определён.

Прибавление одной и той же константы ко всем рёбрам не устраняет проблему отрицательных весов. Пути с разным числом рёбер получают разные суммарные добавки, поэтому сам кратчайший путь может измениться.

Время работы

При списках смежности и двоичной куче происходит O(m) успешных обновлений расстояний, а операции с кучей стоят O(log n). Стандартная оценка:

O((n + m) log n)

часто записывают как O(m log n) для связного графа. Простая реализация на массиве работает за O(n²+m), usually summarized as O(n²)
