Shortest Paths

BFS handles unit edge costs. For nonnegative weights, use Dijkstra's algorithm.

Path Length

A path is shortest when its total cost is minimum. What counts as cost depends on the graph.

Unweighted

Every edge has the same cost. Minimize the number of edges.

BFS
Nonnegative weights

Edges may have different costs, but none is negative.

Dijkstra
Negative weights

A cheaper route may appear after an apparently final choice.

Bellman–Ford

For a weighted path P=(v₀,v₁,…,vₖ), its length is the sum of its edge weights:

length(P) = w(v₀,v₁) + w(v₁,v₂) + ··· + w(vₖ₋₁,vₖ)

BFS is the unit-weight case

If every edge has weight 1, path cost is simply the number of edges. BFS already solves this problem in Θ(n+m) time. With unequal weights, discovery order no longer determines minimum path cost.

Use the simplest algorithm that fits the weights. For an unweighted graph, BFS is simpler and faster than Dijkstra.

Tentative distances

Dijkstra maintains a tentative value d[v] for every vertex: the best path length to v found so far. Initially,

d[s] = 0     and     d[v] = ∞ for v ≠ s

The algorithm also maintains a set S of settled vertices. Once a vertex enters S, its distance is final.

Relaxing an edge

Suppose we know a route to u of length d[u] and there is an edge u→v of weight w(u,v). Going through u gives a candidate route to v.

d[u]+w(u,v)<d[v]?
d[v] ← min(d[v], d[u] + w(u,v))

If the value improves, record u as parent[v]. These parent pointers eventually form a shortest-path tree rooted at the source.

Dijkstra's greedy step

Among all unsettled vertices, choose one with minimum tentative distance. Settle it, then relax all of its outgoing edges.

The algorithm

import heapq

def dijkstra(graph, start):
    distance = {u: float("inf") for u in graph}
    parent = {start: None}
    distance[start] = 0
    heap = [(0, start)]

    while heap:
        dist_u, u = heapq.heappop(heap)

        if dist_u != distance[u]:
            continue

        for v, weight in graph[u]:
            new_dist = dist_u + weight

            if new_dist < distance[v]:
                distance[v] = new_dist
                parent[v] = u
                heapq.heappush(heap, (new_dist, v))

    return distance, parent

Python's heapq has no decrease-key operation, so an improved distance is pushed as a new entry. When an obsolete entry later reaches the top, the equality check skips it.

A small run

Suppose the source is A and the edges are A–B: 6, A–C: 1, C–B: 2, B–D: 2, C–D: 7.

StartA 0B ∞C ∞D ∞
Settle AA 0B 6C 1D ∞
Settle CA 0B 3C 1D 8
Settle BA 0B 3C 1D 5
Settle DA 0B 3C 1D 5

The important update is B: the direct route A→B costs 6, but after C is settled, relaxing C→B replaces it by 1+2=3.

Correctness of Dijkstra's Algorithm

The central invariant is:

Whenever a vertex u is settled, d[u] equals the true shortest-path distance from s to u.

Consider the unsettled vertex v with smallest tentative distance, and imagine a supposedly shorter path to v. That path must at some point leave the settled set. Let x→y be its first edge from a settled vertex to an unsettled one. When x was processed, Dijkstra considered the route through this edge. Because edge weights are nonnegative, continuing from y cannot make the path cheaper. Thus this alternative cannot beat the minimum tentative distance chosen for v.

Negative Edge Weights

Dijkstra relies on nonnegative edge weights: extending a path cannot make it cheaper. With negative edges this argument fails. Bellman–Ford is a standard alternative when negative edges are allowed and no reachable negative cycle makes the shortest path undefined.

Adding the same constant to every edge does not fix negative weights. Paths with different numbers of edges receive different total additions, so the identity of the shortest path can change.

Running time

With adjacency lists and a binary heap, there are O(m) successful distance updates and heap operations cost O(log n). A standard bound is

O((n + m) log n)

often written O(m log n) for a connected graph. A simple array-based implementation takes O(n²+m), usually summarized as O(n²) for dense graphs.
