Shortest Paths

Graphs turn problems about connections, routes, and dependencies into standard algorithmic models.

Choose by edge weights

“Shortest path” is not one algorithm. The right method depends on what weights are allowed.

GraphAlgorithmTime
Unweighted / equal weightsBFSO(V + E)
Nonnegative weightsDijkstra + heapO((V + E) log V)
Negative edges, no negative cycleBellman–FordO(VE)
DAG, arbitrary weightsTopological relaxationO(V + E)

The common operation: relaxation

Shortest-path algorithms repeatedly ask whether going through u improves the best known route to v.

if dist[u] + w(u,v) < dist[v], update dist[v]

The algorithms differ mainly in the order in which they relax edges and in when a distance can be considered final.

Dijkstra's algorithm

Maintain tentative distances and repeatedly finalize the not-yet-finalized vertex with the smallest tentative distance. With nonnegative weights, no later path can make that finalized distance smaller.

import heapq

def dijkstra(graph, start):
    dist = {u: float("inf") for u in graph}
    dist[start] = 0
    pq = [(0, start)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue

        for v, w in graph[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    return dist
Negative edges break Dijkstra. A vertex that looked final can later receive a cheaper path through a negative edge. Use Bellman–Ford or exploit DAG structure instead.
