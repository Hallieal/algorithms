Network Flow

A flow network asks how much can be routed from a source to a sink when every connection has limited capacity.

Flow networks

Take a directed graph. Designate one vertex as the source s, another as the sink t, and attach a nonnegative capacity to every directed edge.

G = (V,E)directed network
c(u,v)capacity of an edge
f(u,v)flow sent through it
|f|total source-to-sink flow

A capacity is an upper bound, not a distance or a cost. If c(u,v)=7, at most seven units may pass from u to v. The units may represent water, cars, packets, products, jobs, or simply an abstract resource.

What you need before this page: directed graphs, paths, adjacency lists, and BFS/DFS. Dynamic programming, Dijkstra, and minimum spanning trees are not prerequisites.

Feasible flow

A flow is not an arbitrary number on every edge. Two conditions must hold simultaneously.

Capacity constraint

Every edge carries a nonnegative amount and cannot exceed its capacity.

0 ≤ f(u,v) ≤ c(u,v)
Flow conservation

At every intermediate vertex, everything that enters must also leave.

Σu f(u,v) = Σw f(v,w)

The source is allowed to create net outflow, and the sink is allowed to absorb it. Everywhere else, flow is conserved.

The value of a flow is the net amount sent out of the source. By conservation, the same amount enters the sink.

|f| = Σv f(s,v) = Σu f(u,t)

Residual networks

Maximum flow is not found by choosing one path and committing to it forever. An early choice may need to be partly undone. The residual network records exactly what can still be changed.

Residual edges

If an edge has capacity 10 and currently carries 6, then four more units can still be added in the forward direction. The reverse residual edge has capacity 6 because up to six units of the current decision may be cancelled.

Residual capacity. For an original edge u→v, the forward residual capacity is c(u,v)-f(u,v). The reverse residual capacity contributed by that flow is f(u,v).

Why reverse edges matter

This is the key idea. Consider unit capacities in the network below. Suppose the first augmenting path chosen is s→a→b→t.

After rerouting, one unit goes along s→a→t and one along s→b→t. Reverse residual edges are what make a greedy sequence of augmentations correctable.

Ford–Fulkerson

Ford–Fulkerson repeatedly finds an augmenting path: an s–t path in the residual network whose every edge has positive residual capacity.

The amount that can be added along a path is its bottleneck:

Δ = mine∈P cf(e)
1Start with zero flow
2Find an augmenting path
3Take its bottleneck Δ
4Update forward and reverse residual capacities

Then repeat. With integer capacities, every augmentation increases the flow by at least one, so the method terminates. If F is the value of the maximum flow and each path search takes O(E), the basic integer-capacity bound is O(EF).

Ford–Fulkerson does not specify how to choose the augmenting path. Different choices can lead to very different running times. Edmonds–Karp fixes this by always choosing a shortest residual path in number of edges.

Augmentation trace

Return to the six-vertex network from the complete example. One possible sequence of augmentations is:

1
s → a → c → t
Δ = 5

The edge a→c becomes saturated. Total flow: 5.

2
s → b → d → t
Δ = 7

The lower route is filled completely. Total flow: 12.

3
s → a → b → c → t
Δ = 3

The remaining three units reach c through a→b→c. Total flow: 15.

At that point both edges entering t are saturated. There is no residual path from s to t, so the algorithm stops.

Edmonds–Karp

Edmonds–Karp is Ford–Fulkerson with BFS in the residual graph. BFS chooses an augmenting path with the fewest edges.

O(VE²)

The important detail in code is that the adjacency list contains both directions of every original edge. A reverse direction may have zero residual capacity initially, but it can become usable later.

from collections import deque

def edmonds_karp(n, edges, s, t):
    capacity = [[0] * n for _ in range(n)]
    graph = [[] for _ in range(n)]

    for u, v, c in edges:
        capacity[u][v] += c
        graph[u].append(v)
        graph[v].append(u)

    flow = 0

    while True:
        parent = [-1] * n
        parent[s] = s
        q = deque([s])

        while q and parent[t] == -1:
            u = q.popleft()

            for v in graph[u]:
                if parent[v] == -1 and capacity[u][v] > 0:
                    parent[v] = u
                    q.append(v)

        if parent[t] == -1:
            break

        add = float("inf")
        v = t

        while v != s:
            u = parent[v]
            add = min(add, capacity[u][v])
            v = u

        v = t

        while v != s:
            u = parent[v]
            capacity[u][v] -= add
            capacity[v][u] += add
            v = u

        flow += add

    return flow

The matrix stores residual capacities; the adjacency list makes each BFS inspect only actual residual-neighbor candidates. Parallel input edges are handled by adding their capacities.

Maximum flow and minimum cut

An s–t cut divides the vertices into two sets S and T with s∈S and t∈T. Its capacity is the sum of capacities of original edges directed from S to T.

c(S,T) = Σu∈S, v∈T c(u,v)

Every unit that reaches t must cross from the source side to the sink side, so every cut is an upper bound on every feasible flow:

|f| ≤ c(S,T)

The remarkable part is that the best upper bound is always attained.

Max-flow min-cut theorem. The value of a maximum s–t flow equals the capacity of a minimum s–t cut.

Run an augmenting-path algorithm until no residual path from s to t remains.

Let S be the vertices still reachable from s in the residual graph, and let T=V\S. Then t∈T.

Every original edge from S to T is saturated; otherwise that edge would give residual capacity into T. Every original edge from T to S carries zero flow; otherwise its reverse residual edge would lead from S back into T.

Therefore the net flow crossing this cut is exactly its capacity. Since a flow can never exceed a cut, both must be optimal.

Finding a minimum cut

The proof gives the algorithm for free. After the maximum-flow computation ends, perform one final BFS or DFS from s using only edges of positive residual capacity. The reached vertices form S; every other vertex is in T.

This is a useful optimality certificate: a flow of value 15 proves that 15 is achievable; a cut of capacity 15 proves that 16 is impossible.

Bipartite matching as flow

Suppose a bipartite graph has a left side L and a right side R. A matching chooses edges so that no vertex is used twice.

→

Add a source connected to every left vertex with capacity 1, direct every allowed left-to-right edge with capacity 1, and connect every right vertex to the sink with capacity 1.

maximum bipartite matching = maximum flow

Because all capacities are integers, an augmenting-path algorithm produces an integral maximum flow. Every unit of flow through a left-to-right edge corresponds to one matched pair.

Modeling patterns

Many problems that do not mention networks can still be written as flow problems. A few reductions are worth recognizing.

Several sources

Add one super-source and connect it to every original source. Give these new edges the appropriate supply limits.

Several sinks

Add one super-sink and connect every original sink to it.

Vertex capacities

Replace a vertex v by vin→vout. Put the vertex capacity on this new edge.

Edge-disjoint paths

Give every edge capacity 1. The maximum integral flow counts how many edge-disjoint s–t paths can be packed.

One-to-one assignments

Use the bipartite-matching reduction with unit capacities.

Minimum separation

When the task asks for the cheapest set of connections whose removal separates s from t, look for a minimum cut.

What to remember

1. Flow has two constraintsCapacity on each edge; conservation at intermediate vertices.
2. Work in the residual graphForward edges add flow; reverse edges undo earlier choices.
3. Augment by the bottleneckThe smallest residual capacity on the chosen path determines the increase.
4. No residual s–t path means optimalityThe reachable set from s exposes a minimum cut.
5. Max-flow equals min-cutOne object is a feasible construction; the other is a matching upper bound.
6. Matching is a flow problemUnit capacities encode “use each vertex at most once.”

The central picture: repeatedly push flow through residual s–t paths. Reverse residual edges let the algorithm revise old decisions. When no such path remains, the residual graph itself proves that the current flow is maximum.
