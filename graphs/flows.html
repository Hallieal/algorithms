Network Flow

Capacities, feasible flows, residual networks, augmenting paths, maximum flow, minimum cuts, and bipartite matching.

Flow networks

A flow network is a directed graph in which every edge has a capacity. One distinguished vertex is the source s, and another is the sink t.

For every directed edge (u,v), its capacity c(u,v) ≥ 0 is the largest amount that may be sent through that edge.

The interpretation can be physical, but it does not have to be. The “flow” may represent water, traffic, data, goods, assignments, or any other quantity that must move through a network with limited capacity.

Prerequisites: directed graphs, paths, adjacency lists, BFS/DFS, and basic running-time notation. Dynamic programming is not required.

Feasible flow

A flow assigns a number f(u,v) to every edge. Two rules make the assignment feasible.

Capacity

Do not exceed an edge

0 ≤ f(u,v) ≤ c(u,v).

Conservation

Flow does not disappear

For every vertex except s and t, total inflow equals total outflow.

Σu f(u,v) = Σw f(v,w)

Think of an intermediate vertex as a junction. It may redirect flow, but it may not create or destroy it.

Value of a flow

The value of a flow is the total amount leaving the source. By conservation, it is also the total amount entering the sink.

|f| = Σv f(s,v)

The maximum-flow problem asks for a feasible flow with the largest possible value.

Residual networks

A first attempt may send flow along a path that later turns out to be inconvenient. A correct algorithm therefore needs a way to undo earlier choices.

If an edge u → v has capacity 10 and currently carries 6 units, then four more units can still be sent forward. At the same time, up to six units can be cancelled by sending flow backward.

Residual edgeResidual capacityMeaning
u → vc(u,v) − f(u,v)How much more can be added
v → uf(u,v)How much of the current choice can be undone
Reverse residual edges are not extra edges in the original network. They record the possibility of cancelling flow that has already been sent.

Augmenting paths

An augmenting path is a path from s to t in the residual network whose edges all have positive residual capacity.

The amount that can be added along a path P is limited by its smallest residual capacity:

Δ = mine ∈ P cf(e)

If the residual capacities along a path are 7, 4, and 9, then the path can carry four additional units. After augmenting, the residual network is updated and the search begins again.

Ford–Fulkerson

Ford–Fulkerson is a method rather than one fixed path-search rule. Repeatedly find any augmenting path and increase the flow along it.

1Start with zero flow
2Build residual capacities
3Find an s–t path
4Augment by its bottleneck
5Repeat until no path remains

With integer capacities, every augmentation changes the flow by an integer amount, and Ford–Fulkerson terminates with a maximum flow. Its running time depends on how augmenting paths are selected.

Edmonds–Karp: choose augmenting paths with BFS

Edmonds–Karp is Ford–Fulkerson with one precise rule: use BFS in the residual network to find an augmenting path with the fewest edges.

O(VE²)

This bound is independent of the numerical sizes of the capacities. The implementation below stores residual capacities directly.

from collections import deque

def max_flow(capacity, s, t):
    n = len(capacity)
    residual = [row[:] for row in capacity]
    answer = 0

    while True:
        parent = [-1] * n
        parent[s] = s
        q = deque([s])

        while q and parent[t] == -1:
            u = q.popleft()
            for v in range(n):
                if parent[v] == -1 and residual[u][v] > 0:
                    parent[v] = u
                    q.append(v)

        if parent[t] == -1:
            break

        add = float("inf")
        v = t
        while v != s:
            u = parent[v]
            add = min(add, residual[u][v])
            v = u

        v = t
        while v != s:
            u = parent[v]
            residual[u][v] -= add
            residual[v][u] += add
            v = u

        answer += add

    return answer

For sparse graphs, the same idea is usually implemented with adjacency lists rather than scanning every possible vertex pair.

Maximum flow and minimum cut

An s–t cut divides the vertices into two sets S and T with s ∈ S and t ∈ T. The capacity of the cut is the sum of capacities of all original edges going from S to T.

Every unit of flow must cross every s–t cut, so no flow can exceed the capacity of any cut.

max flow = min cut

The max-flow min-cut theorem says that the best possible flow reaches this upper bound exactly. When no augmenting path remains, the vertices still reachable from s in the residual graph form the source side of a minimum cut.

This is both an algorithm and a certificate. A maximum flow shows that the value can be achieved; a cut of the same capacity proves that no larger value is possible.

Bipartite matching as a flow problem

Suppose the vertices are split into a left side and a right side, and we want the largest set of non-conflicting pairs. Turn the matching problem into a flow network.

sourceConnect s to every left vertex with capacity 1
allowed pairDirect each left–right edge with capacity 1
sinkConnect every right vertex to t with capacity 1

Because all capacities are integers, a maximum flow can be chosen integral. Every unit of flow through a left–right edge represents one matched pair.

maximum bipartite matching = maximum flow

This reduction is a useful model to remember: capacities of 1 enforce “use each object at most once.”

Recognizing flow problems

If the problem asks for…Think about…
Largest amount that can pass through limited connectionsMaximum flow
Smallest bottleneck separating two sidesMinimum cut
Largest set of one-to-one assignmentsBipartite matching / flow
Several sourcesAdd a super-source
Several sinksAdd a super-sink
Capacity on vertices rather than edgesSplit each vertex into in/out copies

The main modeling question is not “does the statement mention flow?” It is whether some limited resource must move through a network while obeying capacity and conservation constraints.

Common mistakes

Ignoring reverse edges

Then an early bad choice cannot be corrected.

Using the original graph for every search

Augmenting paths live in the residual graph.

Forgetting conservation

Intermediate vertices cannot create or destroy flow.

Confusing path capacity with path length

The added flow is limited by the bottleneck, not by the number of edges.

Applying BFS to capacities directly

BFS chooses an augmenting path in Edmonds–Karp; it does not by itself solve maximum flow.

Reading a cut in both directions

Cut capacity counts original edges from the source side to the sink side.

The reusable idea

Maximum flow repeatedly routes as much as possible through residual paths, while reverse residual edges allow earlier choices to be revised. When no augmenting path remains, the same residual graph reveals a minimum cut and proves optimality.
