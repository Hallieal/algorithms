Breadth-First Search

BFS explores outward from a source one layer at a time. The layers are exactly the shortest-path distances in an unweighted graph.

Layered Exploration

Breadth-first search starts at a source vertex s and explores outward in all possible directions, adding vertices one layer at a time.

The first layer contains all neighbors of s. The second contains all previously unseen vertices adjacent to the first layer. The third is formed from the second in the same way, and the process continues until no new vertices are found.

L₀={s}. For j≥0, layer Lj+1 consists of the vertices not in an earlier layer that have an edge to a vertex in Lj.

Layers are shortest-path distances

If distance is the minimum number of edges on a path, every vertex in Lj is at distance exactly j from s.

BFS distance property. For every j≥1, Lj consists precisely of the vertices whose distance from s is j. A vertex t is reachable from s if and only if it appears in some BFS layer.

Why? Every vertex placed in Lj is reached by extending a path to Lj−1, so there is a path of j edges. It cannot have a shorter path: if it did, BFS would have encountered it in an earlier layer.

Important: this shortest-path statement counts edges. It applies directly to unweighted graphs, or to graphs in which every edge has the same cost. Different edge weights require a weighted shortest-path algorithm.

The BFS tree

When a previously unseen vertex v is discovered while examining a vertex u, record u as the parent of v. These parent edges form a tree rooted at s.

The unique tree path from s to any reachable vertex uses the minimum possible number of edges. The parent array therefore stores shortest paths from the source.

The BFS Queue

The vertices that have been discovered but not yet explored are kept in a first-in, first-out (FIFO) queue. The oldest discovered vertex is processed first. This is what forces the search to finish the current layer before moving farther from the source.

A vertex should be marked as discovered when it enters the queue, not when it leaves. Otherwise the same vertex can be inserted several times by different neighbors.

The algorithm

from collections import deque

def bfs(graph, start):
    distance = {start: 0}
    parent = {start: None}
    queue = deque([start])

    while queue:
        u = queue.popleft()

        for v in graph[u]:
            if v not in distance:
                distance[v] = distance[u] + 1
                parent[v] = u
                queue.append(v)

    return distance, parent

The dictionary distance also serves as the discovered set. When a vertex first appears there, its shortest distance is fixed. The parent dictionary records the BFS tree.

Reconstructing a shortest path

Suppose BFS starts at s and we want a shortest path to t. Follow parent pointers backward from t until reaching s, then reverse the sequence.

def build_path(parent, start, target):
    if target not in parent:
        return None

    path = []
    v = target

    while v is not None:
        path.append(v)
        v = parent[v]

    path.reverse()
    return path

The BFS tree is tied to its root: to obtain shortest paths from x, BFS must be run with x as the source.

Running time

With an adjacency-list representation, each vertex is discovered at most once and each adjacency-list entry is examined once. Hence BFS runs in

Θ(n + m)

for both directed and undirected graphs. In an undirected graph each edge occurs in two adjacency lists, but this changes only the constant factor. The queue, distance table, and parent table use O(n) additional space.

BFS in directed graphs

The algorithm is essentially unchanged: from u, follow only edges directed out of u. The vertices in layer Lj are precisely those reachable from s by a shortest directed path of j edges.

Reachability need not be symmetric: s may reach t even when t cannot reach s.
