Graph Problem Patterns

Many graph problems are mainly modeling problems: identify the vertices, the edges, and the information that must be carried during traversal.

First: find the graph

The statement may never use the word graph. Objects or states can be vertices; relationships or legal moves can be edges.

People + friendshipssocial network
Courses + prerequisitesdirected graph
Cells + legal movesimplicit grid graph
Words + one-step changesstate graph
Tasks + dependenciesDAG
Locations + costsweighted graph

The graph may be explicit, given as an edge list or adjacency list, or implicit: neighbors are generated from the rules of the problem only when needed.

A graph problem in six questions

1What is a vertex?
2What creates an edge?
3Directed or undirected?
4Weighted or unweighted?
5One component or many?
6What must the output tell us?

These questions usually determine the representation and the relevant algorithm.

Traversal: reachability and exploration

Can I reach it?
→
BFS or DFSvisited set + traversal

If the problem asks whether one state can reach another, which vertices belong to the same connected region, or whether every reachable object has been processed, start with graph traversal.

DFS

Explore a component

Natural when recursion or backtracking matches the structure of the problem.

BFS

Explore by layers

Natural when distance in number of moves matters.

Grids are graphs

A matrix of cells often hides a graph. Each relevant cell is a vertex; edges connect cells that the rules allow you to move between. For four-directional movement, the potential neighbors of (r,c) are (r−1,c), (r+1,c), (r,c−1), and (r,c+1).

def dfs(r, c):
    if not inside(r, c) or grid[r][c] != 1:
        return

    grid[r][c] = 0

    for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
        dfs(r + dr, c + dc)

Instead of a separate visited set, a grid problem can sometimes mark a cell directly in the input. Whether mutating the input is acceptable depends on the problem.

Fewest moves: think BFS

Fewest unweighted steps?
→
BFSfirst arrival gives minimum number of edges

This includes problems that look unlike ordinary graphs: minimum transformations between strings, minimum moves in a puzzle, minimum transfers, or minimum steps through a maze. The state is the vertex; one legal operation creates an edge.

Do not build the whole graph unless you need it. For a large state space, generate neighbors when a state is removed from the BFS queue.

Weighted routes: inspect the edge costs

all costs = 1BFS
costs ≥ 0Dijkstra
DAGtopological relaxation
negative edgesnot Dijkstra

Choosing a shortest-path algorithm begins with the weight structure, not with the word “shortest.”

Dependencies: think DAG

Must some items come before others?
→
Topological sortand cycle detection

Course prerequisites, build dependencies, task scheduling, and dependency resolution all fit this pattern. A topological ordering exists exactly when the directed dependency graph is acyclic.

Two groups: think bipartite

Can adjacent objects be placed on opposite sides?
→
Two-coloringBFS or DFS

Color a component as you traverse it. A same-color edge is a certificate that the attempted partition fails; in an undirected graph it corresponds to an odd cycle.

Repeated merging: think Union-Find

Do components only merge?
→
DSU / Union-Findfind + union

DSU is especially useful when edges arrive one by one and the important question is whether two vertices already belong to the same component. Kruskal is the canonical example.

Clone a graph: traversal + a map

When graph vertices are objects with references to neighbors, a deep copy needs two operations at once: traverse the original graph and remember which copy corresponds to each original vertex.

original vertex → cloned vertex

The map is also the visited structure. When an edge leads to a vertex already in the map, reuse its clone instead of recursively cloning it again. This handles cycles without infinite recursion and preserves shared neighbors correctly.

Do not forget disconnected graphs

A BFS or DFS started from one vertex sees only the vertices reachable from that start. If the problem concerns the whole graph, wrap the traversal in an outer loop.

visited = set()

for start in graph:
    if start not in visited:
        traverse(start, visited)

This small pattern is what turns a component traversal into connected-components counting, full bipartite testing, or a DFS forest.

Common mistakes

Forgetting visited

A cycle can make traversal repeat forever.

Marking too late

In BFS, marking on enqueue avoids putting the same vertex into the queue repeatedly.

Using BFS on weighted edges

BFS minimizes edge count, not arbitrary total weight.

Using Dijkstra with negatives

Its greedy finalization argument no longer holds.

Starting only once

One traversal misses other connected components.

Building unnecessary edges

Implicit graphs are often cheaper to explore by generating neighbors on demand.

The reusable idea

Start by deciding what the vertices and edges mean. Then choose the traversal or graph algorithm that matches the required result.

Model first, algorithm second. A problem that looks complicated in its original language can become a standard traversal, shortest-path, ordering, spanning-tree, or connectivity problem once the right graph is visible.
