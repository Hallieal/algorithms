Graph Problem Patterns

Graphs turn problems about connections, routes, and dependencies into standard algorithmic models.

First ask whether there is a hidden graph

Many problems never use the word “graph”. Look for objects connected by allowed transitions, relationships, dependencies, or compatibility rules.

Reachability

Can A get to B?

BFS or DFS. If repeated over all unvisited vertices, this becomes connected components.

Minimum moves

Every move costs the same

BFS. The state itself may be a string, board, bitmask, coordinate, or tuple.

Dependencies

What order is legal?

Directed graph + topological sort. A cycle means the dependencies cannot all be satisfied.

Weighted route

What is the cheapest path?

Dijkstra for nonnegative weights; Bellman–Ford if negative edges are possible.

Global network

Connect everything cheaply

MST: Kruskal or Prim. Do not confuse this with finding a route between two vertices.

Groups merge

Are these in the same component?

Union-Find is ideal when edges are added and you repeatedly query connectivity.

Common mistakes

Marking too late in BFS

Mark a vertex when it is enqueued, not when it is dequeued, or it may enter the queue many times.

Using DFS for unweighted shortest path

DFS can find a path, but not necessarily the shortest one.

Forgetting direction

An undirected edge is normally stored twice in an adjacency list; a directed edge is not.

Running Dijkstra with negative edges

The greedy finalization argument requires nonnegative weights.
