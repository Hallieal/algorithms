Representing Graphs

The two basic representations are adjacency matrices and adjacency lists. The choice changes both memory use and the running time of graph algorithms.

Two parameters: vertices and edges

For a graph G=(V,E), write n=|V| for the number of vertices and m=|E| for the number of edges. Running times for graph algorithms are usually expressed in terms of both n and m.

This distinction matters because graphs with the same number of vertices can contain very different numbers of edges. A graph with relatively few edges is sparse; a graph containing a large fraction of all possible edges is dense.

For many graph algorithms, O(n+m) is called linear time: even reading an adjacency-list representation of the whole input already takes this much time.

One graph, two representations

Consider the undirected graph below. The picture is useful to us, but an algorithm needs a concrete data structure.

Adjacency matrix

The simplest representation is an n × n matrix A. The entry A[u,v] is 1 when the graph contains the edge (u,v), and 0 otherwise. For an undirected graph the matrix is symmetric: A[u,v]=A[v,u].

Strength

Constant-time edge test

To ask whether (u,v) is present, inspect one matrix entry. The operation takes O(1) time.

Cost

Quadratic space

The matrix always contains n² entries, whether the graph has ten edges or almost every possible edge.

There is another disadvantage for sparse graphs. To find all neighbors of a vertex v, the algorithm must scan the entire row A[v,*]. This takes Θ(n) time even if v has only one neighbor.

Adjacency list

In an adjacency-list representation, every vertex stores a list of its neighbors. We can think of an array Adj in which Adj[v] contains exactly the vertices adjacent to v.

For an undirected graph, each edge appears twice: if {u,v} is an edge, then v appears in Adj[u] and u appears in Adj[v]. Consequently, the total length of all adjacency lists is 2m.

space = Θ(n + m)

This is why adjacency lists are particularly effective for sparse graphs. Iterating over all neighbors of v takes time proportional to the degree of v, rather than to the total number of vertices.

graph = {
    0: [1, 2, 3],
    1: [0, 2],
    2: [0, 1, 3],
    3: [0, 2],
}

In Python, a dictionary of lists is convenient when vertex labels are arbitrary. If vertices are numbered 0,1,…,n−1, a list of lists is usually enough.

Why sparse graphs favor adjacency lists

Skiena gives a useful scale example. Model Manhattan as a street graph: intersections are vertices and street segments between neighboring intersections are edges. Roughly 15 avenues crossing about 200 streets produce around 3,000 vertices and about 6,000 edges.

≈ 3,000vertices
≈ 6,000edges
9,000,000matrix cells

An adjacency matrix would allocate 3,000 × 3,000 = 9,000,000 cells, almost all of them empty. An adjacency list stores essentially the vertices and the street segments that actually exist.

Default choice: adjacency lists are the standard representation for most graph algorithms. Adjacency matrices are attractive when the graph is dense or constant-time edge lookup is especially important.

Directed and weighted graphs

The same representations extend naturally. For a directed graph, an edge (u,v) is stored only in u's outgoing adjacency list, or only in matrix entry A[u,v]. The representation is no longer symmetric.

For a weighted graph, store the weight together with the neighbor. An adjacency-list entry can be a pair (v,w), where v is the neighboring vertex and w is the edge weight.

graph = {
    0: [(1, 7), (2, 3)],
    1: [(2, 4)],
    2: []
}

Why representation matters for traversal

Breadth-first search and depth-first search repeatedly ask for the neighbors of the current vertex. With adjacency lists, the total work of examining all lists is proportional to n+m. With an adjacency matrix, scanning rows can require n² work. The next section uses an adjacency list to obtain a linear-time breadth-first search.
