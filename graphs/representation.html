Representing Graphs

Graphs turn problems about connections, routes, and dependencies into standard algorithmic models.

Adjacency list or adjacency matrix?

The representation changes both memory use and the cost of basic operations. Most algorithmic graphs are sparse, so adjacency lists are the default.

Adjacency list

A → B, D
B → A, C
C → B, D
D → A, C

Stores only existing edges: O(V + E) space.

Adjacency matrix

ABCD
A0101
B1010
C0101
D1010

Uses O(V²) space but tests an edge in O(1).

OperationAdjacency listAdjacency matrix
SpaceO(V + E)O(V²)
Iterate neighbors of vO(deg(v))O(V)
Test edge (u,v)O(deg(u))O(1)
Traverse whole graphO(V + E)O(V²)

Python representation

graph = {
    "A": ["B", "D"],
    "B": ["A", "C"],
    "C": ["B", "D"],
    "D": ["A", "C"],
}

For weighted graphs, store pairs such as ("B", 7). For an undirected edge, add both directions. For a directed edge, add only the outgoing direction.

Default rule. Use adjacency lists unless the graph is dense or the algorithm repeatedly needs constant-time edge-existence queries.
