Minimum Spanning Trees and Union-Find

A minimum spanning tree connects all vertices with minimum total edge weight. Prim grows one tree; Kruskal joins components of a forest.

Minimum-Cost Connectivity

A spanning tree of a connected undirected graph uses edges of the graph to connect every vertex without a cycle. A minimum spanning tree, or MST, is a spanning tree whose total edge weight is as small as possible.

weight(T) = Σe ∈ T w(e)

Every tree on n vertices has exactly n−1 edges. Every spanning tree has n−1 edges. An MST chooses, among these spanning trees, one with minimum total edge weight.

Roadconnect locations with little total roadway
Wireconnect sites with little total cable
Pipebuild a low-cost connected network
Clusteringremove long MST edges to separate groups

Spanning tree is not shortest-path tree

An MST minimizes the sum of all edges in the tree. A shortest-path tree minimizes the distance from one chosen source to every vertex. These are different objectives.

MST

Global network cost

No distinguished source. We care about the total weight of the tree.

Shortest paths

Distances from a source

A source is fixed. Individual source-to-vertex paths must be shortest.

The cut property

A cut divides the vertices into two nonempty sets S and V−S. An edge crosses the cut if one endpoint lies on each side.

Cut property. If an edge is a minimum-weight edge crossing a cut compatible with the edges already chosen, then there is a minimum spanning tree containing that edge.

For the exchange argument, take an MST that omits the chosen edge e. Adding e creates a cycle containing another edge f across the same cut. Since e is no heavier than f, replacing f by e preserves connectivity without increasing total weight.

Prim: grow one tree

For a connected graph, Prim's algorithm starts at any vertex. At every step, consider the cut between vertices already in the tree and vertices outside it, and add a minimum-weight edge crossing that cut.

tree— 2 —newchoose the cheapest edge leaving the current tree
larger tree— 4 —newrepeat until every vertex is included
import heapq

def prim(graph, start):
    visited = set()
    heap = [(0, start, None)]
    tree = []
    total = 0

    while heap and len(visited) < len(graph):
        weight, u, parent = heapq.heappop(heap)

        if u in visited:
            continue

        visited.add(u)
        if parent is not None:
            tree.append((parent, u, weight))
            total += weight

        for v, w in graph[u]:
            if v not in visited:
                heapq.heappush(heap, (w, v, u))

    return tree, total

Notice the difference from Dijkstra. Dijkstra's priority is the entire path length d[u]+w(u,v); Prim's priority is only the weight w(u,v) of the edge that would attach the new vertex.

Union-Find

Kruskal repeatedly asks one question: are these two vertices already connected by the selected edges? Disjoint Set Union (DSU), also called Union-Find, is built for exactly this situation.

make_set(x)

Create a one-element component.

find(x)

Return a representative of x's component.

union(a, b)

Merge two different components.

Path compression and union by size

A naive DSU tree can become tall. Two simple rules keep it shallow. Union by size attaches the smaller tree below the larger root. Path compression makes vertices encountered during find point directly toward the root.

→
class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]

    def union(self, a, b):
        a, b = self.find(a), self.find(b)

        if a == b:
            return False

        if self.size[a] < self.size[b]:
            a, b = b, a

        self.parent[b] = a
        self.size[a] += self.size[b]
        return True

Kruskal with Union-Find

def kruskal(n, edges):
    # edges contain (weight, u, v)
    dsu = DSU(n)
    tree = []
    total = 0

    for weight, u, v in sorted(edges):
        if dsu.union(u, v):
            tree.append((u, v, weight))
            total += weight

            if len(tree) == n - 1:
                break

    return tree, total

Sorting dominates the running time: O(m log m). With path compression and union by size/rank, the DSU operations are extremely close to constant amortized time.

Correctness of Kruskal's Algorithm

Just before Kruskal accepts an edge e=(u,v), let S be the current component containing u. Vertex v lies outside S. Because edges are processed from lightest to heaviest, no cheaper edge crossing from S to the outside could still be available to merge two components. Thus e is safe by the cut property.

Prim and Kruskal choose different cuts, but both are justified by the cut property.
