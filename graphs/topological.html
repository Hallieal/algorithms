Directed Graphs, DAGs, and Topological Ordering

A directed edge can encode a prerequisite. If the resulting graph has no directed cycle, its vertices can be placed in an order that respects every prerequisite.

Precedence Constraints

Many systems are governed by statements of the form do u before v. A directed edge u→v is a natural way to record such a precedence constraint.

Vertices might represent courses, jobs in a build system, stages of a computation, or tasks in a project. An edge points from a prerequisite to something that depends on it.

Directed acyclic graphs

A directed acyclic graph, or DAG, is a directed graph containing no directed cycle. DAGs are the natural model for consistent precedence constraints.

A directed cycle makes a precedence schedule impossible: following the cycle says that each item must occur before the next, eventually requiring an item to occur before itself.

Topological ordering

A topological ordering of a directed graph is a linear ordering of its vertices in which every directed edge u→v goes from an earlier vertex u to a later vertex v.

A→C→B→D→E

Only DAGs have topological orderings, and every DAG has at least one. The ordering need not be unique: if two tasks are unrelated by the constraints, either may be placed first.

Sources in DAGs

A source is a vertex of in-degree zero. Every nonempty DAG has at least one source.

Suppose instead that every vertex had an incoming edge. Start anywhere and repeatedly follow an incoming edge backward. Because the graph has finitely many vertices, eventually a vertex must repeat. The repeated segment is a directed cycle, contradicting the assumption that the graph is acyclic.

Kahn's algorithm repeatedly removes a source, appends it to the ordering, and deletes its outgoing edges. Removing a source cannot create a cycle.

from collections import deque

def topological_sort(graph):
    indegree = {u: 0 for u in graph}

    for u in graph:
        for v in graph[u]:
            indegree[v] += 1

    queue = deque(
        u for u in graph if indegree[u] == 0
    )
    order = []

    while queue:
        u = queue.popleft()
        order.append(u)

        for v in graph[u]:
            indegree[v] -= 1
            if indegree[v] == 0:
                queue.append(v)

    if len(order) != len(graph):
        return None

    return order

If every vertex is removed, order is a topological ordering. If the queue becomes empty while vertices remain, every remaining vertex has a prerequisite inside the remaining graph; a directed cycle prevents further progress.

Topological sorting with DFS

DFS gives a second linear-time algorithm. Do not add a vertex to the answer when it is first discovered. Add it only when its DFS call finishes—after all vertices reachable through its outgoing edges have been processed. Reverse the finishing order at the end.

Bfinishes 4
Cfinishes 3
Dfinishes 2
Efinishes 1
topological order = decreasing DFS exit time

For an edge u→v in a DAG, DFS cannot encounter v as an active ancestor of u, because that would be a back edge and would close a directed cycle. The DFS structure therefore forces v to finish before u, placing u before v after reversal.

Cycle Detection

Kahn's algorithm detects a cycle when fewer than n vertices can be removed. DFS detects a cycle when it encounters a back edge to a vertex whose recursive call is still active.

No source remains

The queue is empty but some vertices have not been processed.

DFS

A back edge appears

An edge points from the current DFS branch to one of its active ancestors.

Running time

With adjacency lists, computing all in-degrees examines every edge once. Kahn's algorithm then removes every vertex once and processes every outgoing edge once. DFS has the same accounting.

Θ(n + m)

Both methods also use O(n) auxiliary space beyond the graph representation.

Applications of Topological Ordering

Scheduling

Prerequisites

Courses, jobs, and project tasks can be executed without violating dependencies.

Build systems

Dependency order

A dependency is processed before the object that needs it.

DAG algorithms

Left to right

Dynamic programs and path algorithms can process a vertex only after all relevant predecessors.

Validation

Cycle detection

A failed topological sort reveals inconsistent circular dependencies.

Non-uniqueness of Topological Orders

Topological sorting respects only the comparisons encoded by directed paths and edges. If neither of two vertices must precede the other, the constraints may permit both relative orders.

Do not read extra information into the output. If one valid topological sort places u before v, that alone does not imply that the graph requires u before v.
