Depth-First Search

DFS follows a path as far as possible, then backtracks. Its tree structure, entry and exit times, and back edges are the basis of many graph algorithms.

Depth-First Traversal

Imagine that the graph is a maze. Start at s, take an unexplored passage, and continue from the new room. Keep moving forward until there is nowhere new to go; then backtrack to the most recent room that still has an unexplored passage.

DFS follows one branch before returning. BFS, by contrast, processes vertices layer by layer.

The recursive form

DFS is especially natural as a recursive procedure. When DFS reaches a vertex u, it marks u as visited and recursively explores each still-unvisited neighbor.

def dfs(graph, u, visited):
    visited.add(u)

    for v in graph[u]:
        if v not in visited:
            dfs(graph, v, visited)

The recursive calls themselves form the stack. A call for u remains unfinished while DFS explores a child, its child's descendants, and so on. Only after every neighbor has been dealt with does the call for u return.

The DFS tree

As with BFS, record the edge that first discovers each vertex. These discovery edges form a rooted tree. But a DFS tree usually has a very different shape: it tends to contain long root-to-leaf paths because the search goes as deeply as possible before retreating.

The exact DFS tree depends on the order in which each adjacency list is scanned. Different neighbor orders can produce different, equally valid DFS trees.

Entry and exit times

DFS can attach two timestamps to every vertex. The entry time is recorded when the vertex is first reached. The exit time is recorded after all of its outgoing edges and descendants have been explored.

If u is an ancestor of v in the DFS tree, then entry[u] < entry[v] < exit[v] < exit[u]. The time interval of every descendant is nested inside the interval of its ancestor.

Entry and exit times encode ancestry and are used in topological sorting, articulation-point, bridge, and strongly-connected-component algorithms.

Tree edges and back edges

In an undirected graph, DFS gives a particularly strong structural property. Every edge is either a tree edge, which discovers a new vertex, or a back edge, which joins a vertex to one of its ancestors in the DFS tree.

There are no cross edges between unrelated branches in an undirected DFS tree. If an edge joined two such branches, the first branch explored would have discovered the other endpoint before that branch could finish.

Finding a cycle

Back edges give a direct test for cycles in an undirected graph. If DFS encounters an edge from u to an already discovered ancestor v that is not u's parent, then the edge (u,v) together with the tree path from v to u forms a cycle.

def has_cycle(graph):
    visited = set()

    def dfs(u, parent):
        visited.add(u)

        for v in graph[u]:
            if v not in visited:
                if dfs(v, u):
                    return True
            elif v != parent:
                return True

        return False

    for u in graph:
        if u not in visited and dfs(u, None):
            return True

    return False

The parent check is essential in an undirected graph: the edge by which DFS entered u also appears in u's adjacency list, but traversing it backward does not create a cycle.

DFS with an explicit stack

Recursion is not required. DFS can be implemented with a last-in, first-out stack. Newly encountered vertices are placed on top, so the most recently discovered part of the graph is explored first.

def dfs_iterative(graph, start):
    visited = set()
    stack = [start]

    while stack:
        u = stack.pop()

        if u in visited:
            continue

        visited.add(u)

        for v in reversed(graph[u]):
            if v not in visited:
                stack.append(v)

    return visited
Neighbor order matters. Recursive DFS and an iterative implementation may visit vertices in different orders unless the order in which neighbors are pushed onto the stack is chosen carefully.

Edge Types in Directed Graphs

For undirected graphs, tree and back edges are enough. In directed graphs, DFS can encounter four kinds of edges: tree, back, forward, and cross edges.

Tree

Discovers a new vertex.

Back

Points to an active ancestor.

Forward

Points to an already processed descendant.

Cross

Connects vertices with no ancestor–descendant relation.

This classification is central to DFS algorithms on directed graphs. In particular, a directed graph is acyclic exactly when DFS finds no back edge. Reverse exit order then produces a topological ordering; we will use this in the section on DAGs.

Running time

With adjacency lists, every vertex is entered once and each adjacency-list entry is examined a constant number of times. Therefore DFS runs in

Θ(n + m)

The visited/parent/timestamp arrays use O(n) space. The recursion stack can also contain O(n) vertices in the worst case, for example when the DFS tree is one long path.
