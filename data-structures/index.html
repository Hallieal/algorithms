Data Structures

A data structure is a way of organizing values so that certain operations are cheap. The important question is rarely “where can I put these values?” It is “what will I need to do with them?”

The same collection of values can be stored as an array, a linked structure, a tree, a heap, or a hash table. Those choices change the cost of access, search, insertion, and deletion.

Structure follows operations

Suppose an algorithm repeatedly performs one particular operation. A good data structure is one that makes that operation cheap without making the rest of the program unnecessarily complicated.

If you mostly need to…A natural first choice is…
access element i quicklyarray / dynamic array
remove the most recently added itemstack

repeatedly extract the smallest itempriority queue / heap
Interface versus representation. A stack is an abstract interface: push, pop, top. It can be implemented using a dynamic array or a linked list. The interface says what operations exist; the representation determines their cost.

Arrays and dynamic arrays

An array stores elements in indexed positions. Because the position of element i can be computed directly, random access is constant-time.

OperationTypical costWhy
read or write a[i]Θ(1)address computed directly
scan all elementsΘ(n)visit each position once
insert/delete in the middleΘ(n)a suffix may have to shift
append to a dynamic arrayamortized Θ(1)resizing is rare

Why dynamic-array append is amortized O(1)

A dynamic array keeps spare capacity. When it fills up, it allocates a larger block and copies the old elements. One resize is expensive, but if capacity grows geometrically, the total copying over many appends forms a geometric sum:

1 + 2 + 4 + 8 + ··· < 2n.

So a sequence of n appends performs only Θ(n) total copying. Individual appends can still be slow; the average over the sequence is constant.

Linked lists

A linked list stores each value in a separate node. Instead of relying on neighboring memory locations, nodes contain references to other nodes.

This changes the trade-off. If we already have a reference to the right place, changing a few links can insert or remove a node in Θ(1) time. But there is no direct equivalent of a[i]: reaching the i-th node requires following the chain, which is Θ(n) in the worst case.

A common oversimplification. “Deletion from a linked list is O(1)” is only true if the relevant node—and any predecessor information the representation needs—is already known. Finding that node may take O(n).

Stacks, queues, and deques

These are small interfaces with strict rules about which end of a sequence can be used.

Stack: last in, first out

CBA

push, pop, and top operate on one end. Stacks appear in DFS, parsing, undo systems, and the call stack.

Queue: first in, first out

ABC

Items leave in the order they arrived. BFS is the standard algorithmic example.

Deque: both ends

←ABC→

A deque allows insertion and removal at both ends and is useful in sliding-window algorithms.

# stack
stack = []
stack.append(x)
x = stack.pop()

# queue / deque
from collections import deque
q = deque()
q.append(x)
x = q.popleft()

Python

A Python list works well as a stack. For a queue, use collections.deque: list.pop(0) is Θ(n) because all remaining elements have to shift.

Sets and maps

A set answers membership questions; a map associates keys with values. Those are interfaces, not implementations.

Hash table
Expected Θ(1) lookup, insertion, and deletion under the usual assumptions. Python set and dict are hash-based.
Balanced search tree
Θ(log n) lookup, insertion, and deletion, while keeping keys in order.

The distinction matters because sometimes ordering is part of the problem. Hash tables are usually the simplest choice for pure membership and key lookup; ordered maps and sets are useful when predecessor, successor, or sorted traversal matters.

Heaps and priority queues

A priority queue is useful when we repeatedly need the currently smallest or largest item. A binary heap is the usual compact implementation.

In a min-heap every parent is no larger than its children. The minimum is therefore at the root and can be read in Θ(1). Insertion and extraction move along one root-to-leaf path, so they take Θ(log n).

A heap is not a sorted array. It stores just enough order to find the extreme priority quickly.

Trees

Trees describe hierarchical relationships. They appear in search structures, syntax trees, file systems, recursion, and later in graph algorithms.

root
the node with no parent
depth
distance from the root
height
maximum downward distance to a leaf
subtree
a node together with all of its descendants

For search trees, height is crucial. A balanced binary search tree keeps height Θ(log n), which gives logarithmic search and update operations. An unbalanced tree can degrade to a chain and lose that advantage.

How to choose

There is no universally best data structure. Start from the operations your algorithm performs most often.

StructureUse it when…Main trade-off
Array / dynamic arrayyou need indexing and sequential scansmiddle updates are expensive
Linked listyou already have node references and change local linkspoor random access
Stackthe last item added should be handled firstonly one end matters
Queue / dequeyou process items by arrival order or by endsnot meant for arbitrary indexing
Hash set / mapmembership or key lookup dominatesno inherent sorted order
Heapyou repeatedly need a minimum or maximumthe rest is not globally sorted

Three small examples

1

Detect duplicates

Scan the array and keep previously seen values in a hash set. Membership is expected Θ(1), so the whole scan is expected Θ(n).

2

Process jobs in arrival order

Use a queue: append new jobs at the back and remove the oldest job from the front.

3

Always take the cheapest available option

Use a min-heap. Reading the current minimum is Θ(1), and updating the heap after insertion or extraction is Θ(log n).
