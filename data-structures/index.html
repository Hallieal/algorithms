Chapter 2

Data Structures

Algorithms do not work on abstract “data” alone. They rely on concrete ways to store, access, update, and organize it. This chapter introduces the structures that appear repeatedly throughout the rest of the handbook.

Store

Choose how values are represented in memory: contiguous cells, linked nodes, trees, or hash-based collections.

Access

Different layouts make different operations cheap: indexing, finding the minimum, removing from an end, or looking up a key.

Update

The right structure often turns an expensive algorithmic step into a constant-time or logarithmic-time operation.

What is a data structure?

A data structure is a concrete organization of data together with operations that maintain that organization. The same abstract interface can often be implemented in more than one way.

Abstract data type

An abstract data type describes what operations are available, without fixing how they are implemented.

  • Stack: push, pop, top.
  • Queue: enqueue, dequeue, front.
  • Map: associate keys with values.

Concrete representation

A representation determines how the operations are carried out and therefore their time and memory costs.

  • A stack can use a dynamic array or a linked list.
  • A map can use a hash table or a balanced search tree.
  • A priority queue is commonly implemented with a heap.
The key habit: do not ask only “which structure stores these values?” Ask “which operations does my algorithm perform most often, and which representation makes those operations cheap?”

Arrays and dynamic arrays

Arrays place elements in consecutive logical positions. This gives direct indexing: once the base address is known, the location of element i can be computed immediately.

What arrays are good at

Indexing is Θ(1). Iterating through all elements is Θ(n). Arrays also have good locality because neighboring logical elements are stored close together.

What arrays are bad at

Inserting or deleting in the middle usually requires shifting a suffix, which takes Θ(n) time in the worst case.

Dynamic arrays

A fixed array has a fixed capacity. A dynamic array keeps a larger underlying buffer and occasionally replaces it with a larger one. Python's list behaves conceptually like a dynamic array.

Why append is amortized Θ(1)

A resize may cost Θ(n) because existing elements must be copied. But if capacity grows geometrically, expensive resizes happen rarely.

1 + 2 + 4 + 8 + ··· + n/2 < n

Across n appends, the total number of copied elements is Θ(n). Therefore the average cost per append over the whole sequence is Θ(1). This is an amortized bound: an individual append can still be expensive.

Linked lists

A linked list stores each value in a separate node together with one or more references to neighboring nodes. The nodes do not need to be contiguous in memory.

Strength

If a pointer to the relevant node is already known, insertion or deletion can often be performed in Θ(1) time by changing a constant number of links.

Trade-off

There is no constant-time random indexing: reaching the i-th node requires following links from a known starting point, so access is Θ(n) in the worst case.

Important nuance: saying “deletion in a linked list is O(1)” is only correct when the node to delete, and any predecessor information required by the representation, is already available. Searching for that node can itself cost O(n).

Stacks, queues, and deques

These are linear abstract data types defined by which end or ends may be used for insertion and removal.

Stack · LIFO

The last inserted item is removed first.

CBA
push, pop, top: Θ(1) amortized with a dynamic array.

Queue · FIFO

The first inserted item is removed first.

ABC
enqueue, dequeue: Θ(1) with a suitable deque / linked representation.

Deque · both ends

Insert and remove at either the front or the back.

←ABC→
Useful for sliding windows, monotone queues, and BFS-like processes.

Python choices

# stack
stack = []
stack.append(x)
x = stack.pop()

# queue / deque
from collections import deque
q = deque()
q.append(x)      # push right
x = q.popleft()  # pop left
A common Python pitfall: list.pop(0) is Θ(n), because every remaining element shifts left. For a queue, use collections.deque.

Sets and maps

A set stores distinct keys. A map associates each key with a value. These are interfaces; the implementation determines the complexity.

Hash-based implementation

With a well-behaved hash table, lookup, insertion, and deletion are typically expected Θ(1). This is the model behind Python set and dict.

Tree-based implementation

A balanced search tree can provide ordered keys and Θ(log n) lookup, insertion, and deletion. The order itself can be algorithmically valuable.

The later Hash Tables chapter studies hashing, collisions, load factor, and implementation details. Here the important distinction is between the set/map interface and the data structure used to realize it.

Heaps and priority queues

A priority queue supports repeated access to the currently smallest or largest priority. A binary heap is a compact tree-shaped representation that supports this efficiently.

For index i, children are at 2i+1 and 2i+2 in a zero-indexed array.

Min-heap invariant

Every parent is no larger than its children. Therefore the minimum is always stored at the root and can be read in Θ(1).

Operations

Insertion and extraction restore the heap invariant along one root-to-leaf path, so they take Θ(log n). Building a heap from an array can be done in Θ(n).

A heap is not a sorted array. The invariant only orders each parent against its children. It gives fast access to the extreme priority without maintaining a complete global order.

Trees

A tree is a hierarchical structure of nodes connected by parent-child relations. Trees appear in search structures, syntax trees, file systems, recursion, and many graph algorithms.

Vocabulary

  • Root: the node with no parent.
  • Depth: distance from the root.
  • Height: maximum downward distance to a leaf.
  • Subtree: a node together with all of its descendants.

Traversal

Depth-first traversals explore one branch before returning; breadth-first traversal explores level by level. These traversal patterns will reappear in the Graphs chapter.

A binary search tree additionally maintains an ordering rule, but its operation costs depend on the tree height. Balanced variants keep the height logarithmic.

Choosing a data structure

There is no universally best structure. The right choice follows from the operations the algorithm needs to perform.

Need random access by position?

Start with an array or dynamic array.

Need FIFO or LIFO behavior?

Use a queue/deque or a stack.

Need fast membership by key?

Use a set or map; later we will study hash tables in detail.

Need the current minimum or maximum repeatedly?

A priority queue implemented by a heap is usually the right tool.
