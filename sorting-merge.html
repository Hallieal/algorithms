Merge Sort

Divide the array, sort the smaller parts recursively, and merge them back together.

Divide and conquer

Merge Sort is our first sorting algorithm based on divide and conquer. Instead of choosing the next element directly, we reduce one large sorting problem to several smaller sorting problems.

1

Divide

Split the array into two smaller halves.

2

Solve recursively

Sort each half by applying the same algorithm.

3

Combine

Merge the two sorted halves into one sorted array.

Splitting is easy; merging does the real work

Splitting an array into halves is straightforward. The essential step is combining two halves after they have already been sorted. That operation is called merge.

The merge operation

Suppose we already have two sorted sequences. To merge them, compare their first unused elements. The smaller of the two must be the next element of the final sorted sequence.

Running time of merge

Suppose the left sequence contains p elements and the right sequence contains q elements. The merged output therefore contains exactly p + q elements.

During each step, the algorithm compares the first unused elements of the two sequences and permanently moves one of them to the output. No element ever moves back. Hence every input element is processed exactly once.

p elements + q elements → p + q output positions
Total work Θ(p + q)

There are p + q elements altogether, and each is copied to the output exactly once.

Maximum comparisons p + q − 1

Comparisons continue only while both sequences are nonempty. In the worst case, one sequence becomes empty only after p + q − 1 elements have already been chosen. The final remaining element is then appended without another comparison.

Why merge is correct

!

The key observation

Each input sequence is already sorted. Therefore its first unused element is the smallest element that still remains in that sequence.

So if the current candidates are x from the left sequence and y from the right sequence, the smallest element remaining anywhere in the two inputs must be min(x, y).

1

Invariant

Before every step, the output contains exactly the smallest elements that have already been removed from the two input sequences, and these elements appear in sorted order.

2

Initialization

Before the first step, the output is empty. An empty sequence is sorted, so the invariant holds.

3

Maintenance

Let x and y be the first unused elements of the left and right sequences. Because both sequences are sorted, no later element in the left sequence is smaller than x, and no later element in the right sequence is smaller than y.

Therefore the smaller of x and y is the smallest element remaining anywhere in the two inputs. Appending it to the output preserves sorted order and adds exactly the next element that belongs there.

4

Termination

Eventually one input sequence becomes empty. Every remaining element of the other sequence is already sorted and is at least as large as the last element written to the output.

We can therefore append the entire remainder. The output then contains every input element exactly once and is sorted. Hence merge is correct.

Merge Sort

Merge Sort applies the merge operation recursively. Each half is sorted first; only then are the two halves merged.

Merge Sort = split + sort left half + sort right half + merge

Implementation

It is useful to separate the implementation into two functions: one function merges two sorted sequences, and the other performs the recursive splitting.

Complexity

log₂ n

How many merge levels do we have?

Merge Sort repeatedly divides the array in half until every subarray contains one element. When the recursion returns, these one-element arrays are merged back together level by level.

Example: n = 8

Starting from one-element arrays, three merge levels are needed to obtain an array of length 8: 1 → 2 → 4 → 8. Since 2³ = 8, we have 3 = log₂ 8.

In general

Looking in the opposite direction, the recursive splitting produces subproblems of sizes

n → n / 2 → n / 4 → n / 8 → ··· → 1

After k halvings, the subproblem size is n / 2k. We reach one element when

n / 2k = 1
2k = n
k = log₂ n

Therefore there are log₂ n merge levels when n is a power of two. For arbitrary n, the number differs by at most one level, so asymptotically it is Θ(log n).

Σ

How much work is done on one merge level?

At any fixed merge level, the subarrays are disjoint and together contain all n elements of the original array.

For example, one level may merge four blocks of size n / 4, another may merge two blocks of size n / 2, and the final level merges one block of size n. The block sizes change, but their total size on every level is still n.

Since merging is linear in the number of elements being merged, the total work on every merge level is Θ(n).

Stability and memory

Stability

Merge Sort can be stable. In the merge function above, when two values are equal, the element from the left sequence is chosen first because the condition uses <=.

Since the left sequence contains elements that appeared earlier in the original array, choosing from the left on ties preserves their relative order.

Additional memory

The array-based implementation constructs temporary sequences while merging. The total additional storage required at one time is Θ(n).

The recursion stack has depth Θ(log n), which is smaller than the Θ(n) merge storage.

⇄

A useful trade-off

Compared with the elementary quadratic sorts from the previous sections, Merge Sort guarantees Θ(n log n) running time. The price is additional memory for merging.

Exercises

1

Merge two sequences

Merge [1, 4, 7] and [2, 3, 8] by hand.

The merged sequence is [1, 2, 3, 4, 7, 8]. The chosen values are 1, 2, 3, 4, 7, and finally 8.
2

Recursion depth

If the input contains 16 elements, how many times can the problem size be halved before reaching subarrays of length 1?

Four halvings: 16 → 8 → 4 → 2 → 1. Thus the recursion tree has Θ(log₂ 16) = Θ(4) nontrivial splitting levels.
3

Stability

Why can replacing left[i] <= right[j] with left[i] < right[j] make the implementation unstable?

When the values are equal, the strict comparison chooses the element from the right sequence first. That element originally appeared later, so equal elements may reverse their relative order.
4

Maximum comparisons in one merge

Two sorted sequences have lengths p and q. What is the maximum number of comparisons needed to merge them?

At most p + q − 1. In the worst case, neither sequence becomes empty until only one element remains in total; that last element can then be appended without another comparison.
