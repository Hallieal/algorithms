Merge Sort

Divide the array, sort the smaller parts recursively, and merge them back together.

Divide and conquer

Merge Sort is our first sorting algorithm based on divide and conquer. Instead of choosing the next element directly, we reduce one large sorting problem to several smaller sorting problems.

1

Divide

Split the array into two smaller halves.

2

Solve recursively

Sort each half by applying the same algorithm.

3

Combine

Merge the two sorted halves into one sorted array.

Base case

An array containing zero or one element is already sorted. Recursion stops when a subarray reaches this size.

Splitting is easy; merging does the real work

Splitting an array into halves is straightforward. The essential step is combining two halves after they have already been sorted. That operation is called merge.

The merge operation

Suppose we already have two sorted sequences. To merge them, compare their first unused elements. The smaller of the two must be the next element of the final sorted sequence.

Only two candidates matter

Because each input sequence is already sorted, its first unused element is the smallest element still left in that sequence. Therefore the next output value must be the smaller of the two first unused elements.

Running time of merge

Each element is copied to the result exactly once. If the two input sequences contain p and q elements, merging them takes Θ(p + q) time.

At most p + q − 1 comparisons between elements are needed.

Why merge works

Loop invariant

Before each step, the output contains the smallest elements from the two input sequences that have already been processed, in sorted order.

The first unused element of each input is the smallest remaining element of that input.

Correctness

Initialization. The output is initially empty, so the invariant holds.

Maintenance. The next output value is chosen as the smaller of the two first unused values. No unprocessed element can be smaller than it, because both input sequences are sorted.

Termination. Once one input is exhausted, every element remaining in the other input is already larger than or equal to the last value written. Appending the remainder preserves sorted order.

Merge Sort

Merge Sort applies the merge operation recursively. Each half is sorted first; only then are the two halves merged.

Merge Sort = split + sort left half + sort right half + merge

Implementation

It is useful to separate the implementation into two functions: one function merges two sorted sequences, and the other performs the recursive splitting.

Complexity

Work at one level of recursion

Stability and memory

Stability

Merge Sort can be stable. In the merge function above, when two values are equal, the element from the left sequence is chosen first because the condition uses <=.

Since the left sequence contains elements that appeared earlier in the original array, choosing from the left on ties preserves their relative order.

Additional memory

The array-based implementation constructs temporary sequences while merging. The total additional storage required at one time is Θ(n).

The recursion stack has depth Θ(log n), which is smaller than the Θ(n) merge storage.

A useful trade-off

Compared with the elementary quadratic sorts from the previous sections, Merge Sort guarantees Θ(n log n) running time. The price is additional memory for merging.

Exercises

1

Merge two sequences

Merge [1, 4, 7] and [2, 3, 8] by hand.

The merged sequence is [1, 2, 3, 4, 7, 8]. The chosen values are 1, 2, 3, 4, 7, and finally 8.
2

Recursion depth

If the input contains 16 elements, how many times can the problem size be halved before reaching subarrays of length 1?

Four halvings: 16 → 8 → 4 → 2 → 1. Thus the recursion tree has Θ(log₂ 16) = Θ(4) nontrivial splitting levels.
3

Stability

Why can replacing left[i] <= right[j] with left[i] < right[j] make the implementation unstable?

When the values are equal, the strict comparison chooses the element from the right sequence first. That element originally appeared later, so equal elements may reverse their relative order.
4

Maximum comparisons in one merge

Two sorted sequences have lengths p and q. What is the maximum number of comparisons needed to merge them?

At most p + q − 1. In the worst case, neither sequence becomes empty until only one element remains in total; that last element can then be appended without another comparison.
