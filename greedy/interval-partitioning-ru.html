Разбиение интервалов по ресурсам

Interval Partitioning сохраняет все intervals и минимизирует число ресурсов. Оптимум равен maximum overlap depth и достигается обработкой intervals по времени начала.

Постановка задачи

Каждый interval нужно назначить в room, причём пересекающиеся intervals не могут находиться в одной room. Нужно минимизировать число rooms.

ПравилоИдём по началу и переиспользуем самую раннюю свободную аудиторию

Min-heap хранит время освобождения аудиторий.

Почему работаетНовая аудитория открывается только когда заняты все старые

В этот момент столько же аудиторий требует само число пересечений.

СложностьO(n log n)

Одна сортировка и одна операция heap на интервал.

Разбиение интервалов

Нужно назначить каждый интервал в аудиторию так, чтобы пересекающиеся интервалы находились в разных аудиториях, и минимизировать общее число аудиторий.

Не путайте с Interval Scheduling. Там мы максимизировали число оставленных интервалов. Здесь все интервалы обязательны, а минимизируется число параллельных ресурсов.

Как считаются концы интервалов

Используем полуоткрытые интервалы [s,f). Поэтому встреча, заканчивающаяся в 5, и встреча, начинающаяся в 5, могут использовать одну аудиторию. Именно поэтому в коде стоит finish <= start, а не finish < start.

Нижняя оценка через глубину перекрытия

Если в один момент пересекаются d intervals, требуется как минимум d rooms. Максимальное одновременное overlap задаёт lower bound для любого расписания.

rooms ≥ depth = maxt active(t)

Depth

3

В нашем примере A, B и C пересекаются около момента 2. Значит, нужны как минимум 3 аудитории.

Что достаточно доказать

Если жадный алгоритм никогда не использует больше аудиторий, чем depth, он оптимален: он достигает нижней границы, обязательной для любого расписания.

Selection и partitioning — разные задачи

Один и тот же набор intervals может задавать две разные objectives: выбрать максимум intervals или разместить все с минимумом ресурсов. Greedy-rule из одной задачи не переносится автоматически в другую.

Одна аудитория, некоторые пары можно выкинуть

Цель — оставить максимум пар. Earliest finish полезен, потому что оставляет больше свободного timeline.

→

Несколько аудиторий, оставить нужно все пары

Цель — использовать минимум комнат. Теперь выбор не какую пару взять?, а какую комнату переиспользовать?

Проверка понимания

Если в 10:30 одновременно идут три пары, может ли хитрый порядок обойтись двумя аудиториями?

Нет. Сам overlap уже даёт lower bound 3. Это главная картинка задачи: greedy оптимален, потому что каждая новая комната открывается только тогда, когда её объективно невозможно избежать.

Не переносите greedy-rule только потому, что объекты выглядят знакомо. Сначала выясните, что разрешено выбрасывать, что обязано остаться и какая objective оптимизируется.

Жадное распределение по rooms

Обрабатываем intervals по start time и переиспользуем room с минимальным текущим finish, если она уже свободна. Иначе нужно открыть новую room.

Что делать с одинаковым временем начала

Если длительности положительны и два интервала начинаются одновременно, порядок между ними не влияет на корректность. Сразу после начала они пересекаются, поэтому всё равно обязаны находиться в разных аудиториях.

1

Сортируем по началу

Когда рассматриваем интервал, все более ранние по началу уже распределены.

2

Берём самое раннее освобождение

Min-heap позволяет мгновенно найти аудиторию, которая освободится первой.

3

Переиспользуем, если можно

Если эта аудитория освобождается не позже начала нового интервала, назначаем его туда.

4

Иначе открываем новую

Если даже самая ранняя аудитория ещё занята, значит заняты все существующие.

Распределим интервалы по аудиториям

Оранжевым показан только что добавленный интервал. Зелёные уже закреплены.

Подсчёт числа rooms через sweep line

Если нужен только минимум rooms, достаточно найти maximum overlap, отсортировав endpoints и поддерживая число активных intervals.

1

Для каждого интервала создаём start-event (+1) и finish-event (−1).

2

Сортируем события по времени. При полуоткрытой модели [s,f) на равном времени finish обрабатывается раньше start.

3

Идём по событиям и считаем число активных интервалов. Его максимум — depth, а значит и оптимальное число комнат.

Эквивалентная задача: железнодорожные платформы

Arrivals/departures поездов образуют ту же interval-partitioning model. Минимум platforms равен максимальному числу одновременно присутствующих поездов.

Arrival+1 active train

Может понадобиться новая platform.

Departure−1 active train

Platform освобождается и может быть переиспользована.

AnswerMaximum prefix sum

Peak числа active trains — минимальное количество platforms.

Tie rule важен. Если departure и arrival имеют один timestamp и уходящий train успевает освободить platform, departure надо обработать первым. Иначе sweep создаст несуществующий overlap.

Чем полезен этот пример

Lower-bound proof становится почти физическим: если три trains одновременно стоят на станции, никакой scheduling trick не разместит их на двух platforms.

Sweep по двум массивам

Starts и finishes можно отсортировать отдельно и двигать указатель того события, которое происходит раньше, обновляя число активных intervals.

1starts = sorted(s for s, f in intervals)
2ends = sorted(f for s, f in intervals)
3i = j = active = best = 0
4if starts[i] < ends[j]: active += 1; i += 1
5else: active -= 1; j += 1
6best = max(best, active)

Почему strict inequality?

Для half-open intervals [s,f) пара, заканчивающаяся в 10:00, не пересекается с начинающейся в 10:00. Поэтому при равных timestamps сначала обрабатывается end — ветка else.

Representation choice. Tagged events и два sorted endpoint arrays реализуют один и тот же sweep; two-array версия делает tie-rule особенно заметным.

Доказательство оптимальности

Когда алгоритм открывает новую room для interval с началом s_j, в каждой существующей room уже находится interval, пересекающий s_j. Значит текущая depth действительно требует столько rooms.

1

Аудитория с самым ранним временем освобождения всё ещё занята после sⱼ.

2

Значит, в каждой существующей аудитории есть интервал, пересекающийся с j в момент sⱼ.

3

Если уже было d аудиторий, то одновременно пересекаются d+1 интервалов: по одному в каждой аудитории плюс j.

4

Следовательно, depth не меньше d+1. Любое расписание требует столько же аудиторий. Новая аудитория неизбежна.

Оптимальность

Каждая новая аудитория открывается только тогда, когда её наличие вынуждено одновременным пересечением. Поэтому число аудиторий у greedy равно depth, и лучше сделать невозможно.

Priority queue для rooms

На каждом шаге нужно находить room с минимальным finish time. Это естественная операция min-heap.

Сканировать все rooms

Храним finish times в обычном list. Поиск earliest-free room стоит O(r) для r комнат, поэтому assignment для n intervals может стоить O(nr) после sorting.

Использовать min-heap

Минимальный finish всегда лежит в root. Посмотреть его можно сразу, а заменить или добавить room finish — за O(log r). Assignment phase становится O(n log r).

Data structure выбирается по повторяющейся операции. Алгоритм постоянно спрашивает минимум finish time — именно его min-heap умеет быстро выставлять наверх.

Реализация на Python

В heap хранятся пары (finish_time, room_id). Минимальная пара соответствует room, которая освободится раньше остальных.

1import heapq
2
3def partition_intervals(intervals):
4 intervals = sorted(intervals)
5 heap = []
6 room_count = 0
7 for start, finish in intervals:
8 if heap and heap[0][0] <= start:
9 _, room = heapq.heappop(heap)
10 else:
11 room = room_count
12 room_count += 1
13 heapq.heappush(heap, (finish, room))
14 return room_count

Почему важна interval structure

Conflict graph здесь является interval graph, а не произвольным graph. Координаты start/finish задают порядок, который позволяет использовать greedy.

Arbitrary conflicts

Дан только graph

Из того, что A конфликтует с B и C, не видно, где происходят conflicts, и не возникает natural chronological sweep.

Interval conflicts

У каждой vertex есть start и finish

Sorting by start создаёт meaningful left-to-right order, а current finish times полностью описывают, когда каждая room снова свободна.

Certificate

Maximum overlap виден напрямую

Точка, одновременно покрытая d intervals, сразу доказывает, что меньше d colors/rooms невозможно.

Special structure — не техническая мелочь. Часто разница между трудной general problem и простым greedy algorithm ровно в representation, которую разрешено использовать.

Другой взгляд: раскраска интервального графа

Создадим вершину для каждого интервала и соединим две вершины, если интервалы пересекаются. Распределение по аудиториям — это ровно раскраска такого интервального графа. Для общих графов раскраска NP-трудна, но интервальные графы совершенны: хроматическое число равно размеру максимальной клики, а здесь это как раз максимальная глубина пересечений. Жадный алгоритм использует именно эту специальную структуру.

Задачи

1

Depth

Если в 10:30 одновременно пересекаются пять встреч, какую нижнюю границу это даёт на число аудиторий?

Нужно как минимум 5 аудиторий, потому что никакие две пересекающиеся встречи не могут находиться в одной аудитории.
2

Почему самая ранняя аудитория?

Если аудитория с самым ранним временем освобождения ещё занята, почему мы знаем, что свободных аудиторий вообще нет?

Её время окончания минимально среди всех аудиторий. Если даже этот минимум позже начала нового интервала, все остальные заканчиваются ещё позже.
3

Сложность

Почему не искать свободную аудиторию простым линейным проходом?

Это может занимать O(n) на каждый интервал и O(n²) суммарно. Min-heap находит и обновляет самое раннее окончание за O(log n).
