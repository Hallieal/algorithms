Minimum Spanning Trees

Build a minimum-weight spanning tree with the cut property, Kruskal’s algorithm, Prim’s algorithm, DSU, and priority queues.

The problem

Given a connected, undirected, weighted graph, we want to connect every vertex while paying as little total edge weight as possible.

Minimum Spanning Tree

A spanning tree contains every vertex, is connected, has no cycles, and therefore uses exactly |V|−1 edges. An MST is a spanning tree of minimum total edge weight.

MST is not a shortest-path tree. It minimizes the sum of all selected edge weights, not the distance from one source to every vertex.

The cut property

The central greedy fact behind both Kruskal and Prim is about cuts. A cut partitions the vertices into two nonempty sets S and V\S. An edge crosses the cut if its endpoints lie on different sides.

Cut property

If a cut respects the edges already chosen, then a minimum-weight edge crossing that cut is safe: there exists an MST containing all previously chosen edges plus that edge.

Why it is true

Take an MST T consistent with the current choices. If the light edge e is already in T, we are done. Otherwise add e; this creates a cycle. That cycle must contain another edge f crossing the same cut. Because e is the lightest crossing edge, w(e) ≤ w(f). Remove f. The tree remains spanning and its weight does not increase.

Kruskal’s algorithm

Kruskal looks at edges globally from lightest to heaviest. It adds an edge exactly when that edge connects two currently different components.

Why the next accepted edge is safe

Immediately before Kruskal accepts an edge (u,v), vertices u and v lie in different components. Consider the cut formed by one of those components versus the rest. The accepted edge is a lightest available edge crossing a cut that respects the current forest, so the cut property applies.

Prim’s algorithm

Prim grows one tree rather than many components. Start at any vertex. At every step, add the minimum-weight edge that leaves the current tree and reaches an unvisited vertex.

Prim’s correctness is almost a direct reading of the cut property: take the cut “vertices already in the tree” versus “vertices not yet in the tree”. The cheapest crossing edge is safe.

Python implementations

Kruskal + DSU

def kruskal(n, edges):
    parent = list(range(n))
    rank = [0] * n

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        a, b = find(a), find(b)
        if a == b:
            return False
        if rank[a] < rank[b]:
            a, b = b, a
        parent[b] = a
        if rank[a] == rank[b]:
            rank[a] += 1
        return True

    mst = []
    for w, u, v in sorted(edges):
        if union(u, v):
            mst.append((u, v, w))
    return mst

Prim + heap

import heapq

def prim(graph, start=0):
    seen = {start}
    heap = []

    for v, w in graph[start]:
        heapq.heappush(heap, (w, start, v))

    mst = []
    while heap and len(seen) < len(graph):
        w, u, v = heapq.heappop(heap)
        if v in seen:
            continue

        seen.add(v)
        mst.append((u, v, w))

        for to, weight in graph[v]:
            if to not in seen:
                heapq.heappush(heap, (weight, v, to))

    return mst

Since E ≤ V², the logarithmic factors are closely related. In practice, representation and surrounding code often matter more than the asymptotic distinction.

Useful MST facts

Distinct weights imply uniqueness

If every edge weight is different, the graph has a unique MST.

Ties may give several MSTs

Different safe choices of equal weight can lead to different spanning trees with the same minimum total weight.

Disconnected graph

There is no spanning tree. Kruskal instead produces a minimum spanning forest, one tree per connected component.

Negative edge weights are fine

Unlike Dijkstra, MST algorithms have no problem with negative weights. They simply prefer them when they are safe.

Exercises

1

Tree edge count

How many edges must a spanning tree on 17 vertices contain?

Exactly 16 edges.
2

Kruskal decision

Why does Kruskal reject an edge whose endpoints are already in the same DSU component?

There is already a path between the endpoints. Adding the edge would create a cycle, so it cannot belong to the current forest.
3

Cut property

If several minimum-weight edges cross the same cut, must every MST contain all of them?

No. Each such light edge is safe in the sense that some MST can contain it, but different MSTs may choose different tied edges.
