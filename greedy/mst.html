Minimum Spanning Trees

Minimum spanning tree algorithms connect all vertices with minimum total edge weight. Kruskal and Prim use different data structures but are justified by the same cut property.

Problem statement

Given a connected weighted undirected graph, find a spanning tree whose total edge weight is minimum.

Core factThe lightest safe edge across a cut can be taken

This single statement drives both Kruskal and Prim.

Two viewsKruskal grows a forest; Prim grows one tree

Different mechanics, same cut argument.

CostO(E log E) or O(E log V)

DSU for Kruskal, a heap for Prim.

Minimum Spanning Tree

A spanning tree contains every vertex, is connected, has no cycles, and therefore uses exactly |V|−1 edges. An MST is a spanning tree of minimum total edge weight.

w(T) = ∑e∈T w(e)    →    min
MST is not a shortest-path tree. It minimizes the sum of all selected edge weights, not the distance from one source to every vertex.

Graph model

Vertices represent sites that must be connected, edges represent available direct links, and edge weights represent construction costs.

Vertices

Things that must be connected

Each office becomes a vertex.

Edges

Possible direct links

An edge means a link can be built; its weight is the construction cost.

Objective

Connect everything as cheaply as possible

We minimize the sum of chosen edge weights while keeping the graph connected.

Do not confuse the story with shortest paths. MST minimizes the total cost of the whole network; Dijkstra minimizes a route from one source to each destination.

Minimum spanning tree versus shortest paths

An MST minimizes the total cost of the selected network. A shortest-path tree minimizes source-to-vertex path costs. These are different objectives even on the same weighted graph.

Dijkstra: cheapest routes from one source

With edges AB=2, AC=2, BC=1 and source A, the shortest-path tree may use AB and AC. Each destination gets a cheapest route from A; the selected edge total is 4.

≠

MST: cheapest connected network

The MST can use AB and BC for total weight 3. C is reached from A through B, because the objective is the cost of the whole network, not each source-to-vertex route separately.

Objective comparison

Route cost versus network cost

Trip cost suggests shortest paths. Construction cost of a connected network suggests an MST. The graphs can be identical while the optimization objective is different.

Cut property

For any cut of the vertices, a minimum-weight edge crossing that cut is safe for some minimum spanning tree. Kruskal and Prim both rely on this fact.

Cut property

If a cut respects the edges already chosen, then a minimum-weight edge crossing that cut is safe: there exists an MST containing all previously chosen edges plus that edge.

Why it is true

Take an MST T consistent with the current choices. If the light edge e is already in T, we are done. Otherwise add e; this creates a cycle. That cycle must contain another edge f crossing the same cut. Because e is the lightest crossing edge, w(e) ≤ w(f). Remove f. The tree remains spanning and its weight does not increase.

Proof by the first conflicting edge

Assume the current greedy forest is contained in some MST and consider the first selected edge not in that tree. Adding it creates a cycle, from which an edge of no smaller weight can be exchanged out.

Before the mistake

Assume the current greedy forest F is contained in some MST T.

Greedy picks e

The next edge e is lightest across the relevant cut, but suppose e∉T.

Add e to T

A cycle appears. That cycle contains another edge f crossing the same cut.

Exchange

Because w(e)≤w(f), replacing f by e gives an MST that now contains the larger greedy forest.

No first mistake can exist. This is the cut property written as a “first bad decision” contradiction, a proof style that generalizes far beyond MST.

Kruskal's algorithm

Process edges in nondecreasing weight order. Add an edge if and only if it joins two different connected components.

Run Kruskal step by step

The edge list is sorted by weight. Green edges enter the forest; faded edges are rejected because they close a cycle.

Current components
Current forest weight: 0

Why the next accepted edge is safe

Immediately before Kruskal accepts an edge (u,v), vertices u and v lie in different components. Consider the cut formed by one of those components versus the rest. The accepted edge is a lightest available edge crossing a cut that respects the current forest, so the cut property applies.

Prim's algorithm

Start from any vertex and repeatedly add the minimum-weight edge from the current tree to a vertex outside the tree.

Prim’s correctness is almost a direct reading of the cut property: take the cut “vertices already in the tree” versus “vertices not yet in the tree”. The cheapest crossing edge is safe.

Borůvka's algorithm

In each round, every current component selects a cheapest outgoing edge. Adding these safe edges merges components until one spanning tree remains.

1. One choice per component

For each connected component of the current forest, find its minimum-weight outgoing edge.

2. Add all safe edges

Each chosen edge is lightest across the cut “this component versus the rest”, so the cut property makes it safe.

3. Contract and repeat

Merge the connected components created by those edges. The number of components drops by at least a factor of two each round.

Why Borůvka matters

The choices for different components can be found simultaneously, which makes Borůvka a natural starting point for parallel and distributed MST algorithms. A straightforward sequential implementation scans all edges in each of O(log V) rounds, giving O(E log V).

Data structures for MST algorithms

Kruskal repeatedly tests whether two endpoints are already connected; Prim repeatedly finds the cheapest frontier edge. These operations lead naturally to Union-Find and priority queues.

Do not fully order what you do not need

Prim never asks for the complete sorted order of all frontier edges. It repeatedly asks only for the current minimum.

Weak ordering is enough

A heap keeps the minimum accessible while allowing updates without maintaining a globally sorted list. That is precisely the operation profile Prim needs.

Algorithm design has two layers. First prove which local edge is safe; then choose a representation that exposes that edge efficiently.

Union-Find in Kruskal's algorithm

Union-Find maintains the current connected components and answers whether an edge would create a cycle.

find(x)

Which component contains x?

Each component has a representative. If find(u) == find(v), adding edge (u,v) would create a cycle and Kruskal skips it.

union(x,y)

Merge two components

If the representatives differ, the edge is safe with respect to acyclicity. Accept it, then union the two sets so future cycle tests see the new component.

Optimization

Union by size + path compression

Attach the smaller tree under the larger representative and flatten parent chains during find. The operations become effectively constant amortized time.

1for w, u, v in sorted(edges):
2 if find(u) != find(v):
3 take(u, v, w)
4 union(u, v)

Separate the two ideas

Sorting is the greedy priority rule. Union-Find is not the proof of optimality; it is the fast mechanism for enforcing the “no cycles” feasibility constraint.

Kruskal and Prim implementations

Kruskal + DSU

def kruskal(n, edges):
    parent = list(range(n))
    rank = [0] * n

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        a, b = find(a), find(b)
        if a == b:
            return False
        if rank[a] < rank[b]:
            a, b = b, a
        parent[b] = a
        if rank[a] == rank[b]:
            rank[a] += 1
        return True

    mst = []
    for w, u, v in sorted(edges):
        if union(u, v):
            mst.append((u, v, w))
    return mst

Prim + heap

import heapq

def prim(graph, start=0):
    seen = {start}
    heap = []

    for v, w in graph[start]:
        heapq.heappush(heap, (w, start, v))

    mst = []
    while heap and len(seen) < len(graph):
        w, u, v = heapq.heappop(heap)
        if v in seen:
            continue

        seen.add(v)
        mst.append((u, v, w))

        for to, weight in graph[v]:
            if to not in seen:
                heapq.heappush(heap, (weight, v, to))

    return mst

Applications of minimum spanning trees

Clustering

Build an MST of points or objects, then remove the largest edges. What remains are connected clusters separated by expensive links—a simple way to turn connectivity into a hierarchy.

Maximum spanning tree

Run the same greedy logic with weights in the opposite order. Equivalently, negate weights and compute a minimum spanning tree.

Minimum bottleneck

Every MST minimizes the largest edge used among all spanning trees. The objective “minimize the worst link” comes for free from the same structure.

Representation is part of the algorithm

Kruskal naturally wants an edge list plus DSU. Prim naturally wants adjacency by vertex. The mathematical greedy choice may be the same quality while the best data structure changes with graph density.

Useful properties

Distinct weights imply uniqueness

If every edge weight is different, the graph has a unique MST.

Ties may give several MSTs

Different safe choices of equal weight can lead to different spanning trees with the same minimum total weight.

Disconnected graph

There is no spanning tree. Kruskal instead produces a minimum spanning forest, one tree per connected component.

Negative edge weights are fine

Unlike Dijkstra, MST algorithms have no problem with negative weights. They simply prefer them when they are safe.

Exercises

1

Tree edge count

How many edges must a spanning tree on 17 vertices contain?

Exactly 16 edges.
2

Kruskal decision

Why does Kruskal reject an edge whose endpoints are already in the same DSU component?

There is already a path between the endpoints. Adding the edge would create a cycle, so it cannot belong to the current forest.
3

Ties and multiple MSTs

Take a triangle whose three edges all have weight 1. How many different MSTs does it have, and what does this say about “safe” edges?

Any two of the three edges form an MST, so there are three MSTs. A light edge can be safe—contained in some MST—without being forced into every MST.
