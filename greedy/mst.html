Minimum Spanning Trees

Connect every vertex with minimum total edge weight. Kruskal and Prim look different, but both are powered by the same cut property.

Connect everything as cheaply as possible

We need a connected set of edges that reaches every vertex and contains no cycle. Among all such trees, choose the one with minimum total weight.

Minimum Spanning Tree

A spanning tree contains every vertex, is connected, has no cycles, and therefore uses exactly |V|−1 edges. An MST is a spanning tree of minimum total edge weight.

MST is not a shortest-path tree. It minimizes the sum of all selected edge weights, not the distance from one source to every vertex.

One fact powers both algorithms: the cut property

A cut simply separates the vertices into two nonempty sides, S and V\S. The useful question is: which edge is the cheapest way to cross from one side to the other?

Cut property

If a cut respects the edges already chosen, then a minimum-weight edge crossing that cut is safe: there exists an MST containing all previously chosen edges plus that edge.

Why it is true

Take an MST T consistent with the current choices. If the light edge e is already in T, we are done. Otherwise add e; this creates a cycle. That cycle must contain another edge f crossing the same cut. Because e is the lightest crossing edge, w(e) ≤ w(f). Remove f. The tree remains spanning and its weight does not increase.

A powerful proof habit: assume the first greedy mistake

For incremental greedy algorithms, it is often easier to reason about the first choice that could possibly destroy optimality. Before that moment, the partial greedy solution still fits inside some optimum.

Before the mistake

Assume the current greedy forest F is contained in some MST T.

Greedy picks e

The next edge e is lightest across the relevant cut, but suppose e∉T.

Add e to T

A cycle appears. That cycle contains another edge f crossing the same cut.

Exchange

Because w(e)≤w(f), replacing f by e gives an MST that now contains the larger greedy forest.

No first mistake can exist. This is the cut property written as a “first bad decision” contradiction, a proof style that generalizes far beyond MST.

Kruskal: grow a forest

Sort all edges by weight. Walk through them once. Keep an edge if it joins two different components; reject it if its endpoints are already connected.

Why the next accepted edge is safe

Immediately before Kruskal accepts an edge (u,v), vertices u and v lie in different components. Consider the cut formed by one of those components versus the rest. The accepted edge is a lightest available edge crossing a cut that respects the current forest, so the cut property applies.

Prim: grow one tree

Start from any vertex. Keep one connected tree and repeatedly add the cheapest edge leaving that tree. The new endpoint joins the tree; the frontier updates.

Prim’s correctness is almost a direct reading of the cut property: take the cut “vertices already in the tree” versus “vertices not yet in the tree”. The cheapest crossing edge is safe.

Borůvka: every component moves at once

Kruskal chooses one safe edge at a time; Prim grows one component. Borůvka lets every current component choose its cheapest outgoing edge in the same round.

1. One choice per component

For each connected component of the current forest, find its minimum-weight outgoing edge.

2. Add all safe edges

Each chosen edge is lightest across the cut “this component versus the rest”, so the cut property makes it safe.

3. Contract and repeat

Merge the connected components created by those edges. The number of components drops by at least a factor of two each round.

Why Borůvka matters

The choices for different components can be found simultaneously, which makes Borůvka a natural starting point for parallel and distributed MST algorithms. A straightforward sequential implementation scans all edges in each of O(log V) rounds, giving O(E log V).

Same proof, different data structures

Kruskal + DSU

def kruskal(n, edges):
    parent = list(range(n))
    rank = [0] * n

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        a, b = find(a), find(b)
        if a == b:
            return False
        if rank[a] < rank[b]:
            a, b = b, a
        parent[b] = a
        if rank[a] == rank[b]:
            rank[a] += 1
        return True

    mst = []
    for w, u, v in sorted(edges):
        if union(u, v):
            mst.append((u, v, w))
    return mst

Prim + heap

import heapq

def prim(graph, start=0):
    seen = {start}
    heap = []

    for v, w in graph[start]:
        heapq.heappush(heap, (w, start, v))

    mst = []
    while heap and len(seen) < len(graph):
        w, u, v = heapq.heappop(heap)
        if v in seen:
            continue

        seen.add(v)
        mst.append((u, v, w))

        for to, weight in graph[v]:
            if to not in seen:
                heapq.heappush(heap, (weight, v, to))

    return mst

Since E ≤ V², the logarithmic factors are closely related. In practice, representation and surrounding code often matter more than the asymptotic distinction.

What else the MST structure gives you

Clustering

Build an MST of points or objects, then remove the largest edges. What remains are connected clusters separated by expensive links—a simple way to turn connectivity into a hierarchy.

Maximum spanning tree

Run the same greedy logic with weights in the opposite order. Equivalently, negate weights and compute a minimum spanning tree.

Minimum bottleneck

Every MST minimizes the largest edge used among all spanning trees. The objective “minimize the worst link” comes for free from the same structure.

Dense vs sparse implementation

Heap-based Prim is natural for sparse adjacency lists. A simple O(V²) array implementation can be competitive on dense graphs because it avoids heap overhead.

Representation is part of the algorithm

Kruskal naturally wants an edge list plus DSU. Prim naturally wants adjacency by vertex. The mathematical greedy choice may be the same quality while the best data structure changes with graph density.

Four facts worth remembering

MST is the clean matroid example

The edge sets that contain no cycle form the graphic matroid. A spanning tree is a basis of this matroid. Kruskal is therefore an instance of the general matroid greedy theorem: order elements by weight and keep an element whenever independence is preserved. The cut-property proof is the graph-specific form of that exchange theorem.

Distinct weights imply uniqueness

If every edge weight is different, the graph has a unique MST.

Ties may give several MSTs

Different safe choices of equal weight can lead to different spanning trees with the same minimum total weight.

Disconnected graph

There is no spanning tree. Kruskal instead produces a minimum spanning forest, one tree per connected component.

Negative edge weights are fine

Unlike Dijkstra, MST algorithms have no problem with negative weights. They simply prefer them when they are safe.

Exercises

1

Tree edge count

How many edges must a spanning tree on 17 vertices contain?

Exactly 16 edges.
2

Kruskal decision

Why does Kruskal reject an edge whose endpoints are already in the same DSU component?

There is already a path between the endpoints. Adding the edge would create a cycle, so it cannot belong to the current forest.
3

Ties and multiple MSTs

Take a triangle whose three edges all have weight 1. How many different MSTs does it have, and what does this say about “safe” edges?

Any two of the three edges form an MST, so there are three MSTs. A light edge can be safe—contained in some MST—without being forced into every MST.
