Chapter 9 · Section 11

Matroids and Beyond

A final map of the chapter: when a general exchange theorem guarantees greedy optimality, when greedy proofs work for other reasons, and when greedy is valuable even without an exact optimum.

Three different reasons greedy can be useful

The previous ten pages all make irreversible local choices, but they are not instances of one single theorem. It is useful to separate three levels of structure.

Exact + matroidA general theorem guarantees greedy

Kruskal is the clean example: acyclic edge sets form a graphic matroid.

Exact + problem-specificA tailored exchange or invariant proves safety

Interval Scheduling, Huffman, Fractional Knapsack, and Dijkstra live here.

Approximate greedyThe local rule is not exact, but has a provable ratio

Set Cover is the standard example.

Matroids: when exchange is an axiom

A matroid is a finite ground set E together with a family 𝓘 of subsets called independent sets. The definition makes “borrowing” an element from a larger independent set always possible.

1

Nonempty

∅ ∈ 𝓘.

2

Hereditary

If B ∈ 𝓘 and A ⊆ B, then A ∈ 𝓘.

3

Exchange

If A,B ∈ 𝓘 and |A| < |B|, some x ∈ B \ A satisfies A ∪ {x} ∈ 𝓘.

Matroid greedy theorem

With nonnegative element weights, sort from largest weight to smallest and add an element whenever independence is preserved: this gives a maximum-weight independent set. For a minimum-weight basis, process weights from smallest to largest.

Why this is stronger than one clever proof

Once the feasible sets are known to form a matroid, the greedy rule works for every weight assignment covered by the theorem. The exchange axiom supplies the proof globally.

Kruskal is matroid greedy

For a graph, take the edges as the ground set and call an edge set independent when it contains no cycle. These independent sets form the graphic matroid.

1

Sort edges from lightest to heaviest.

2

Add an edge exactly when the selected edges remain acyclic.

3

A maximal independent set in a connected graph is a spanning tree—a basis of the graphic matroid.

Kruskal is exactly the minimum-weight basis algorithm for the graphic matroid.

An exchange proof does not automatically mean “matroid”

Several algorithms in the chapter use exchanges, but their feasible objects do not satisfy the matroid axioms.

Interval Scheduling is not a matroid

Let A={[0,4)} and B={[0,2),[2,4)}. Both are feasible and |A|<|B|, but neither interval from B can be added to A without overlap. The exchange axiom fails.

Yet earliest finish is still optimal

Its proof exchanges the first choice in a schedule, not arbitrary elements between all feasible sets. Problem-specific exchange is broader than matroid exchange.

Huffman

The proof swaps leaf labels and contracts two siblings. It is a recursive merge argument, not selection of an independent subset.

Fractional Knapsack

The exchange happens in a continuous amount of weight, closer to a linear relaxation than a finite independence system.

Dijkstra

The safe object is a finalized distance. Correctness comes from nonnegative path extensions, not a matroid axiom.

0/1 Knapsack

The capacity constraint lacks the needed exchange structure: one locally attractive item can block a better combination.

When exact search explodes, change the question

Set Cover is a useful turning point in the chapter because the exact formulation is easy to state but expensive to search exhaustively.

Exact search

With m candidate sets, enumerate subsets of those sets and keep the smallest cover. There are 2^m subsets before we even check whether each one covers the universe.

→

Greedy approximation

Repeatedly choose the set that covers the largest number of still-uncovered elements. We stop asking for guaranteed equality with OPT and instead ask for speed plus a provable quality bound.

Criterion 1: speed

Can the algorithm handle input sizes for which enumerating every subset is hopeless?

Criterion 2: solution quality

How far from OPT can the answer be in the worst case? This is what separates an approximation theorem from “seems good”.

Heuristics and approximation algorithms are not the same thing

Both may return a non-optimal solution, but only one comes with a theorem about how bad the answer can be.

Heuristic

Designed to work well or quickly in practice. Quality may be excellent on real data, but there is no general worst-case ratio unless one is separately proved.

Approximation algorithm

Runs efficiently and comes with a proved relationship to OPT. For a minimization problem, a ratio α means ALG ≤ α·OPT on every allowed input.

Why the distinction matters. “Greedy is often good enough” is an engineering statement. “Greedy is within ln n+1 of optimum” is a mathematical guarantee.

Coverage can be exact when the geometry gives you an order

General Set Cover needs approximation, but a one-dimensional covering problem can have a clean exact greedy rule.

Cell towers along a road

Suppose houses lie at points on a line and each tower covers distance R in both directions. Let x be the leftmost uncovered house. Any valid solution must place some tower within distance R of x. Push that tower as far right as possible—to x+R—so it still covers x while reaching maximally far into the future.

1

Find the leftmost uncovered house x.

2

Place a tower at the rightmost location that still covers it: x+R.

3

That tower covers through x+2R; discard all houses in that range and repeat.

Exchange intuition

Take any optimal solution’s tower that covers the first uncovered house. Sliding it right until x+R cannot uncover any house to the right that it previously covered, and there are no still-uncovered houses to the left of x. So the greedy placement is safe.

Structural lesson. The same word “cover” can mean exact greedy on a line and approximation in unrestricted Set Cover. Geometry changes the feasible structure.

Greedy can be valuable without being exact

Approximation algorithms ask a different question: if greedy misses the optimum, how far away can it ever be?

Set Cover

There are n elements and a collection of sets covering them. Repeatedly choose the set containing the largest number of still-uncovered elements. The result may not use the minimum number of sets, but it uses at most Hₙ times optimum, where Hₙ=1+1/2+···+1/n ≤ ln n+1.

Exact greedy

Prove every irreversible choice is safe. The approximation ratio is 1.

Approximation greedy

Allow local loss, then bound the total loss across all steps.

An MST can be a scaffold for approximation

A classic example shows how an exactly solved greedy subproblem can become part of an approximation algorithm for a harder problem.

1

Build an MST

Its weight is at most the weight of an optimal travelling-salesperson tour with one edge removed, so w(MST) ≤ OPT.

2

Walk the tree

A depth-first traversal that returns along tree edges uses each MST edge twice, for total walk length 2w(MST).

3

Shortcut repeats

For metric distances, triangle inequality lets us skip already visited vertices without increasing the tour length.

tour ≤ 2·w(MST) ≤ 2·OPT

The condition matters

The simple “MST + DFS gives factor 2” sketch is valid for metric TSP, where distances satisfy the triangle inequality. Without that condition, shortcutting repeated vertices need not preserve the bound.

Worked approximation example: Set Cover

Imagine radio stations whose broadcast areas overlap. We want to cover every target region while choosing as few stations as possible.

1

Keep a set uncovered of regions still needing coverage.

2

For each station, compute uncovered & station_regions. Its size is the number of new regions that station would add right now.

3

Choose the station with the largest intersection, add it to the answer, and remove those newly covered regions with set difference.

4

Repeat until uncovered is empty.

chosen = []
while uncovered:
    best = max(
        stations,
        key=lambda s: len(uncovered & stations[s])
    )
    newly_covered = uncovered & stations[best]
    if not newly_covered:
        raise ValueError("universe cannot be covered")
    chosen.append(best)
    uncovered -= newly_covered

Why sets fit the algorithm

The mathematics of the greedy step is literally set intersection and set difference: intersection measures the immediate gain, and difference updates what remains. The data structure mirrors the problem statement.

The stronger theorem

The intuitive rule above is not merely “often good”. Greedy Set Cover has the harmonic approximation guarantee H_n ≤ ln n + 1, where n is the universe size.

Set Cover becomes simple when the data matches the operation

The greedy rule repeatedly asks one set question: “How many still-uncovered elements would this candidate add?” Python sets make that question almost literal.

Exact search

Try every subset of sets

There are exponentially many subsets. Exact brute force is conceptually simple but becomes unusable quickly.

Greedy step

Take maximum new coverage

For every candidate set, compute its intersection with the uncovered elements and choose the largest.

Evaluate approximation

Speed + closeness to OPT

An approximation algorithm is useful because it is efficient and because its solution quality can be bounded.

def greedy_set_cover(universe, sets):
    uncovered = set(universe)
    chosen = []

    while uncovered:
        best_name = None
        best_new = set()

        for name, elements in sets.items():
            newly = uncovered & elements
            if len(newly) > len(best_new):
                best_name = name
                best_new = newly

        if best_name is None:
            raise ValueError("universe is not fully coverable")

        chosen.append(best_name)
        uncovered -= best_new

    return chosen
Implementation mirrors the idea. Intersection finds new coverage; set difference removes what is already covered. Good data structures can make an algorithmic idea much easier to see in code.

Greedy is broader than “sort and select”

A useful optimization view is that greedy can compress a large space of partial possibilities into a tiny running state—provided the discarded possibilities are provably dominated.

One value

Array maximum

All previous values smaller than best_so_far are irrelevant to the final maximum. One number summarizes the prefix.

One running prefix

Maximum subarray

A negative accumulated prefix can never help a future continuation. Resetting it removes an entire family of dominated histories.

Two thresholds

Increasing triplet

Keep the lowest first value and the lowest feasible middle threshold. Lower thresholds dominate higher ones because they are easier for a future third value to exceed.

Best-imaginable Big O is a design target, not a correctness proof

Knowing that an O(n) solution feels plausible can motivate a one-pass search for compressed state. It does not justify the discard rule. Correctness still requires an invariant, dominance argument, exchange, or another proof.

A compact state is the reward for a proof. First show which alternatives can never matter again; only then delete them from the algorithm.

There is no one-size-fits-all greedy template—build a pattern library instead

A better way to prepare for interviews is to remember several structural moves and the proof obligation behind each one.

Backward frontier

Reachability

Replace a far destination by an earlier index that can already reach it. The proof shows earlier solutions are preserved.

Block elimination

Circular feasibility

A failed prefix can certify that many possible starting points are impossible, so the candidate jumps forward instead of backtracking.

Directional passes

Local inequalities

When constraints come from left and right neighbors, satisfy each direction separately and combine the necessary lower bounds.

Sorted intervals

Ordering creates locality

Sorting by the right endpoint feature can turn global overlap questions into comparisons against one current frontier.

Priority queue

Repeated best candidate

If a changing candidate set repeatedly asks for the current minimum or maximum, a heap often exposes exactly the choice the greedy rule needs.

Union-Find

Dynamic components

If greedy considers edges while needing fast “same component?” checks, DSU separates feasibility maintenance from the greedy priority rule.

What pattern recognition should not become

Do not match keywords to memorized code. Match the problem to an invariant: what frontier is safe, what candidates are dominated, what constraint is being enforced, and what information can be discarded permanently?

A checklist for new problems

1

Can feasible partial solutions be viewed as an independence system? If yes, test the matroid exchange axiom.

2

Can an optimum be locally transformed to agree with the greedy choice? A problem-specific exchange proof may be enough without a matroid.

3

Does the future need several incomparable states? That points toward dynamic programming.

4

If exact greedy fails, can the loss be charged or bounded? That opens the door to approximation algorithms.

Exercises

1

Test the exchange axiom

Use A={[0,4)} and B={[0,2),[2,4)} to explain exactly which matroid axiom interval scheduling violates.

Both sets are feasible and |A|<|B|, but no element of B\A can be added to A while preserving non-overlap. The exchange axiom fails.
2

Uniform matroid

Suppose any subset of at most k elements is feasible. What does matroid greedy do for maximum weight?

It takes the k largest positive weights. These feasible sets form the uniform matroid U(k,n).
3

Exact or approximate?

What changes in a proof when greedy is only an approximation algorithm?

You no longer prove each choice preserves an optimum. Instead, compare greedy with a lower or upper bound on OPT and prove the total loss stays within a factor.
