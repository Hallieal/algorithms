Chapter 9 · Section 11

Matroids and Beyond

A final map of the chapter: when a general exchange theorem guarantees greedy optimality, when greedy proofs work for other reasons, and when greedy is valuable even without an exact optimum.

Three different reasons greedy can be useful

The previous ten pages all make irreversible local choices, but they are not instances of one single theorem. It is useful to separate three levels of structure.

Exact + matroidA general theorem guarantees greedy

Kruskal is the clean example: acyclic edge sets form a graphic matroid.

Exact + problem-specificA tailored exchange or invariant proves safety

Interval Scheduling, Huffman, Fractional Knapsack, and Dijkstra live here.

Approximate greedyThe local rule is not exact, but has a provable ratio

Set Cover is the standard example.

Matroids: when exchange is an axiom

A matroid is a finite ground set E together with a family 𝓘 of subsets called independent sets. The definition makes “borrowing” an element from a larger independent set always possible.

1

Nonempty

∅ ∈ 𝓘.

2

Hereditary

If B ∈ 𝓘 and A ⊆ B, then A ∈ 𝓘.

3

Exchange

If A,B ∈ 𝓘 and |A| < |B|, some x ∈ B \ A satisfies A ∪ {x} ∈ 𝓘.

Matroid greedy theorem

With nonnegative element weights, sort from largest weight to smallest and add an element whenever independence is preserved: this gives a maximum-weight independent set. For a minimum-weight basis, process weights from smallest to largest.

Why this is stronger than one clever proof

Once the feasible sets are known to form a matroid, the greedy rule works for every weight assignment covered by the theorem. The exchange axiom supplies the proof globally.

Kruskal is matroid greedy

For a graph, take the edges as the ground set and call an edge set independent when it contains no cycle. These independent sets form the graphic matroid.

1

Sort edges from lightest to heaviest.

2

Add an edge exactly when the selected edges remain acyclic.

3

A maximal independent set in a connected graph is a spanning tree—a basis of the graphic matroid.

Kruskal is exactly the minimum-weight basis algorithm for the graphic matroid.

An exchange proof does not automatically mean “matroid”

Several algorithms in the chapter use exchanges, but their feasible objects do not satisfy the matroid axioms.

Interval Scheduling is not a matroid

Let A={[0,4)} and B={[0,2),[2,4)}. Both are feasible and |A|<|B|, but neither interval from B can be added to A without overlap. The exchange axiom fails.

Yet earliest finish is still optimal

Its proof exchanges the first choice in a schedule, not arbitrary elements between all feasible sets. Problem-specific exchange is broader than matroid exchange.

Huffman

The proof swaps leaf labels and contracts two siblings. It is a recursive merge argument, not selection of an independent subset.

Fractional Knapsack

The exchange happens in a continuous amount of weight, closer to a linear relaxation than a finite independence system.

Dijkstra

The safe object is a finalized distance. Correctness comes from nonnegative path extensions, not a matroid axiom.

0/1 Knapsack

The capacity constraint lacks the needed exchange structure: one locally attractive item can block a better combination.

Heuristics and approximation algorithms are not the same thing

Both may return a non-optimal solution, but only one comes with a theorem about how bad the answer can be.

Heuristic

Designed to work well or quickly in practice. Quality may be excellent on real data, but there is no general worst-case ratio unless one is separately proved.

Approximation algorithm

Runs efficiently and comes with a proved relationship to OPT. For a minimization problem, a ratio α means ALG ≤ α·OPT on every allowed input.

Why the distinction matters. “Greedy is often good enough” is an engineering statement. “Greedy is within ln n+1 of optimum” is a mathematical guarantee.

Greedy can be valuable without being exact

Approximation algorithms ask a different question: if greedy misses the optimum, how far away can it ever be?

Set Cover

There are n elements and a collection of sets covering them. Repeatedly choose the set containing the largest number of still-uncovered elements. The result may not use the minimum number of sets, but it uses at most Hₙ times optimum, where Hₙ=1+1/2+···+1/n ≤ ln n+1.

Exact greedy

Prove every irreversible choice is safe. The approximation ratio is 1.

Approximation greedy

Allow local loss, then bound the total loss across all steps.

Worked approximation example: Set Cover

The greedy step is easy to execute: among the remaining sets, choose the one that covers the most elements not yet covered. The proof of the approximation ratio is harder than the algorithm.

1

Universe: {1,2,3,4,5,6}. Suppose A covers {1,2,3}, B covers {2,4,5}, C covers {3,5,6}, and D covers {4,6}.

2

Greedy first takes A because it covers three uncovered elements. Remaining: {4,5,6}.

3

B and C each cover two remaining elements. Choose either; after B, only {6} remains, so C or D finishes the cover.

What the approximation proof measures

At each stage, if OPT uses k sets to cover what remains, some OPT-set must cover at least a 1/k fraction of the remaining elements. Greedy covers at least that much. Repeating this charging idea yields the harmonic bound.

A checklist for new problems

1

Can feasible partial solutions be viewed as an independence system? If yes, test the matroid exchange axiom.

2

Can an optimum be locally transformed to agree with the greedy choice? A problem-specific exchange proof may be enough without a matroid.

3

Does the future need several incomparable states? That points toward dynamic programming.

4

If exact greedy fails, can the loss be charged or bounded? That opens the door to approximation algorithms.

Five textbook lenses behind this chapter

The strongest version of this handbook does not imitate one textbook. It combines different teaching strengths.

Steven S. Skiena — The Algorithm Design Manual

Best lens: design by false starts. Try a plausible rule, build a counterexample, then isolate the structural reason the successful rule survives. The weighted-graph chapters also emphasize exchange proofs and practical modeling.

Useful here: strategy, proofs, interval scheduling, MST, Dijkstra, heuristics vs approximation.

Narasimha Karumanchi — Data Structures and Algorithms Made Easy

Best lens: breadth of variants and exercises. It connects greedy to Huffman, interval coloring, coin change, fractional knapsack, platform counting, job scheduling, Prim/Kruskal, and Dijkstra.

Useful here: edge cases, alternative implementations, sweep line, problem bank.

Alex Xu & Shaun Gunawardane — Coding Interview Patterns

Best lens: recognition through invariants. Jump Game compresses a suffix to one frontier, Gas Station eliminates blocks of candidates, and Candies solves directional constraints with two passes.

Useful here: strategy recognition, Greedy vs DP, interview-style exercises.

Jay Wengrow — A Common-Sense Guide to Data Structures and Algorithms in Python

Best lens: derive the fast solution from a slow one in plain language. The greedy discussion treats pattern discovery as an optimization technique rather than a bag of named algorithms.

Useful here: intuition, runtime motivation, Dijkstra walkthrough.

Aditya Y. Bhargava — Grokking Algorithms

Best lens: visual intuition and memorable stories. Its scheduling, knapsack, Set Cover, Huffman, and Dijkstra explanations make the local choice tangible before formalizing it.

Useful here: pictures-in-words, approximation intuition, prefix-code and shortest-path mental models.

Exercises

1

Test the exchange axiom

Use A={[0,4)} and B={[0,2),[2,4)} to explain exactly which matroid axiom interval scheduling violates.

Both sets are feasible and |A|<|B|, but no element of B\A can be added to A while preserving non-overlap. The exchange axiom fails.
2

Uniform matroid

Suppose any subset of at most k elements is feasible. What does matroid greedy do for maximum weight?

It takes the k largest positive weights. These feasible sets form the uniform matroid U(k,n).
3

Exact or approximate?

What changes in a proof when greedy is only an approximation algorithm?

You no longer prove each choice preserves an optimum. Instead, compare greedy with a lower or upper bound on OPT and prove the total loss stays within a factor.
