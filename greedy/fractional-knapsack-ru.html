Дробная задача о рюкзаке

Fractional Knapsack точно решается сортировкой items по value density и последовательным заполнением capacity, при необходимости используя долю последнего item.

Постановка задачи

У каждого item есть weight и value, capacity ограничена, но item можно делить. Нужно максимизировать суммарный value.

ПравилоСначала берём максимальную ценность на единицу веса

Идём по убыванию отношения vᵢ/wᵢ.

Почему работаетОдинаковый вес выгоднее держать в более плотном предмете

Перенос веса с меньшей плотности на большую не уменьшает ценность.

СложностьO(n log n)

Посчитать отношения, отсортировать, пройти один раз.

Дробный рюкзак

Нужно выбрать доли 0 ≤ xᵢ ≤ 1, максимизируя ∑ xᵢvᵢ при ограничении ∑ xᵢwᵢ ≤ W.

Стандартные предположения

В математической постановке обычно предполагают wᵢ > 0 и vᵢ ≥ 0. Код ниже чуть устойчивее: отрицательный вес запрещён, предметы с неположительной ценностью пропускаются, а положительная ценность при нулевом весе берётся бесплатно.

Fractional и 0/1 Knapsack

Divisibility меняет задачу: value density даёт точный greedy для Fractional Knapsack, но не для general 0/1 Knapsack.

Только целые items

В классическом примере с вором самый дорогой отдельный предмет даёт value 3000, тогда как другая пара стоит 3500. После первого выбора занятую capacity уже нельзя «откусить» обратно маленькими кусками.

Fractions разрешены

Теперь capacity можно тратить непрерывно. Вопрос меняется с «какой целый объект лучший?» на «куда отдать следующую единицу веса?». Ответ — item с максимальной value density.

0/1 decision

Либо берём item i, либо нет: xᵢ∈{0,1}. Один ранний выбор может заблокировать лучшую комбинацию.

→

Fractional decision

Можно взять любую долю 0≤xᵢ≤1. Одинаковые порции веса можно переносить между items — именно это делает density-proof корректным.

Главный modeling lesson

Greedy-rule не стал магически умнее. Изменилось множество допустимых решений.

Divisibility — то самое предположение, которое превращает естественную density-эвристику в exact greedy algorithm.

Специальные случаи Knapsack

Equal values, equal weights, divisibility и integer capacity дают разную структуру. Выбор алгоритма зависит от того, какие assumptions выполняются.

VariantЧто даёт structureЕстественный method
Items divisibleCapacity можно непрерывно переносить между itemsExact greedy по убыванию v_i/w_i
0/1, у всех items одинаковый valueMaximize value = maximize число itemsСначала smallest weights
0/1, у всех items одинаковый weightКаждый chosen item тратит одинаковую capacityСначала largest values
General 0/1, integer capacityПростой order не доминирует, но capacity задаёт DP stateDynamic programming за O(nC)
Одинаковая density не делает general 0/1 Knapsack простым. Если у всех items одинаковый value-to-weight ratio, остаётся задача плотно упаковать sizes и использовать capacity — это уже subset-sum structure, а не полезный greedy ranking.
Ищите, что схлопывает choice. Divisibility, equal values или equal sizes могут превратить трудный combinatorial choice в простой ordering rule; без такой structure density для 0/1 Knapsack остаётся лишь heuristic.

Почему divisibility меняет ответ

В 0/1 instance density-order может ошибаться, потому что целые items нельзя обменивать на произвольный вес. Fractional model снимает это ограничение.

0/1: сначала самый valuable item

Берём weight 5, value 70. Остаётся одна единица capacity, поэтому weight-1 item добавляет 10. Итого 80.

0/1 optimum

Берём weights 3 и 4 со values 50 и 40. Они ровно заполняют capacity 7 и дают 90.

Теперь разрешим fractions

Densities равны 14, 50/3≈16.67, 10 и 10. Fractional Knapsack может полностью взять weight-3 item, а оставшиеся 4 units capacity потратить на 4/5 weight-5 item. Divisibility позволяет непрерывно исправлять решение exchange-ом по density.

Вопрос, который надо задать сразу

«Можно ли брать часть item?» Если да — проверяйте value density. Если items неделимы, ordering по density или raw value требует отдельного proof; для общего 0/1 Knapsack такого exact greedy rule нет.

Плотность ценности

Для item i определим density как v_i / w_i. Это value, получаемый с единицы capacity, и именно по этой величине сортируются делимые items.

Алгоритм

1

Считаем плотности

Для каждого предмета вычисляем vᵢ/wᵢ.

2

Сортируем по убыванию

Сначала рассматриваем предметы с максимальной ценностью на единицу веса.

3

Берём целиком, пока помещается

Если текущий предмет помещается, кладём его полностью.

4

Берём последнюю долю

Если следующий предмет целиком не помещается, берём ровно ту долю, которая заполнит остаток вместимости.

Заполним рюкзак вместимости 50

Предметы идут по убыванию ценности на единицу веса.

Обменное доказательство

Если solution использует часть low-density item, оставляя неиспользованной часть high-density item, переносим тот же weight на более плотный item. Feasibility сохраняется, value не уменьшается.

Перенесём маленький вес δ с предмета меньшей плотности на предмет большей плотности. Общий вес не меняется, а ценность меняется на δ(rhigh − rlow) ≥ 0. Значит, существует оптимальное решение, в котором предметы большей плотности заполняются раньше.

Свойство жадного выбора

Существует оптимальное решение, которое берёт максимально возможную долю текущего предмета с наибольшей плотностью. После этого то же рассуждение применяется к оставшейся вместимости.

Линейная интерпретация

При одном capacity constraint и делимых items оптимум можно выбрать как полный prefix density-order плюс не более одного fractional item.

1

Единица capacity, потраченная на density ρ₁, ценнее или равна той же единице на меньшей density ρ₂.

2

Если low-density item уже используется, а high-density item ещё не заполнен, переносим небольшую порцию веса вверх. Value не уменьшается.

3

После всех обменов получаем полностью заполненный density-sorted prefix, возможно один fractional boundary item, затем нули. При ties можно выбрать эквивалентный optimum такой формы.

marginal value одной дополнительной единицы capacity = value / weight

Роль divisibility

Доказательство использует возможность переносить произвольное количество weight между items. В 0/1 model такая операция запрещена.

0/1: только целые items

После выбора leftover capacity может плохо подходить оставшимся предметам. Нельзя заменить «немного» одного объекта другим, поэтому локальная density не обязана сохранять OPT.

Fractional: weight делим

Если часть low-density weight уже лежит в рюкзаке, а high-density weight ещё доступен, переносим маленькую порцию capacity наверх. Value только увеличится.

Урок моделирования

До вопроса «какой greedy-rule?» спросите «какие операции вообще разрешены?»

Proof работает именно потому, что fractions допустимы. Уберите это разрешение — и тот же priority перестаёт быть безопасным.

Почему proof не работает для 0/1 Knapsack

Для indivisible items обмен из fractional proof может быть невозможен. High-density item способен заблокировать более ценную комбинацию других items.

Дробная версия

Вместимость 50, A=(10,60), B=(20,100), C=(30,120). Greedy по плотности даёт 240: A, B и 2/3 C. Это оптимум.

Версия 0/1

Тот же порядок по плотности берёт A и B и получает 160. Но B+C помещаются ровно и дают 220. Первый жадный выбор A блокирует оптимум.

Вывод. Небольшое изменение модели может полностью уничтожить жадное свойство. Нельзя переносить доказательство с одной версии задачи на другую, не проверив ключевое предположение.

Но дробный greedy всё ещё полезен для 0/1 Knapsack

Оптимум дробной задачи — верхняя граница для 0/1-оптимума: разрешение дробей может только улучшить ответ. Такая граница используется в branch-and-bound. Для точного 0/1 Knapsack стандартный DP по вместимости псевдополиномиален. Простое density-greedy само по себе не имеет постоянной гарантии приближения; для approximation нужен дополнительный приём, например сравнение с лучшим одиночным предметом.

Сложность

Полная сортировка по density даёт O(n log n). Если потребуется лишь небольшое число лучших items, можно использовать priority queue.

Naive

Сканировать remaining items ради maximum density

Повторяющийся linear maximum search после каждого выбранного item может стоить O(n²).

Sort once

Заранее упорядочить densities

Считаем ratios за O(n), сортируем за O(n log n), затем проходим список один раз.

Heap alternative

Показывать только следующий maximum

Если capacity заполнится после извлечения лишь c items, max-heap строится за O(n) и делает c extractions за O(c log n).

Proof задаёт order relation, а не обязуется использовать sorting. Когда “largest density next” уже доказано, data structure стоит выбирать по операциям конкретного input.

Сортировка и priority queue

Обе реализации следуют одному density-order; отличается только способ извлечения следующего item.

РеализацияСтоимостьКогда удобна
Отсортировать все items по densityO(n log n)Самый простой код; всё равно просматриваем почти все items.
Построить max-heap по densityO(n + c log n)Если capacity заполнится после извлечения только c лучших items и c ≪ n.

Не оптимизируйте структуру данных раньше доказательства

Proof относится к density order, а не к сортировке как таковой. После доказательства greedy-order sort и priority queue становятся взаимозаменяемыми implementation choices.

Задачи

1

Плотность

Предмет имеет вес 8 и ценность 52. Чему равна его ценность на единицу веса?

52 / 8 = 6.5.
2

Последняя доля

Осталась вместимость 10, следующий предмет весит 25 и имеет ценность 100. Какую долю берём и какую ценность она добавит?

Берём 10/25 = 40% предмета. Добавленная ценность: 0.4·100 = 40.
3

Предположение доказательства

Какое свойство задачи позволяет в обменном аргументе переносить одинаковый вес между двумя предметами?

Делимость предметов. Без дробных решений обмен одинакового веса может вообще не соответствовать допустимому решению.
4

Граничные случаи

Что должно происходить, если вместимость уже равна 0? А если предмет имеет вес 0 и положительную ценность?

При вместимости 0 нельзя брать предметы положительного веса. Но положительная ценность нулевого веса ничего не расходует, поэтому её надо взять; именно поэтому код обрабатывает такие предметы до основного цикла по capacity.
5

Sort или heap?

Есть n items, но knapsack заполняется после извлечения только c high-density items. Сравните полный sorting и max-heap.

Sorting стоит O(n log n). Heapify — O(n), затем c извлечений по O(log n), итого O(n + c log n). Heap особенно выгоден, когда c намного меньше n.
