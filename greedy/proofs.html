Proving Greedy Correctness

A greedy proof has one job: show that the next local choice can be fixed without losing optimality.

What a greedy proof must show

The code may be one loop. The proof has to explain why that loop is allowed to throw alternatives away. At every step, we need to know that at least one optimal solution is still compatible with the choices already fixed.

What to proveThe next greedy choice is safe

Some optimal solution can be made to contain it.

ThenReduce to a smaller instance

The remaining decisions must have the same structure.

Typical toolsExchange, staying ahead, cuts

Pick the proof that matches the shape of the problem.

The core statement

After the greedy algorithm makes its next choice, there must still be at least one optimal solution consistent with all choices made so far.

Safety of the choice

The next greedy decision can be included in some optimal solution.

Correct remainder

After fixing that decision, the rest of the problem can be solved optimally using the same structure.

Four proof patterns worth knowing

Most greedy proofs are variations of a few ideas. The names matter less than the move you make: exchange a choice, compare partial progress, reduce the instance, or use a cut.

↔

Exchange argument

Start from an optimal solution. If it does not use the greedy choice, modify it so that it does, without making the objective worse.

≥

Greedy stays ahead

Compare the greedy partial solution with an arbitrary optimal one after every step and show that greedy is never behind.

1

Induction on choices

Prove the first greedy choice is safe, reduce the problem, then apply the same reasoning to the smaller instance.

✂

Safe edge / cut argument

For graph problems, identify a boundary and prove that a best edge crossing it can safely be added.

These patterns are different views of the same move

An exchange argument proves one local replacement is safe. “Staying ahead” repeats that comparison over every prefix. Induction packages the same safe step into a proof on the reduced instance. A cut proof is an exchange argument specialized to graph structure. In practice, these techniques often appear together rather than in isolation.

Counterexamples are a proof tool too

Before proving a greedy rule, actively try to falsify it. Tiny failures are often more informative than a page of successful examples because they expose the exact resource a local choice is consuming.

Worked example: shortest jobs first

Return to the previous page’s problem: we have a time budget T, independent jobs with positive durations, and we want to complete as many jobs as possible. Greedy sorts jobs by increasing duration and takes them while they fit.

Greedy solution

Let the sorted durations be d₁ ≤ d₂ ≤ ··· ≤ dₙ. Suppose greedy takes the first k jobs, so

d₁ + ··· + dₖ ≤ T

but adding dₖ₊₁ would exceed T.

Why no solution can take k + 1 jobs

Among all subsets of k+1 jobs, the minimum possible total duration is the sum of the k+1 shortest jobs.

d₁ + ··· + dₖ₊₁ > T

Therefore every set of k+1 jobs exceeds the budget. Greedy is optimal.

This can also be phrased as an exchange argument: whenever a solution uses a longer job instead of a shorter omitted one, swapping them cannot hurt feasibility.

A second worked pattern: staying ahead on intervals

Suppose greedy always picks the compatible interval that finishes earliest. Let gᵢ be the finish time of greedy’s i-th chosen interval and oᵢ the finish time of the i-th interval in any other feasible schedule. Inductively, gᵢ ≤ oᵢ: greedy’s first finish is earliest, and if it is no later after i−1 choices, it has at least as many candidates available for choice i. Greedy therefore never uses up more of the timeline than a competitor with the same number of intervals.

2. Greedy stays ahead

Sometimes it is easier to compare partial solutions step by step. We define a quantity that measures progress and prove that after the first choice, the second choice, and so on, greedy is at least as far ahead as any optimal solution.

Typical form

If the greedy solution makes choices g₁, g₂, ... and an optimal solution makes o₁, o₂, ..., prove an inequality such as progress(g₁,...,gᵢ) ≥ progress(o₁,...,oᵢ) for every i.

A classic example is interval scheduling: after choosing the first i compatible intervals, the schedule that always picks the earliest finishing interval finishes no later than any other schedule containing i intervals. That leaves at least as much room for future intervals.

3. Safe choice, then induction

Many greedy proofs have the same recursive shape even when the algorithm itself is written as a loop.

1

Prove the next greedy choice is safe. Show that some optimal solution contains it.

2

Reduce the problem. Once the choice is fixed, describe the remaining instance precisely.

3

Show the structure remains the same. The same greedy rule must still make sense on the smaller instance.

4

Apply induction. If greedy solves the smaller instance optimally, adding the safe first choice gives an optimal full solution.

A greedy proof can justify throwing information away

One-pass greedy optimizations often look different from scheduling or MST: the commitment is not “take this item”, but “forget this entire class of prefixes”. The proof obligation is the same—show the discarded alternatives can never help later.

Maximum-subarray reset

Suppose the running sum of the current prefix is p<0. Let a future continuation have sum T. Keeping the negative prefix produces p+T.

Why reset is safe

Because p<0, we have p+T<T. Starting the future subarray after the negative prefix is strictly better than carrying that prefix forward.

Greedy discard rule. Once a partial state is provably worse for every possible continuation, it can be deleted forever.

This is a reusable proof shape

To justify state compression, compare two histories under an arbitrary common future. If one history is never better after any continuation, it is dominated and does not need to survive.

A reusable greedy-proof template

The surface details change from intervals to graphs to codes, but most exact greedy proofs can be organized around the same four questions.

1. Name the choice

Specify the exact local object greedy commits to: interval, edge, item fraction, merge, or vertex distance.

2. Compare with OPT

Take an optimal solution and identify where it first disagrees with greedy—or compare both solutions at the same prefix.

3. Repair the disagreement

Exchange, replace, or reroute so OPT adopts the greedy choice without becoming infeasible or worse.

4. Reduce and repeat

After fixing that choice, prove the remaining instance has the same form. Finish by induction or an invariant.

Stress-test assumptions before writing QED

Check ties, zero values, equal endpoints, disconnected inputs, empty inputs, negative weights, and whether the objective changed from cardinality to weight. Many “proofs” silently use one of these assumptions.

First make the choice feel inevitable. Then prove it.

A good greedy explanation has two layers. The first is the picture in your head: why does this move seem to leave the future in the best shape? The second is the proof that no hidden counterexample survives.

Classroom scheduling

Finishing first feels right because it frees the room as early as possible. That intuition suggests the invariant: every class available after a later finish is still available after the earlier finish.

0/1 Knapsack

“Take the most valuable item first” feels just as natural, but one item can consume capacity needed by a better pair. The picture alone does not tell us whether commitment is safe.

Try before reading the proof

What future opportunity can the greedy choice never make worse?

If you cannot answer that in one sentence, you probably do not yet know what your proof should preserve.

Intuition

Describe the local choice in ordinary language: “free the room earlier”, “use the denser material”, “finalize the cheapest reachable node”.

Invariant

Translate that picture into something comparable: remaining candidates, total capacity, cut weight, or tentative distance.

Counterexample test

Try to construct the smallest instance that breaks the invariant. If you succeed, change the rule.

Formal proof

Only after the invariant survives should you write the exchange, staying-ahead, induction, or cut argument.

Examples discover the proof; they do not replace it. The purpose of the story is to expose the invariant you will later prove for every input.

Your state variables do not always have to form the final witness

Greedy summaries can encode enough information to prove that a solution exists without literally storing one consistent solution at every instant.

Increasing triplet

Maintain the smallest low seen and the smallest possible middle that has appeared after some earlier lower value. If a later number exceeds middle, a triplet exists.

The subtle point

After middle is set, low may later be replaced by an even smaller value that occurs after that middle. The current pair (low, middle) may therefore not itself be an ordered pair from the witness.

What the invariant must really say

Whenever middle is finite, there existed some earlier value smaller than it. Updating low later does not erase that historical fact. Therefore a future value larger than middle completes a valid increasing triplet.

Proof the abstraction, not the picture in the variables. A compressed state may represent a fact about the past rather than a literal partial solution.

What is not a proof

“It is obviously best now”

“Best right now” is exactly the claim that needs justification. The future can overturn a local advantage.

Only checking examples

Examples can falsify a greedy rule, but no finite set of successful examples proves correctness.

Assuming optimal substructure is enough

Dynamic programming also has optimal substructure. Greedy additionally needs a safe irreversible choice.

Proving feasibility instead of optimality

Showing that every greedy step keeps the solution valid only proves that the algorithm returns a legal answer. It says nothing about whether a better legal answer was discarded.

Exercises

1

Exchange step

Suppose an optimal job set contains a 7-minute job but omits an available 3-minute job. What happens if we exchange them?

The number of chosen jobs stays the same and total duration decreases by 4 minutes, so feasibility cannot be harmed.
2

What must be preserved?

In an exchange argument, is it enough that the new solution has the same objective value?

No. The transformed solution must also remain feasible. A swap that improves the objective but violates constraints proves nothing.
3

Counterexamples

What role does a counterexample play in greedy algorithm design?

A single counterexample is enough to disprove a proposed greedy rule. If no counterexample is found, the rule is still unproved.
4

Cut property as exchange

In an MST proof, take a lightest edge crossing a cut. Explain how the usual cut-property proof is an exchange argument.

Start from an MST that does not contain the chosen light edge e. Adding e creates a cycle; that cycle contains another edge f crossing the same cut. Since w(e) ≤ w(f), replacing f by e keeps a spanning tree and does not increase weight. That is exactly an exchange.
