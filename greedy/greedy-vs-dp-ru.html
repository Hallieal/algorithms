Жадные алгоритмы и динамическое программирование

Greedy оставляет одно будущее. Динамическое программирование хранит несколько состояний, пока не станет ясно, какое из них победит.

Один путь или несколько состояний?

Оба метода используют структуру задачи вместо полного перебора. Разница в том, что они позволяют себе забыть: greedy оставляет одно продолжение, а DP хранит несколько частичных ответов, потому что будущее может по-разному использовать каждый из них.

GreedyОставляет одно будущее

Фиксирует выбор сразу, как только его безопасность доказана.

DPХранит несколько состояний

Разные частичные решения ещё могут оказаться важны позже.

ПроверкаОдно состояние точно доминирует остальные?

Если это нельзя доказать, отбрасывать альтернативы опасно.

Жадный алгоритм

Выбирает одно локально лучшее продолжение и сразу отбрасывает альтернативы.

Динамическое программирование

Хранит лучшие значения для нескольких состояний подзадач, потому что разные частичные решения могут оказаться важны позже.

Практический вопрос: можете ли вы доказать, что один локальный выбор доминирует альтернативы? Если да, greedy может быть достаточно. Если нет, скорее всего, нужно состояние.

Что у них общего на самом деле

Оптимальная подструктура

Оба метода часто используют тот факт, что оптимальное решение большой задачи содержит оптимальные решения меньших подзадач.

Повторяющаяся структура

Оба метода эксплуатируют регулярный способ свести большую задачу к меньшим.

Но DP обычно сравнивает несколько меньших вариантов перед решением, а greedy сразу фиксирует один. Поэтому наличие оптимальной подструктуры само по себе не оправдывает жадность.

Размен монет: что именно greedy выбрасывает

Пусть есть монеты 1, 3 и 4, а сумму 6 нужно набрать минимальным числом монет.

Жадный алгоритм

Берём крупнейшую подходящую монету:

6 → 2 → 1 → 0

Монеты: 4, 1, 1. Всего 3.

Динамическое программирование

Для каждой суммы x храним минимальное число монет:

dp[x] = 1 + min dp[x − c]

Для x = 6 лучший переход использует монету 3 дважды, поэтому ответ равен 2.

Почему greedy ошибается? После выбора 4 он навсегда отбрасывает альтернативное частичное состояние 3. Но именно оно идеально дополняется ещё одной тройкой. DP сохраняет достаточно состояний, чтобы это увидеть.

Рюкзак 0/1: классическая граница

Очень естественное жадное правило — брать предмет с максимальным отношением ценности к весу. Для дробного рюкзака, где предметы можно делить, оно работает. Если каждый предмет можно взять только целиком, правило может сломаться.

Вместимость = 50

Предмет Aвес 10 · ценность 60отношение 6
Предмет Bвес 20 · ценность 100отношение 5
Предмет Cвес 30 · ценность 120отношение 4
Greedy по отношению:
A + B занимают вес 30 и дают ценность 160. C после этого не помещается.
Оптимум для 0/1:
B + C занимают вес 50 и дают ценность 220.

Первый жадный выбор A локально выглядит лучше, но блокирует глобально лучшую комбинацию. DP по оставшейся или использованной вместимости умеет сравнивать такие варианты.

Практический тест

Спросите, какая информация может понадобиться будущим решениям. Если два частичных ответа по-разному расходуют ресурс и ни один явно не доминирует, хранить только один опасно.

Сигнал в пользу greedy: обменяемость

Вы можете заменить выбор в оптимальном решении на жадный выбор, не ухудшая ответ.

Сигнал в пользу greedy: безопасный фронт

Есть очевидное следующее ребро, интервал, предмет или вершина, которые можно окончательно зафиксировать.

Сигнал в пользу DP: компромисс по ресурсу

Разные частичные решения тратят разное количество времени, вместимости, денег или другого ресурса, и ни одно явно не доминирует.

Сигнал в пользу DP: будущее зависит от прошлого

Локально худший шаг может создать лучшую комбинацию позже, поэтому нужно сохранять несколько состояний.

Разница видна по памяти

Для одной и той же задачи о монетах жадная реализация идёт по одной траектории. DP явно хранит ответы для множества меньших сумм.

Жадный размен

def greedy_change(amount, coins):
    result = []

    for coin in sorted(coins, reverse=True):
        while coin <= amount:
            result.append(coin)
            amount -= coin

    return result

Динамическое программирование

def min_coins(amount, coins):
    dp = [float("inf")] * (amount + 1)
    dp[0] = 0

    for x in range(1, amount + 1):
        for coin in coins:
            if coin <= x:
                dp[x] = min(
                    dp[x],
                    dp[x - coin] + 1
                )

    return dp[amount]

Жадная функция почти не хранит альтернативную историю. DP хранит лучший ответ для каждой суммы от 0 до целевой.

Задачи

1

Состояние в монетах

Для монет 1, 3, 4 почему выбор монеты 4 при сумме 6 теряет полезную информацию?

Потому что частичное решение «сначала взять 3» локально выглядит хуже, чем взять 4, но именно оно позволяет получить оптимальное продолжение 3 + 3. Greedy навсегда отбрасывает это состояние.
2

Какой метод?

Есть ограничение по вместимости, предметы нельзя делить, и несколько частичных решений с разной использованной вместимостью остаются конкурентными. Какой метод стоит заподозрить первым?

Динамическое программирование: оставшаяся вместимость — естественное состояние, а разные частичные решения могут приводить к разным возможностям в будущем.
3

Оптимальная подструктура

Почему наличие оптимальной подструктуры не доказывает существование жадного алгоритма?

Оптимальная подструктура говорит лишь о том, что оптимальное решение содержит оптимальные подрешения. Она не говорит, какой первый выбор можно безопасно сделать без сравнения альтернатив.
