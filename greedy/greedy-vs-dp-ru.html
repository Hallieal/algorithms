Жадные алгоритмы и динамическое программирование

Главное различие между greedy и dynamic programming — сколько частичных состояний нужно сохранить. Это видно на размене монет, Knapsack и interval problems.

Greedy choice и состояние динамики

Greedy оставляет одно продолжение только тогда, когда остальные варианты доказанно доминируются. DP хранит несколько состояний, если будущие решения могут различать их.

GreedyОставляет одно будущее

Фиксирует выбор сразу, как только его безопасность доказана.

DPХранит несколько состояний

Разные частичные решения ещё могут оказаться важны позже.

ПроверкаОдно состояние точно доминирует остальные?

Если это нельзя доказать, отбрасывать альтернативы опасно.

Выбирает одно локально лучшее продолжение и сразу отбрасывает альтернативы.

Практический вопрос: можете ли вы доказать, что один локальный выбор доминирует альтернативы? Если да, greedy может быть достаточно. Если нет, скорее всего, нужно состояние.

Что у них общего

Оптимальная подструктура

Оба метода часто используют тот факт, что оптимальное решение большой задачи содержит оптимальные решения меньших подзадач.

Повторяющаяся структура

Оба метода эксплуатируют регулярный способ свести большую задачу к меньшим.

Но DP обычно сравнивает несколько меньших вариантов перед решением, а greedy сразу фиксирует один. Поэтому наличие оптимальной подструктуры само по себе не оправдывает жадность.

Размен монет: что теряет greedy

Для номиналов 1, 3 и 4 и суммы 6 правило крупнейшей монеты фиксирует локально хороший, но глобально неоптимальный путь.

Жадный алгоритм

Берём крупнейшую подходящую монету:

6 → 2 → 1 → 0

Монеты: 4, 1, 1. Всего 3.

Динамическое программирование

Для каждой суммы x храним минимальное число монет:

dp[x] = 1 + min dp[x − c]

Для x = 6 лучший переход использует монету 3 дважды, поэтому ответ равен 2.

Почему greedy ошибается? После выбора 4 он навсегда отбрасывает альтернативное частичное состояние 3. Но именно оно идеально дополняется ещё одной тройкой. DP сохраняет достаточно состояний, чтобы это увидеть.

Ещё один контрпример для размена монет

Проблема не ограничивается набором {1,3,4}. Другие системы номиналов тоже содержат локальные решения, которые блокируют оптимум.

Denominations

{1,5,10,20,25,50}, target amount 40.

Largest-coin-first выбирает 25+10+5: три coins.

Лучшее сочетание

20+20 набирает ту же сумму всего двумя coins.

Первый greedy coin оставляет remainder, который локально допустим, но глобально дорог.

Урок

Нельзя выводить корректность coin-change greedy из того, что он работает для одной знакомой валюты. Exactness зависит от denomination system. Без structural proof DP сохраняет remainder states, которые greedy выбрасывает.

0/1 Knapsack и Fractional Knapsack

Сортировка по value-to-weight ratio точна для делимых предметов. Для 0/1 Knapsack тот же порядок может отбросить комбинацию, которая позже окажется оптимальной.

Вместимость = 50

Предмет Aвес 10 · ценность 60отношение 6
Предмет Bвес 20 · ценность 100отношение 5
Предмет Cвес 30 · ценность 120отношение 4
Greedy по отношению:
A + B занимают вес 30 и дают ценность 160. C после этого не помещается.
Оптимум для 0/1:
B + C занимают вес 50 и дают ценность 220.

Первый жадный выбор A локально выглядит лучше, но блокирует глобально лучшую комбинацию. DP по оставшейся или использованной вместимости умеет сравнивать такие варианты.

Три подхода к Knapsack

Здесь хорошо видны три стратегии: полный перебор, быстрый, но неточный в общем случае greedy и dynamic programming по множеству capacities.

Естественная greedy-ошибка

В классическом примере с вором выбор самого дорогого отдельного предмета даёт value 3000, тогда как другая пара стоит 3500. Первый локально привлекательный выбор блокирует лучшую комбинацию.

Что сохраняет DP

Вместо commitment к одному packing DP хранит лучший value для нескольких меньших capacities. Состояние, которое сейчас выглядит хуже, может лучше соединиться с будущим item.

1

Перебрать все subsets

Проверить все комбинации и выбрать лучшую допустимую.

Exact, но экспоненциально: 2ⁿ subsets.
2

Сделать greedy guess

Идти по локально привлекательному порядку и не пересматривать решения.

Быстро, но не exact для 0/1 Knapsack.
3

Строить из sub-knapsacks

Для каждой меньшей capacity хранить лучший найденный value и переиспользовать его при добавлении нового item.

Exact для integer capacities; pseudo-polynomial по capacity.
CapacityЗачем её хранить?

2Сейчас это не итоговый optimum, но это другой budget для будущих комбинаций.

Сохранение состояний

Greedy выбрасывает альтернативные будущие; DP хранит те, которые ещё могут понадобиться.

Именно этот структурный вопрос полезно задавать до выбора техники.

Pseudo-polynomial динамическое программирование

Стандартный integer-capacity Knapsack работает за O(nC). Это polynomial по числовому значению C, но не по длине двоичной записи C.

Сколько стоит table

При n items и integer capacity C одномерная implementation работает за O(nC) time и O(C) space.

Почему “pseudo-polynomial”?

Число C записывается всего Θ(log C) bits. Поэтому runtime, линейный по численному значению C, может быть экспоненциальным по длине этой части input.

Small C

DP практичен

Если capacity — несколько тысяч, хранить state для каждого значения может быть совершенно нормально.

Huge C

State range взрывается

Capacity в миллионы или миллиарды делает ту же recurrence неудобной даже при умеренном n.

Greedy heuristic

Fast не значит safe

Для общего 0/1 Knapsack density ordering может быть сколь угодно плохим относительно optimum. Скорость не заменяет proof или approximation guarantee.

Выбор метода зависит и от structure, и от чисел. DP сохраняет нужные alternatives, но диапазон state variable определяет, насколько exact method практичен.

Weighted Interval Scheduling

Earliest finish точен при одинаковой ценности intervals. После добавления profits приходится сохранять несколько несовместимых partial schedules, что приводит к DP.

Без весов

Нас интересует только число совместимых интервалов, поэтому раннее окончание оставляет место для большего числа будущих выборов.

С весами

Теперь нужно сравнивать два состояния: «взять интервал j» и «пропустить j». После сортировки по окончанию DP хранит оба варианта.

OPT(j) = max( wⱼ + OPT(p(j)), OPT(j−1) )

Роль сортировки

Это гибридный случай: сортировка по окончанию не решает задачу, но делает DP аккуратным. p(j) — последний интервал, заканчивающийся до начала j. Отдельной страницы про Weighted Interval Scheduling в handbook пока нет.

Сколько состояния нужно сохранить?

Главный вопрос — можно ли безопасно заменить несколько partial solutions одним representative state. Если future choices различают их, одного greedy-state недостаточно.

Один frontier

Jump Game

При проходе справа налево достаточно хранить самую левую позицию, из которой конец уже достижим. Все успешные suffix-состояния позади неё доминируются этим frontier.

Один кандидат

Gas Station

Первый отрицательный running balance позволяет выбросить целый блок стартовых точек. Алгоритм хранит одного выжившего кандидата, а не состояние для каждого старта.

Много capacities

0/1 Knapsack

Два частичных рюкзака с разной занятой вместимостью могут оба понадобиться позже. Ни один не обязан доминировать, поэтому DP хранит таблицу альтернатив.

Greedy-вопрос: можно ли заменить много историй одним доминирующим состоянием?

Когда greedy и DP описывают один алгоритм

Некоторые однопроходные recurrence можно читать и как сжатый DP, и как greedy-dominance argument. Классический пример — maximum subarray.

DP view

Пусть E_i — лучший subarray sum, который обязан заканчиваться в позиции i. Тогда

Eᵢ = max(aᵢ, Eᵢ₋₁ + aᵢ)

Нужно только предыдущее state, поэтому вся DP table сжимается в одну переменную.

Greedy view

Если running prefix sum становится отрицательной, больше не тащим её вперёд. Любой будущий suffix лучше без отрицательного вклада, поэтому делаем reset и начинаем заново.

current_sum

Лучший sum subarray, заканчивающегося в текущей позиции.

best_sum

Лучший ответ среди всех ending positions, увиденных до сих пор.

discard rule

Отрицательный running prefix dominated вариантом начать после него.

Более глубокая граница — сколько state должно выжить. Некоторые DP recurrences сжимаются до constant state; некоторые greedy arguments можно записать маленькой recurrence. Название техники менее важно, чем понимание того, что реально нужно будущему.

Проверка доминирования ветки

Ветку можно навсегда отбросить только если сохранённое состояние не хуже её при любом возможном продолжении. Иначе обе ветки могут понадобиться DP.

Jump to the End

Выживает один frontier

Как только index j умеет достигать старого destination, перенос destination в j не теряет ранних решений: любой более ранний index, достигавший старую цель, достигнет и j.

Gas Stations

Failed segment убивает кандидатов

Если start a впервые провалился у b, весь блок стартов можно выбросить сразу. Нет смысла отдельно branching/test каждого кандидата.

0/1 Knapsack

Include и exclude оба могут понадобиться

Если item помещается, ветки «взять» и «не взять» могут приводить к optimum при разных remaining capacities. В общем случае ни одна не доминирует, поэтому DP сохраняет обе через recurrence.

Вопрос, который стоит проговорить вслух

«Могу ли я доказать, что после этого local choice каждая выброшенная альтернатива не лучше при любом future continuation?» Если да — greedy правдоподобен. Если нет — ищите state, который обязан хранить конкурирующие futures.

Практический признак

Несколько ресурсов, несравнимые partial solutions или зависимость ценности решения от будущих данных обычно означают, что нужно хранить несколько состояний.

Сигнал в пользу greedy: обменяемость

Вы можете заменить выбор в оптимальном решении на жадный выбор, не ухудшая ответ.

Сигнал в пользу greedy: безопасный фронт

Есть очевидное следующее ребро, интервал, предмет или вершина, которые можно окончательно зафиксировать.

Сигнал в пользу DP: компромисс по ресурсу

Разные частичные решения тратят разное количество времени, вместимости, денег или другого ресурса, и ни одно явно не доминирует.

Сигнал в пользу DP: будущее зависит от прошлого

Локально худший шаг может создать лучшую комбинацию позже, поэтому нужно сохранять несколько состояний.

Быстрый тест контрпримером

Попробуйте быстро построить пример, где локально лучший greedy-шаг приводит к глобально худшему ответу. Если получилось, перестаньте искать доказательство greedy и ищите состояние, которое вы теряете.

Требования к памяти

В реализации различие видно напрямую: greedy ведёт одно текущее состояние, а DP хранит набор ответов для подзадач.

Жадный размен

def greedy_change(amount, coins):
    result = []

    for coin in sorted(coins, reverse=True):
        while coin <= amount:
            result.append(coin)
            amount -= coin

    return result

Динамическое программирование

def min_coins(amount, coins):
    dp = [float("inf")] * (amount + 1)
    dp[0] = 0

    for x in range(1, amount + 1):
        for coin in coins:
            if coin <= x:
                dp[x] = min(
                    dp[x],
                    dp[x - coin] + 1
                )

    return dp[amount]

Жадная функция почти не хранит альтернативную историю. DP хранит лучший ответ для каждой суммы от 0 до целевой.

Задачи

1

Состояние в монетах

Для монет 1, 3, 4 почему выбор монеты 4 при сумме 6 теряет полезную информацию?

Потому что частичное решение «сначала взять 3» локально выглядит хуже, чем взять 4, но именно оно позволяет получить оптимальное продолжение 3 + 3. Greedy навсегда отбрасывает это состояние.
2

Какой метод?

Есть ограничение по вместимости, предметы нельзя делить, и несколько частичных решений с разной использованной вместимостью остаются конкурентными. Какой метод стоит заподозрить первым?

Динамическое программирование: оставшаяся вместимость — естественное состояние, а разные частичные решения могут приводить к разным возможностям в будущем.
3

Оптимальная подструктура

Почему наличие оптимальной подструктуры не доказывает существование жадного алгоритма?

Оптимальная подструктура говорит лишь о том, что оптимальное решение содержит оптимальные подрешения. Она не говорит, какой первый выбор можно безопасно сделать без сравнения альтернатив.
