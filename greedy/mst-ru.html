Глава 9 · Раздел 9

Минимальные остовные деревья

Нужно соединить все вершины с минимальным суммарным весом. Краскал и Прим выглядят по-разному, но оба основаны на свойстве разреза.

Соединить всё как можно дешевле

Нужно выбрать связный набор рёбер, который достигает всех вершин и не содержит циклов. Среди всех таких деревьев ищем минимальный суммарный вес.

Главный фактСамое лёгкое безопасное ребро через разрез можно брать

На этом одном утверждении держатся и Краскал, и Прим.

Два взглядаКраскал растит лес, Прим — одно дерево

Механика разная, доказательство одно.

СложностьO(E log E) или O(E log V)

DSU для Краскала, heap для Прима.

Минимальное остовное дерево

Остовное дерево содержит все вершины, связно, не имеет циклов и поэтому содержит ровно |V|−1 рёбер. MST — остовное дерево минимального суммарного веса.

MST — не дерево кратчайших путей. Оно минимизирует сумму весов всех выбранных рёбер, а не расстояние от одной исходной вершины до остальных.

До выбора алгоритма превратите сюжет в граф

Конкретная история делает objective видимым. Пусть несколько офисов нужно соединить новой оптоволоконной сетью, а для каждой возможной линии известна стоимость строительства.

Objective

Минимизируем сумму выбранных weights при условии connected graph.

Не путайте сюжет с shortest paths. MST минимизирует стоимость всей сети, Dijkstra — маршрут от одного source до каждой destination.

Один факт для обоих алгоритмов: свойство разреза

Разрез просто делит вершины на две непустые стороны, S и V\S. Нас интересует самый дешёвый способ перейти с одной стороны на другую.

Сторона S

Часть вершин и уже зафиксированные безопасные рёбра.

самое лёгкое ребро
через разрез

Сторона V \ S

Оставшиеся вершины с другой стороны разбиения.

Свойство разреза

Если разрез согласован с уже выбранными рёбрами, то ребро минимального веса, пересекающее этот разрез, безопасно: существует MST, содержащее все прежние выбранные рёбра и это ребро.

Почему это верно

Берём MST T, согласованное с текущими выборами. Если лёгкое ребро e уже входит в T, всё готово. Иначе добавим e: появится цикл. В этом цикле обязательно есть другое ребро f, пересекающее тот же разрез. Так как e — минимальное среди пересекающих, w(e) ≤ w(f). Удаляем f; дерево остаётся остовным, а его вес не увеличивается.

Сильный proof-приём: предположить первую ошибку greedy

Для инкрементальных greedy-алгоритмов удобно рассматривать первый шаг, который якобы может уничтожить оптимальность. До него текущий greedy-prefix ещё содержится в некотором optimum.

До ошибки

Пусть текущий greedy-forest F входит в некоторое MST T.

Greedy выбирает e

Следующее ребро e минимально через нужный cut, но предположим e∉T.

Добавляем e в T

Появляется цикл. В нём есть другое ребро f, пересекающее тот же cut.

Exchange

Поскольку w(e)≤w(f), замена f на e даёт MST, уже содержащее более длинный greedy-prefix.

Первой ошибки быть не может. Это cut property, переписанное как contradiction через «первое плохое решение» — очень переносимый proof-style.

Краскал: растим лес

Сортируем все рёбра по весу и проходим один раз. Ребро оставляем, если оно соединяет разные компоненты; если его концы уже связаны, оно создаст цикл и пропускается.

Краскал по шагам

Список рёбер уже отсортирован по весу. Зелёные рёбра входят в лес, бледные отклонены из-за цикла.

Текущие компоненты
Вес текущего леса: 0

Почему очередное принятое ребро безопасно

Перед добавлением ребра (u,v) вершины u и v лежат в разных компонентах. Берём разрез: одна из этих компонент против всех остальных вершин. Выбранное ребро является одним из самых лёгких доступных рёбер, пересекающих разрез, согласованный с текущим лесом, поэтому работает свойство разреза.

Прим: растим одно дерево

Начинаем с любой вершины. Поддерживаем одно связное дерево и каждый раз добавляем самое дешёвое ребро, которое выходит из него наружу.

Корректность Прима почти буквально следует из свойства разреза: берём разрез «вершины уже в дереве» против «вершины ещё вне дерева». Самое лёгкое пересекающее ребро безопасно.

Борувка: все компоненты делают шаг одновременно

Краскал добавляет безопасные рёбра по одному, Прим растит одну компоненту. Алгоритм Борувки в каждом раунде позволяет каждой текущей компоненте выбрать самое дешёвое исходящее ребро.

1. Один выбор на компоненту

Для каждой компоненты текущего леса находим ребро минимального веса, ведущее наружу.

2. Добавляем все безопасные рёбра

Каждое выбранное ребро минимально через разрез «эта компонента против остальных», поэтому свойство разреза делает его безопасным.

3. Сжимаем компоненты

Объединяем связанные выбранными рёбрами компоненты и повторяем. За раунд число компонент уменьшается как минимум вдвое.

Зачем нужен Борувка

Выборы для разных компонент можно искать одновременно, поэтому алгоритм естественно параллелизуется и используется как основа распределённых MST-алгоритмов. Простая последовательная версия просматривает все рёбра в каждом из O(log V) раундов и работает за O(E log V).

Одно доказательство, разные структуры данных

Краскал + DSU

def kruskal(n, edges):
    parent = list(range(n))
    rank = [0] * n

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        a, b = find(a), find(b)
        if a == b:
            return False
        if rank[a] < rank[b]:
            a, b = b, a
        parent[b] = a
        if rank[a] == rank[b]:
            rank[a] += 1
        return True

    mst = []
    for w, u, v in sorted(edges):
        if union(u, v):
            mst.append((u, v, w))
    return mst

Прим + heap

import heapq

def prim(graph, start=0):
    seen = {start}
    heap = []

    for v, w in graph[start]:
        heapq.heappush(heap, (w, start, v))

    mst = []
    while heap and len(seen) < len(graph):
        w, u, v = heapq.heappop(heap)
        if v in seen:
            continue

        seen.add(v)
        mst.append((u, v, w))

        for to, weight in graph[v]:
            if to not in seen:
                heapq.heappush(heap, (weight, v, to))

    return mst

Так как E ≤ V², логарифмические множители близки. На практике часто важнее формат хранения графа и окружающий код.

Что ещё даёт структура MST

Clustering

Строим MST по точкам или объектам и удаляем самые тяжёлые рёбра. Оставшиеся connected components дают кластеры, разделённые дорогими связями.

Maximum spanning tree

Используем ту же greedy-логику, но идём по весам в обратном порядке. Эквивалентно — меняем знак весов и строим minimum spanning tree.

Minimum bottleneck

Любое MST минимизирует максимальный использованный вес ребра среди всех spanning trees. Цель «минимизировать худшую связь» получается бесплатно.

Dense vs sparse implementation

Heap-based Prim естественен на sparse adjacency lists. Простая array-версия O(V²) может быть конкурентной на dense graphs из-за отсутствия heap overhead.

Representation — часть алгоритма

Kruskal естественно использует edge list + DSU, Prim — adjacency по вершинам. Математический greedy-choice может быть одинаково хорош, а оптимальная data structure зависит от плотности графа.

Четыре факта, которые стоит помнить

MST — чистый пример матроида

Множества рёбер без циклов образуют графический матроид. Остовное дерево — базис этого матроида. Поэтому Краскал является частным случаем общей greedy-теоремы для матроидов: упорядочиваем элементы по весу и добавляем элемент, пока сохраняется независимость. Свойство разреза — графовая форма того же обменного принципа.

Разные веса ⇒ единственность

Если веса всех рёбер различны, MST единственно.

При равных весах MST может быть несколько

Разные безопасные рёбра одинакового веса могут привести к разным остовным деревьям с одной и той же минимальной стоимостью.

Несвязный граф

Остовного дерева нет. Краскал построит минимальный остовный лес — по дереву на каждую компоненту связности.

Отрицательные веса допустимы

В отличие от Дейкстры, MST-алгоритмы нормально работают с отрицательными весами и просто предпочитают их, когда это безопасно.

Задачи

1

Число рёбер

Сколько рёбер должно быть в остовном дереве на 17 вершинах?

Ровно 16.
2

Решение Краскала

Почему Краскал отклоняет ребро, концы которого уже находятся в одной DSU-компоненте?

Между концами уже существует путь. Добавление ребра создаст цикл, поэтому текущий лес перестанет быть лесом.
3

Равные веса и несколько MST

Возьмите треугольник, у которого все три ребра имеют вес 1. Сколько у него различных MST и что это говорит о «безопасном» ребре?

Любые два из трёх рёбер образуют MST, значит всего три MST. Ребро может быть безопасным — входить в некоторое MST — но не обязано входить во все MST.
