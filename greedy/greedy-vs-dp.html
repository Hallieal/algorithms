Greedy vs Dynamic Programming

How greedy algorithms differ from dynamic programming, when local commitment is safe, and when a problem needs multiple states.

Same goal, different commitment

Greedy algorithms and dynamic programming are both ways to exploit structure instead of brute-force enumeration. The key difference is how many possibilities remain alive after each decision.

Greedy

Choose one locally best continuation and discard the alternatives immediately.

ABCD
VS

Dynamic programming

Keep the best value for many subproblem states because different partial choices may matter later.

ABCD
The practical question: can you prove that one local choice dominates all alternatives? If yes, greedy may be enough. If not, the problem may need state.

What they have in common

Optimal substructure

Both methods often rely on the fact that an optimal solution contains optimal solutions to smaller subproblems.

Repeated structure

Both methods exploit a regular way in which a large problem reduces to smaller ones.

But DP normally compares several smaller possibilities before deciding, while greedy commits to one choice immediately. Therefore optimal substructure does not by itself justify greediness.

Coin change: greedy loses information

Suppose the coins are 1, 3, and 4 and we want to make amount 6 with the minimum number of coins.

Greedy

Take the largest coin that fits:

6 → 2 → 1 → 0

Choices: 4, 1, 1. Total: 3 coins.

Dynamic programming

For every amount x, remember the minimum number of coins needed for x:

dp[x] = 1 + min dp[x − c]

For x = 6, the best transition uses coin 3 twice, giving 2 coins.

Why does greedy fail? After taking 4, it discards the alternative partial amount 3. But that alternative combines with another 3 perfectly. DP keeps enough state to discover this.

0/1 Knapsack: a classic boundary

A very natural greedy rule is to take the item with the largest value-to-weight ratio. This works for fractional knapsack, where items may be split. It can fail when each item must be taken whole.

Capacity = 50

Item Aweight 10 · value 60ratio 6
Item Bweight 20 · value 100ratio 5
Item Cweight 30 · value 120ratio 4
Greedy by ratio:
A + B uses weight 30 and gives value 160. C no longer fits.
Optimal 0/1 solution:
B + C uses weight 50 and gives value 220.

The greedy first choice A is locally attractive but blocks the globally best combination. A DP indexed by remaining capacity or used capacity can compare these alternatives.

How to decide which technique to try

These are not proofs, but they are useful signals when solving a new problem.

Signal for greedy: exchangeability

You can replace a choice in an optimal solution by the greedy choice without making the answer worse.

Signal for greedy: one safe frontier

There is a clear next edge, interval, item, or vertex that can be finalized permanently.

Signal for DP: resource trade-offs

Different partial solutions use different amounts of time, capacity, cost, or another resource, and none obviously dominates.

Signal for DP: future-dependent choices

A locally worse choice can create a better combination later, so several states must remain alive.

The difference in code

For the same coin problem, the greedy implementation follows one path. The DP implementation explicitly stores answers to many smaller amounts.

Greedy change

def greedy_change(amount, coins):
    result = []

    for coin in sorted(coins, reverse=True):
        while coin <= amount:
            result.append(coin)
            amount -= coin

    return result

Dynamic programming

def min_coins(amount, coins):
    dp = [float("inf")] * (amount + 1)
    dp[0] = 0

    for x in range(1, amount + 1):
        for coin in coins:
            if coin <= x:
                dp[x] = min(
                    dp[x],
                    dp[x - coin] + 1
                )

    return dp[amount]

The greedy function has almost no memory of alternative histories. The DP function stores one best answer for every amount from 0 to the target.

Exercises

1

Coin state

For coins 1, 3, 4, why does taking coin 4 at amount 6 lose useful information?

Because the partial choice “take 3 first” looks worse locally than taking 4, but it enables the optimal completion 3 + 3. Greedy discards that state permanently.
2

Which method?

You have a capacity constraint and items cannot be split. Several combinations with different used capacities remain competitive. Which technique should you suspect first?

Dynamic programming is a natural first candidate because remaining capacity is a meaningful state and different partial solutions may lead to different future possibilities.
3

Optimal substructure

Why does the existence of optimal substructure not prove that a greedy algorithm exists?

Optimal substructure only says optimal solutions contain optimal subsolutions. It does not say which first choice is safe without comparing alternatives.
