Greedy vs Dynamic Programming

Greedy and dynamic programming differ mainly in how many partial states must survive. This page uses coin change, Knapsack, and interval problems to make that distinction concrete.

Greedy choice versus dynamic-programming state

Greedy keeps one continuation only when the discarded alternatives are provably dominated. Dynamic programming keeps several states when future decisions can distinguish between them.

GreedyKeep one future

Commit as soon as one choice can be proved safe.

DPKeep several states

Different partial choices remain relevant to the future.

DiagnosticCan one state dominate the rest?

If you cannot prove that, throwing alternatives away is dangerous.

Greedy

Choose one locally best continuation and discard the alternatives immediately.

VS

Dynamic programming

Keep the best value for many subproblem states because different partial choices may matter later.

The practical question: can you prove that one local choice dominates all alternatives? If yes, greedy may be enough. If not, the problem may need state.

Shared ingredients

Optimal substructure

Both methods often rely on the fact that an optimal solution contains optimal solutions to smaller subproblems.

Repeated structure

Both methods exploit a regular way in which a large problem reduces to smaller ones.

But DP normally compares several smaller possibilities before deciding, while greedy commits to one choice immediately. Therefore optimal substructure does not by itself justify greediness.

Coin change: information lost by greedy choice

With coin values 1, 3, and 4 and target 6, the largest-coin-first rule commits to a state that is locally good but globally suboptimal.

Greedy

Take the largest coin that fits:

6 → 2 → 1 → 0

Choices: 4, 1, 1. Total: 3 coins.

Dynamic programming

For every amount x, remember the minimum number of coins needed for x:

dp[x] = 1 + min dp[x − c]

For x = 6, the best transition uses coin 3 twice, giving 2 coins.

Why does greedy fail? After taking 4, it discards the alternative partial amount 3. But that alternative combines with another 3 perfectly. DP keeps enough state to discover this.

A second coin-change counterexample

The failure of greedy coin change is not specific to the set {1,3,4}. Other denomination systems also produce locally attractive choices that block the optimum.

Denominations

{1,5,10,20,25,50}, target amount 40.

Largest-coin-first chooses 25+10+5: three coins.

Better combination

20+20 reaches the same amount using only two coins.

The first greedy coin creates a remainder that is locally feasible but globally expensive.

Lesson

Do not infer a coin-change greedy rule from the fact that it works for one familiar currency. Exactness depends on the denomination system. When no structural proof is available, DP keeps the remainder states that greedy discards.

0/1 Knapsack and Fractional Knapsack

Sorting by value-to-weight ratio is exact when items may be split. With indivisible items, the same order can discard combinations that later become optimal.

Capacity = 50

Item Aweight 10 · value 60ratio 6
Item Bweight 20 · value 100ratio 5
Item Cweight 30 · value 120ratio 4
Greedy by ratio:
A + B uses weight 30 and gives value 160. C no longer fits.
Optimal 0/1 solution:
B + C uses weight 50 and gives value 220.

The greedy first choice A is locally attractive but blocks the globally best combination. A DP indexed by remaining capacity or used capacity can compare these alternatives.

Three approaches to Knapsack

Knapsack illustrates three distinct strategies: exhaustive search, a fast but generally inexact greedy order, and dynamic programming that stores the best value for many capacities.

A natural greedy mistake

In the classic thief example, taking the most expensive single item first yields value 3000, while a different pair is worth 3500. The first locally attractive choice blocks the better combination.

What DP preserves

Instead of committing to one packing, DP keeps the best value for many smaller capacities. A state that looks weaker now may combine better with a later item.

1

Try every subset

Enumerate all combinations and keep the best feasible one.

Exact, but exponential: 2ⁿ subsets.
2

Make a greedy guess

Choose items in a locally attractive order and never revisit the decision.

Fast, but not exact for 0/1 Knapsack.
3

Build from sub-knapsacks

For each smaller capacity, store the best value seen so far and reuse it when a new item is considered.

Exact for integer capacities; pseudo-polynomial in capacity.

State preservation

Greedy throws away alternative futures; DP stores the ones that may still matter.

That is the structural question to ask before choosing between the two techniques.

Pseudo-polynomial dynamic programming

The standard integer-capacity Knapsack algorithm runs in O(nC) time. This is polynomial in the numeric capacity C, but not in the number of bits needed to encode C.

What the table costs

With n items and integer capacity C, a one-dimensional implementation can run in O(nC) time and O(C) space.

Why “pseudo-polynomial”?

The number C is written using only Θ(log C) bits. So a runtime linear in the numeric value of C can still be exponential in the length of that part of the input.

Small C

DP is practical

If capacity is a few thousand, keeping one state per capacity may be entirely reasonable.

Huge C

The state range explodes

A capacity in the millions or billions can make the same recurrence unattractive even when n is modest.

Greedy heuristic

Fast does not mean safe

For general 0/1 Knapsack, density ordering can be arbitrarily far from optimum. Its speed does not replace a correctness or approximation guarantee.

Method choice depends on both structure and numbers. DP preserves the necessary alternatives, but the range of the state variable determines whether that exact method is computationally attractive.

Weighted interval scheduling

Earliest finish is exact when every interval has equal value. Once profits differ, several incompatible partial schedules may have to be retained, which leads naturally to dynamic programming.

Unweighted view

Greedy asks only how many compatible intervals can fit, so finishing early preserves room for more choices.

Weighted view

Now we must compare “take interval j” with “skip j”. After sorting by finish time, dynamic programming keeps both possibilities.

OPT(j) = max( wⱼ + OPT(p(j)), OPT(j−1) )

Role of sorting

This is a hybrid pattern: sorting by finish time does not solve the problem, but it makes the DP state clean. p(j) is the last interval finishing before j starts. Weighted Interval Scheduling does not yet have its own page in this handbook.

How much state must be preserved?

The main distinction is whether different partial solutions can be safely collapsed into one representative. If future choices can value them differently, a single greedy state is insufficient.

One frontier

Jump Game

A backward scan only needs the leftmost index already known to reach the end. Every successful suffix behind that frontier is dominated by the frontier itself.

One candidate

Gas Station

When a running deficit first appears, an entire block of starting points can be discarded. The algorithm keeps one surviving candidate rather than a state for every start.

Many capacities

0/1 Knapsack

Two partial packings with different used capacities may both matter later. Neither necessarily dominates the other, so DP preserves a table of alternatives.

Greedy question: can many histories be replaced by one dominant state?

When greedy and DP descriptions coincide

Some one-pass recurrences can be read either as a compressed dynamic program or as a greedy dominance argument. Maximum subarray is a standard example.

DP view

Let E_i be the best subarray sum that must end at position i. Then

Eᵢ = max(aᵢ, Eᵢ₋₁ + aᵢ)

Only the previous state is needed, so the whole DP table collapses to one variable.

Greedy view

If the running prefix sum becomes negative, carry none of it forward. Any future suffix is better without a negative contribution, so reset the running sum and start fresh.

current_sum

Best sum of a subarray ending at the current position.

best_sum

Best answer over all ending positions seen so far.

discard rule

A negative running prefix is dominated by starting after it.

The deeper distinction is how much state survives. Some DP recurrences compress to constant state; some greedy arguments can be written as tiny recurrences. Algorithm labels are less important than understanding what information the future needs.

Dominance test for discarding a branch

A greedy choice is justified when one partial state is at least as good as another for every possible continuation. Otherwise, both states may need to remain in the dynamic program.

Jump to the End

One frontier survives

Once index j can reach the old destination, making j the new destination does not lose any earlier solution: any earlier index that could reach the old destination can also reach j.

Gas Stations

A failed segment kills candidates

If start a first fails at b, all starts in that block can be discarded together. There is no reason to branch and test each one independently.

0/1 Knapsack

Include and exclude both matter

For an item that fits, “take it” and “skip it” can each lead to the optimum under different remaining capacities. Neither branch dominates in general, so DP preserves both through the recurrence.

The question to ask out loud

“Can I prove that after this local decision, every discarded alternative is no better for every future continuation?” If yes, greedy is plausible. If no, identify the state needed to keep the competing futures.

Practical diagnostic

Look for competing resources, incomparable partial solutions, or choices whose value depends on future input. These are signs that several states may need to be preserved.

Greedy condition: exchangeability

You can replace a choice in an optimal solution by the greedy choice without making the answer worse.

Greedy condition: one safe frontier

There is a clear next edge, interval, item, or vertex that can be finalized permanently.

DP condition: resource trade-offs

Different partial solutions use different amounts of time, capacity, cost, or another resource, and none obviously dominates.

DP condition: future-dependent choices

A locally worse choice can create a better combination later, so several states must remain alive.

Counterexample test

Try to make the locally best greedy choice lead to a globally worse answer. If you can do it quickly, stop searching for a greedy proof and look for the missing state.

Memory requirements

The contrast appears directly in the implementation: greedy follows one current state, while dynamic programming stores a family of subproblem answers.

Greedy change

def greedy_change(amount, coins):
    result = []

    for coin in sorted(coins, reverse=True):
        while coin <= amount:
            result.append(coin)
            amount -= coin

    return result

Dynamic programming

def min_coins(amount, coins):
    dp = [float("inf")] * (amount + 1)
    dp[0] = 0

    for x in range(1, amount + 1):
        for coin in coins:
            if coin <= x:
                dp[x] = min(
                    dp[x],
                    dp[x - coin] + 1
                )

    return dp[amount]

The greedy function has almost no memory of alternative histories. The DP function stores one best answer for every amount from 0 to the target.

Exercises

1

Coin state

For coins 1, 3, 4, why does taking coin 4 at amount 6 lose useful information?

Because the partial choice “take 3 first” looks worse locally than taking 4, but it enables the optimal completion 3 + 3. Greedy discards that state permanently.
2

Which method?

You have a capacity constraint and items cannot be split. Several combinations with different used capacities remain competitive. Which technique should you suspect first?

Dynamic programming is a natural first candidate because remaining capacity is a meaningful state and different partial solutions may lead to different future possibilities.
3

Optimal substructure

Why does the existence of optimal substructure not prove that a greedy algorithm exists?

Optimal substructure only says optimal solutions contain optimal subsolutions. It does not say which first choice is safe without comparing alternatives.
