Interval Partitioning

Schedule every interval while using as few rooms as possible. Reuse the room that becomes free first.

Use as few rooms as possible

Every interval must stay. The only freedom is where to place it. Overlapping intervals need different rooms, so the problem is to reuse rooms as aggressively as possible without creating a conflict.

RuleProcess by start time; reuse the earliest-free room

A min-heap tells us which room becomes available first.

Why it worksA new room is opened only when all rooms are busy

Interval Partitioning

Assign every interval to a room so that overlapping intervals receive different rooms, while minimizing the total number of rooms.

Do not confuse this with Interval Scheduling. There we maximized how many intervals to keep. Here every interval must remain, and we minimize the number of parallel resources.

Endpoint convention

We use half-open intervals [s,f). Therefore a meeting ending at time 5 and another starting at time 5 may use the same room. This is why the implementation checks finish <= start, not finish < start.

First find the lower bound: depth

If d intervals overlap at one instant, they need d different rooms. The maximum such overlap is called the depth, and no schedule can beat it.

Depth

3

In our example, A, B, and C overlap around time 2. Therefore at least 3 rooms are necessary.

Goal of the greedy proof

If our algorithm never uses more rooms than the depth, then it is optimal: it matches a lower bound that every schedule must obey.

The same classroom picture can mean a completely different problem

Greedy rules are tied to objectives, not to surface vocabulary. “Classes with start and finish times” can describe two problems whose correct local choices are different.

One room, reject some classes

Goal: keep as many classes as possible. Choosing the class that ends first is useful because it preserves room on the timeline.

→

Many rooms, keep every class

Goal: use as few rooms as possible. No interval may be discarded, so the decision changes from which class? to which room?

Recognition check

Suppose three classes overlap at 10:30. Can any clever ordering use only two rooms?

No. The overlap itself is a lower bound of three. This is the key mental picture: greedy is optimal because every new room it opens is forced by a simultaneous overlap.

Do not copy a greedy rule just because the objects look familiar. First ask what can be rejected, what must be kept, and what quantity is being optimized.

Reuse the room that frees first

Sort by start time. For each interval, look at the room with the smallest current finish time. If that room is free, reuse it. If even that room is still busy, every room is busy.

Ties at the same start time

Assuming positive-duration intervals, if two intervals start simultaneously, their relative order does not affect correctness. They overlap immediately, so they cannot reuse the same room regardless of which one is processed first.

If you only need the number of rooms: sweep the endpoints

The heap algorithm constructs an actual room assignment. If the task asks only for the minimum number of rooms, we can compute the maximum overlap depth directly with a sweep line.

1

Create one start event (+1) and one finish event (−1) for every interval.

2

Sort events by time. Under half-open semantics [s,f), process a finish before a start when times are equal.

3

Scan the events, maintaining the number of active intervals. The maximum active count is exactly the depth and therefore the optimal number of rooms.

Same mathematics, different story: railway platforms

Replace classes by trains and rooms by platforms. The minimum number of platforms is again the maximum number of simultaneously active intervals.

Arrival+1 active train

A new platform may be needed.

A platform becomes reusable.

AnswerMaximum prefix sum

The peak number of active trains is the minimum number of platforms.

Tie rule matters. If a departure and an arrival occur at the same timestamp and the departing train releases its platform in time, process the departure first. Otherwise the sweep invents an overlap that does not exist.

Why this example is useful

It makes the lower-bound proof almost physical: if three trains are simultaneously at the station, no scheduling trick can serve them with only two platforms.

Interview variant: split starts and finishes into two sorted arrays

The sweep-line idea can be implemented without building tagged events. Keep sorted starts and sorted finishes, then advance whichever event happens next.

1starts = sorted(s for s, f in intervals)
2ends = sorted(f for s, f in intervals)
3i = j = active = best = 0
4if starts[i] < ends[j]: active += 1; i += 1
5else: active -= 1; j += 1
6best = max(best, active)

Why the strict inequality?

For half-open intervals [s,f), a class ending at 10:00 does not overlap one starting at 10:00. So equal timestamps process the end first—the else branch.

Representation choice. Tagged events and two sorted endpoint arrays implement the same sweep. The two-array version makes the tie rule especially visible.

Why opening a new room is unavoidable

The key moment is when the algorithm opens a new room for an interval j starting at time sⱼ.

1

The earliest-finishing existing room is still occupied after sⱼ.

2

Therefore every existing room contains an interval that overlaps j at time sⱼ.

3

If the algorithm already had d rooms, then d+1 intervals overlap at that moment: one in every room plus j.

4

So the depth is at least d+1. Any schedule needs at least that many rooms. Opening the new room is unavoidable.

Optimality

Every room opened by the greedy algorithm is forced by a simultaneous overlap. Hence the number of rooms used equals the depth, and no solution can do better.

The greedy rule is easy; the data structure makes it fast

At every interval, we need one operation: find the room whose current class finishes earliest. How we represent rooms determines the runtime.

Scan all rooms

Keep room finish times in a plain list. Finding the earliest-free room costs O(r) for r rooms, so assigning n intervals can cost O(nr) after sorting.

Use a min-heap

The earliest finish is always at the root. Reading it is immediate, while replacing or inserting a room finish costs O(log r). The assignment phase becomes O(n log r).

Choose the structure from the operation you repeat. The algorithm repeatedly asks for the minimum finish time, which is exactly the operation a min-heap is designed to expose.

Python with a priority queue

The heap stores pairs (finish_time, room_id). Its minimum is always the room that becomes available first.

Why the interval representation is doing real algorithmic work

Room assignment can be viewed as graph coloring, but the input is not an arbitrary conflict graph. Every conflict comes from overlap on a line, and that extra structure is exactly what makes the greedy schedule possible.

Arbitrary conflicts

Only a graph is given

Knowing that A conflicts with B and C does not tell us where those conflicts occur or provide a natural chronological sweep.

Interval conflicts

Every vertex has a start and finish

Sorting by start creates a meaningful left-to-right order, while the current finish times summarize when each room becomes reusable.

Certificate

Maximum overlap is visible

A point covered by d intervals simultaneously certifies that at least d colors/rooms are unavoidable.

Special structure is not a technicality. Often the difference between a hard general problem and a simple greedy algorithm is exactly the representation you are allowed to exploit.

Another view: coloring an interval graph

Create one graph vertex per interval and connect two vertices when the intervals overlap. Assigning rooms is exactly graph coloring on this interval graph. General graph coloring is NP-hard, but interval graphs are perfect: their chromatic number equals their clique number, which here is exactly the maximum overlap depth. The greedy scheduling proof is the algorithmic version of that structure.

Exercises

1

Depth

If at 10:30 five meetings overlap, what lower bound does this give on the number of rooms?

At least 5 rooms are necessary, because no two overlapping meetings can share a room.
2

Why earliest finishing room?

If the earliest-finishing room is not free, why do we know that no existing room is free?

Its finish time is the minimum among all rooms. If even that minimum is later than the new interval’s start, every other room finishes even later.
3

Complexity

Why not scan all rooms linearly for every interval?

That can take O(n) per interval and O(n²) total. A min-heap finds and updates the earliest finishing room in O(log n).
