Fractional Knapsack

When items are divisible, every unit of capacity should go to the item that pays the most per unit of weight.

Spend capacity where it pays most

The knapsack has limited capacity, but items are divisible. That changes the problem completely: instead of choosing whole objects, we can treat capacity as a resource and ask where each next unit of weight earns the most value.

RuleTake the highest value per unit of weight first

Fill by decreasing ratio vᵢ/wᵢ.

Why it worksEqual weight is always better in the denser item

Move weight from lower density to higher density and value cannot fall.

CostO(n log n)

Compute densities, sort once, scan once.

Fractional Knapsack

Choose fractions 0 ≤ xᵢ ≤ 1 to maximize ∑ xᵢvᵢ subject to ∑ xᵢwᵢ ≤ W.

Standard assumptions

The mathematical version normally assumes wᵢ > 0 and vᵢ ≥ 0. The implementation below is slightly more defensive: negative weights are rejected, nonpositive-value items are skipped, and positive-value zero-weight items are taken for free.

Compare value per unit of weight

Total value alone is misleading: a valuable item may also be very heavy. The meaningful quantity is density, vᵢ/wᵢ — value earned by one unit of capacity.

Move a small weight δ from the lower-density item to the higher-density item. The total weight stays unchanged, but value changes by δ(rhigh − rlow) ≥ 0. Therefore an optimal solution can always be rearranged so that higher-density items are filled before lower-density items.

Greedy-choice property

There exists an optimal solution that takes as much as possible from the currently highest-density remaining item. After fixing that amount, the same argument applies to the remaining capacity.

Why the greedy solution has a simple shape

Fractional Knapsack is a linear optimization problem with one capacity constraint. That geometry explains a fact the greedy algorithm makes visible: after sorting by density, an optimal solution can fill a prefix completely and then take at most one partial item.

1

Every unit of capacity spent on density ρ₁ is at least as valuable as the same unit spent on lower density ρ₂.

2

So if a lower-density item is used while a higher-density item is not full, transfer a small amount of weight upward. Value cannot decrease.

3

After all such exchanges, items form a density-sorted full prefix, possibly one fractional boundary item, then zeros. With tied densities, choose an equivalent optimum of this form.

marginal value of one more unit of capacity = value / weight

This proof breaks in 0/1 Knapsack

Everything above relies on being able to move an arbitrary amount of weight. With indivisible items, that exchange may not be legal at all.

Fractional version

Capacity 50 with A=(10,60), B=(20,100), C=(30,120). Density-greedy gets value 240 by taking A, B, and 2/3 of C — optimal.

0/1 version

The same density order takes A and B for value 160. But B+C fits exactly and gives 220. The greedy first choice A blocks the optimum.

Lesson. A tiny modeling change can destroy the greedy-choice property. Never transfer a greedy proof from one problem variant to another without checking its key assumption.

Greedy is still useful around 0/1 Knapsack

The fractional optimum is an upper bound on the 0/1 optimum: allowing fractions can only help. That bound is useful in branch-and-bound. For exact 0/1 Knapsack, a standard DP over capacity is pseudo-polynomial. A plain density-greedy choice by itself has no constant-factor guarantee; approximation needs an additional idea, such as also comparing against the best single item.

Full sort or priority queue?

The mathematical rule is the same—take the remaining item of largest density—but the data structure can change depending on how many items you expect to consume.

ImplementationCostWhen it is attractive
Sort all items by densityO(n log n)Simplest code; you may inspect most items anyway.
Build a max-heap of densitiesO(n + c log n)If only c highest-density items are extracted before capacity fills and c ≪ n.

Do not optimize the data structure before the proof

The proof is about density order, not sorting specifically. Once the greedy order is justified, sorting and a priority queue are interchangeable implementation choices.

Exercises

1

Value density

An item has weight 8 and value 52. What is its value density?

52 / 8 = 6.5 units of value per unit of weight.
2

Final fraction

Capacity 10 remains and the next item weighs 25 with value 100. What fraction is taken and how much value does it contribute?

Take 10/25 = 40% of the item. Its contribution is 0.4·100 = 40.
3

Proof assumption

Which assumption lets the exchange proof move equal weight between two items?

Items must be divisible. Without fractional choices, an equal-weight exchange may not correspond to any legal solution.
4

Edge cases

What should happen if capacity is already 0? What about an item with weight 0 and positive value?

No positive-weight item can be taken when capacity is 0. A positive-value item of weight 0 costs no capacity, so it should still be taken; this is why the implementation handles zero-weight items before the capacity loop.
