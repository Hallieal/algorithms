Постановка задачи

Что значит отсортировать последовательность?

Определение

Пусть дана последовательность элементов a = (a₁, a₂, …, aₙ), каждому из которых сопоставлен сравнимый ключ. Требуется построить перестановку исходных элементов b = (b₁, b₂, …, bₙ) такую, что key(b₁) ≤ key(b₂) ≤ … ≤ key(bₙ).

В определении существенны два требования: порядок должен стать неубывающим, а набор элементов должен остаться тем же. Сортировка не имеет права потерять элемент, добавить новый или изменить число его вхождений.

Связь с книгой

В книге Адитьи Бхаргавы сортировка вводится через практическую задачу упорядочивания объектов по числовому показателю: на каждом шаге выбирается следующий экстремальный элемент. Ниже эта идея формализована как сортировка выбором.

Перед началом

Мы будем различать три вопроса: корректен ли алгоритм, сколько операций он выполняет и сколько дополнительной памяти использует. Эти вопросы независимы: правильный алгоритм может быть слишком медленным, а быстрый — требовать слишком много памяти.

Алгоритм 1

Сортировка выбором

На позиции i должен стоять наименьший элемент среди a[i], a[i+1], …, a[n−1]. Поэтому на каждом шаге достаточно найти минимум неотсортированной части и поставить его на позицию i.

1

Разделить массив на отсортированный префикс и неотсортированный суффикс.

2

Найти минимальный элемент в неотсортированном суффиксе.

3

Поменять его местами с первым элементом этого суффикса.

4

Увеличить длину отсортированного префикса на единицу.

Инвариант цикла

Перед началом итерации с номером i префикс a[0:i] состоит из i наименьших элементов исходного массива и расположен в неубывающем порядке.

137485
Зелёная часть уже окончательно отсортирована. В оставшейся части ищется минимум.

Корректность

База. При i = 0 префикс пуст; утверждение выполняется.

Переход. Выбирается минимум суффикса. Все элементы префикса не больше него, поэтому после обмена новый элемент занимает правильную позицию i.

Завершение. После n−1 итераций первые n−1 элементов стоят на своих местах; последний определяется автоматически.

def selection_sort(a):
    n = len(a)
    for i in range(n - 1):
        min_pos = i
        for j in range(i + 1, n):
            if a[j] < a[min_pos]:
                min_pos = j
        a[i], a[min_pos] = a[min_pos], a[i]
    return a

Разбор реализации

Строка 3. После каждой итерации позиция i становится окончательной.

Строка 4. Изначально считаем, что минимум суффикса стоит на его первой позиции.

Строки 5–7. Полный просмотр суффикса находит позицию истинного минимума.

Строка 8. Один обмен расширяет отсортированный префикс на один элемент.

Число сравнений

На первой итерации выполняется n−1 сравнений, затем n−2, и так далее до одного:

(n−1) + (n−2) + ··· + 2 + 1 = n(n−1)/2.

Следовательно, число сравнений равно Θ(n²). Оно не зависит от исходного порядка элементов: уже отсортированный массив просматривается столь же полно, как и массив в обратном порядке.

худший случайΘ(n²)тот же полный поиск минимума
памятьΘ(1)in-place версия
Устойчивость

Сортировка называется устойчивой, если элементы с равными ключами сохраняют взаимный порядок. Приведённая in-place реализация сортировки выбором в общем случае неустойчива.

При первом обмене элемент 1 переносится в начало, а два равных элемента 2 меняют взаимный порядок.

Алгоритм 2

Сортировка вставками

Теперь используем другую идею: вместо поиска следующего минимума будем поддерживать отсортированный префикс и вставлять в него очередной элемент.

Инвариант цикла

Перед итерацией с номером i префикс a[0:i] отсортирован и содержит ровно те элементы, которые находились в первых i позициях исходного массива.

текущий элемент: 4
136487
Элементы 6 и, если потребуется, другие большие элементы сдвигаются вправо; затем 4 вставляется в освободившуюся позицию.

Корректность

База. Префикс длины один уже отсортирован.

Переход. Все элементы, большие текущего ключа, сдвигаются вправо. Ключ помещается после последнего элемента, не превосходящего его. Поэтому новый префикс отсортирован.

Завершение. При i = n отсортированный префикс совпадает со всем массивом.

Интерактивный пример

def insertion_sort(a):
    for i in range(1, len(a)):
        key = a[i]
        j = i - 1
        while j >= 0 and a[j] > key:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key
    return a

Разбор реализации

Строка 2. Элемент с индексом 0 уже образует отсортированный префикс.

Строки 3–4. Сохраняем вставляемый ключ и начинаем просмотр слева от него.

Строки 5–7. Каждый элемент, строго больший ключа, сдвигается на одну позицию вправо.

Строка 8. После завершения цикла позиция j+1 является единственным допустимым местом вставки ключа.

Почему лучший и худший случаи различаются?

Если массив уже отсортирован, условие a[j] > key сразу ложно на каждой итерации. Выполняется линейное число проверок и ни одного сдвига: время Θ(n).

Если массив отсортирован в обратном порядке, очередной ключ приходится переносить через весь текущий префикс:

1 + 2 + ··· + (n−1) = n(n−1)/2,

поэтому худшее время равно Θ(n²).

Дополнение курса

Более точная характеристика использует число инверсий. Инверсией называется пара индексов i < j, для которой a[i] > a[j]. Каждый сдвиг в сортировке вставками устраняет ровно одну инверсию. Если их число равно I, время работы можно оценить как Θ(n + I).

средний случайΘ(n²)квадратичное число сдвигов
худший случайΘ(n²)обратный порядок
памятьΘ(1)сортировка на месте
Почему эта реализация устойчива?

В условии внутреннего цикла используется строгое сравнение a[j] > key. Равный ключ не сдвигается вправо, поэтому новый элемент вставляется после уже находившихся в префиксе элементов с тем же ключом. Их взаимный порядок сохраняется.

Проверка понимания

Когда сортировка выбором может быть предпочтительнее?

Оба алгоритма имеют квадратичное худшее время. Попробуйте указать ситуацию, в которой свойство сортировки выбором всё же полезно.

Сортировка выбором выполняет не более n−1 обменов. Если запись или обмен элементов существенно дороже сравнения, малое число обменов может быть полезным, несмотря на Θ(n²) сравнений.
Вывод

Асимптотика не исчерпывает поведение алгоритма. Два алгоритма с одинаковым худшим временем могут различаться устойчивостью, числом записей, адаптивностью к входу и константами.

Задачи

Проверьте понимание

1

Точное число сравнений

Сколько сравнений элементов выполнит сортировка выбором для массива длины 8?

7 + 6 + 5 + 4 + 3 + 2 + 1 = 28 сравнений. Исходный порядок элементов на этот результат не влияет.
2

Почти отсортированный массив

В массиве длины n лишь один элемент сдвинут на несколько позиций влево. Какой из двух алгоритмов естественнее выбрать?

Сортировку вставками. Она использует уже существующий порядок: число сдвигов пропорционально числу инверсий, которое здесь мало. Сортировка выбором всё равно выполнит Θ(n²) сравнений.
3

Устойчивость

Почему замена условия a[j] > key на a[j] >= key в сортировке вставками разрушает устойчивость?

При равенстве ключей более ранний элемент будет сдвинут вправо, а более поздний окажется перед ним. Следовательно, относительный порядок равных ключей может измениться.
4

Изменение порядка сортировки

Какие сравнения нужно изменить в двух реализациях, чтобы получить сортировку по невозрастанию?

В сортировке выбором нужно выбирать максимум, то есть заменить a[j] < a[min_pos] на сравнение с максимумом. В сортировке вставками сдвигать нужно элементы, меньшие ключа: a[j] < key.
5

Трассировка

Как будет выглядеть массив [5, 2, 4, 6, 1, 3] после первых трёх внешних итераций сортировки вставками?

После i = 1: [2, 5, 4, 6, 1, 3].
После i = 2: [2, 4, 5, 6, 1, 3].
После i = 3: [2, 4, 5, 6, 1, 3], поскольку 6 уже стоит после отсортированного префикса в правильной позиции.
