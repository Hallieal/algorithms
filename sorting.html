What does it mean to sort a sequence?

Start with a simple example

Suppose you have a list of songs together with the number of times each song has been played. You want the most frequently played songs to appear first.

One possible procedure is straightforward: find the song with the largest play count, put it first, then repeat the same operation for the remaining songs.

Definition

Sorting is the process of arranging a set of elements or data according to a specified rule or property, for example in ascending order, descending order, alphabetical order, or by date.

A sorting algorithm is a step-by-step procedure for placing the elements of an array or list in the required order. Common examples include Bubble Sort, Selection Sort, and Merge Sort.

Selection Sort

Selection Sort fills the array from left to right. First, it finds the smallest element in the whole array and puts it in the first position. Then it finds the smallest element among those that remain and puts it in the second position. The same operation is repeated until the array is sorted.

More precisely, at step i the positions before i are already fixed. The algorithm searches for the smallest element among ai, ai+1, …, an−1 and moves it to position i.

1

Choose the unsorted part

The positions already filled on the left will no longer change.

2

Find the minimum

Look through the remaining elements and keep track of the smallest value found.

3

Place it

Move the smallest value found into the first free position.

4

Continue

One more position is now correct; repeat the same procedure for the rest.

Loop invariant

After the first i positions have been filled, they contain the i smallest elements of the array in sorted order. The next scan finds the smallest element that is still left and places it immediately after them.

1 3 7 4 8 5

The green prefix is final. The minimum is searched only in the remaining suffix.

Correctness

Initialization. At the beginning, no position has been filled yet.

Maintenance. At each step, the smallest element that has not yet been placed is moved into the first free position. Therefore the sorted part remains correct and grows by one element.

Termination. Once all but one positions have been filled, the only remaining element must belong in the last position. The entire array is then sorted.

Line 3. We fill the array from left to right. During this pass, the algorithm decides which value belongs in position i.

4

5–7

Number of comparisons

The first iteration performs n−1 comparisons, the next performs n−2, and so on.

(n − 1) + (n − 2) + ··· + 2 + 1
=
n(n − 1) / 2

Thus Selection Sort performs Θ(n2) comparisons. The number of comparisons does not depend on the initial order of the array.

Insertion Sort

Insertion Sort also processes the array from left to right, but it uses a different idea. The left part of the array is kept sorted. The next element is taken from the unsorted part and inserted into the correct place among the elements that have already been processed.

Loop invariant

Before step i, the elements to the left of position i are already sorted. The current element is then inserted into the correct place inside this sorted part.

1 3 6 4 8 7

The current element 4 must be inserted into the sorted prefix 1, 3, 6.

Correctness

Initialization. The first element alone is already sorted.

Maintenance. To insert the next element, every larger element immediately to its left is shifted one position to the right. The new element is placed in the gap that remains.

Termination. When every element has been inserted, the whole array is sorted.

Implementation

2

Line 2. The first element is already sorted by itself, so the algorithm starts with the second element and processes the array from left to right.

3–4

Lines 3–4. We save the element that must be inserted and start comparing it with the element immediately to its left.

5–7

Lines 5–7. While an element on the left is larger, it is shifted one position to the right. This creates space for the element being inserted.

8

Line 8. When no larger element remains on the left, the saved value is placed into the open position.

Best and worst cases

If the array is already sorted, the condition inside the while-loop fails immediately on every iteration. There are only linearly many checks and no shifts, so the running time is Θ(n).

If the array is in decreasing order, the element processed at iteration i must pass through the entire sorted prefix.

1 + 2 + ··· + (n − 1)
=
n(n − 1) / 2

Therefore the worst-case running time is Θ(n2).

Inversions

An inversion is a pair of positions i < j such that ai > aj. Each shift performed by Insertion Sort removes exactly one inversion.

If the input contains I inversions, the running time can be written more precisely as Θ(n + I). This explains why Insertion Sort is efficient on nearly sorted arrays.

Best caseΘ(n)already sorted
Average caseΘ(n²)quadratic number of shifts
Worst caseΘ(n²)decreasing order
Extra memoryΘ(1)in-place

Stability

The implementation above is stable because the loop shifts an element only when it is strictly larger than the element being inserted. Equal elements are not moved past one another.

Replacing the strict comparison by a[j] >= key would destroy this property: an earlier element with the same value could be shifted to the right of a later one.

Question

When can Selection Sort still be useful even though its best-case running time is quadratic?

Selection Sort performs at most n−1 swaps. If writing or moving an element is much more expensive than comparing two elements, reducing the number of swaps can be useful even though the algorithm still performs Θ(n²) comparisons.

Conclusion

Asymptotic running time does not describe every relevant property of an algorithm. Algorithms with the same worst-case complexity may differ in stability, data movement, adaptivity to the input, memory use, and constant factors.

Exercises

1

Exact number of comparisons

How many element comparisons does Selection Sort perform on an array of length 8?

7 + 6 + 5 + 4 + 3 + 2 + 1 = 28 comparisons. The initial order of the elements does not change this number.
2

Nearly sorted input

An array of length n is already sorted except that one element has been moved a few positions to the left. Which of the two algorithms above is the more natural choice?

Insertion Sort. The number of inversions is small, so only a small number of shifts is required. Selection Sort still performs Θ(n²) comparisons.
3

Stability

Explain why replacing a[j] > key with a[j] >= key makes the Insertion Sort implementation unstable.

With the non-strict comparison, an earlier element equal to the current element is shifted to the right. The later element can therefore move in front of it, changing the relative order of equal keys.
4

Decreasing order

Which comparisons should be changed in the two implementations to sort in nonincreasing order?

Selection Sort should search for the maximum instead of the minimum. In Insertion Sort, elements smaller than the current value should be shifted to the right.
