Chapter 1 · Section 4

Quick Sort

Choose a pivot, partition around it, and recursively sort the two sides.

Pivot and partition

Quick Sort organizes the array around one chosen element, called the pivot. Every other element is placed on the correct side of the pivot, and the two resulting parts are sorted recursively.

p

The pivot creates a boundary

After partitioning, every element in the left part is at most the pivot, and every element in the right part is greater than the pivot. The pivot therefore belongs between the two parts in the final sorted order.

1

Choose a pivot

In our educational implementation, the first element is used as the pivot.

2

Partition

Put every remaining element into the left part if it is at most the pivot, otherwise into the right part.

3

Sort recursively

Apply Quick Sort independently to the left and right parts.

4

Combine

Concatenate the sorted left part, the pivot, and the sorted right part.

Why Quick Sort is correct

≤ | >

The partition property

Partitioning establishes the only boundary we need: every value in the left part is at most the pivot, while every value in the right part is greater than the pivot.

1

Base case

An array containing zero or one element is already sorted. Quick Sort returns it immediately.

2

Induction assumption

Assume that Quick Sort correctly sorts every array shorter than the current one. Both partitions are shorter because the pivot itself is removed from them.

3

Recursive calls

By the induction assumption, the recursive call correctly sorts the left part and the recursive call correctly sorts the right part.

4

Concatenation

Every element of the sorted left part is at most the pivot, and every element of the sorted right part is greater than the pivot. So the three blocks can be placed next to one another without creating an inversion across their boundaries.

sorted left + pivot + sorted right → sorted array

Implementation

This version mirrors the algorithm directly: choose the first element as the pivot, build the two partitions, sort both recursively, and concatenate the result.

1def quick_sort(a):
2 if len(a) < 2:
3 return a
4
5 pivot = a[0]
6 left = [x for x in a[1:] if x <= pivot]
7 right = [x for x in a[1:] if x > pivot]
8
9 sorted_left = quick_sort(left)
10 sorted_right = quick_sort(right)
11
12 return sorted_left + [pivot] + sorted_right

Implementation notes

2–3

Lines 2–3. Empty and one-element arrays are already sorted. This is the base case of the recursion.

5

Line 5. The first element is chosen as the pivot. This is simple, but it is not always a good pivot choice.

6–7

Lines 6–7. Every remaining element is classified exactly once: values at most the pivot go left; larger values go right.

9–10

Lines 9–10. The two smaller partitions are sorted recursively.

12

Line 12. Because partitioning established the correct boundary, placing the pivot between the two sorted parts gives the final sorted array.

This educational implementation is not in-place

The list comprehensions create new left and right arrays. Standard production implementations often partition the original array in place instead. The time analysis below applies to the partition structure itself; memory usage depends on the implementation.

Pivot choice

Why random pivots help

The code above always uses the first element, so an already sorted array produces the worst-case chain. If the pivot is chosen uniformly at random instead, systematically bad partitions become unlikely. Randomized Quick Sort has expected running time Θ(n log n).

Complexity

n

Partitioning one subarray is linear

Every element other than the pivot is inspected once to decide whether it belongs to the left or right partition. Partitioning an array of length n therefore costs Θ(n).

Memory and stability

Memory

The implementation shown above allocates new arrays for the two partitions, so it is not an in-place implementation.

A standard in-place Quick Sort rearranges elements inside the original array. Its additional memory is then mainly the recursion stack: Θ(log n) for balanced recursion and Θ(n) in the worst case.

Stability

Quick Sort is not stable in its usual form. Partitioning and swaps can change the relative order of elements with equal keys.

Even the simple implementation above can move an element equal to the pivot before that pivot, although the pivot originally appeared first.

Merge Sort vs Quick Sort

Both algorithms use divide and conquer, but they do the important work at different moments.

Merge Sort

  • splits by position into two nearly equal halves;
  • recursively sorts the halves;
  • does the main combine work after recursion;
  • guarantees Θ(n log n) time;
  • standard array implementation uses Θ(n) extra memory;
  • can be stable.

Quick Sort

  • splits according to values relative to a pivot;
  • the partition sizes depend on the pivot;
  • does the main organizing work before recursion;
  • has average / expected Θ(n log n) time;
  • can partition arrays in place;
  • is usually not stable.

Exercises

1

Partition by hand

Using the first element as the pivot, partition [6, 2, 9, 1, 7, 4] into the two groups used by the implementation above.

The pivot is 6. The left partition is [2, 1, 4] and the right partition is [9, 7].
2

Worst-case input

Why is an already increasing array a worst-case input for the displayed implementation?

The first element is always the smallest remaining value. Therefore the left partition is empty and the right partition has sizes n−1, n−2, .... The recursion becomes a chain, producing Θ(n²) work.
3

Correctness

After the recursive calls return, why is no comparison needed between an element of the left partition and an element of the right partition?

Partitioning already guarantees that every left value is at most the pivot and every right value is greater than the pivot. Hence every left value is automatically no larger than every value that appears after the pivot in the final concatenation.
4

Pivot choice

Suppose every partition splits the array approximately in the ratio 1:3 instead of exactly in half. Does the asymptotic running time remain Θ(n log n)?

Yes. The larger recursive subproblem shrinks by a constant factor on every level, so the recursion depth is still Θ(log n). The total partition work per level remains Θ(n).
