Ближайшая пара точек

Два отсортированных представления одних и тех же точек позволяют заменить полный перебор на O(n log n).

HardDivide & conquerГеометрия

Условие

Перебрать все пары просто, но это O(n²). Нужно доказать, что подавляющее большинство пар можно вообще не рассматривать.

Задача

Найти минимальное евклидово расстояние

Даны n ≥ 2 различных точек на плоскости. Нужно найти минимальное евклидово расстояние между двумя точками и вернуть одну пару, на которой оно достигается.

d(p,q) = √((pₓ−qₓ)² + (pᵧ−qᵧ)²)
Геометрическая картина
фиолетовая область = полоса ширины 2dкрасные точки = кандидат через границу

Главная идея

Рекурсивно решим задачу в двух половинах. После этого улучшить найденное расстояние d может только пара, пересекающая линию разбиения и лежащая в узкой полосе.

Divide and conquer

После рекурсии остаётся проверить только полосу

Сортируем точки по x-координате и делим пополам. Пусть d — минимум из двух рекурсивных ответов. Если пара из разных половин ближе, чем d, то её горизонтальное расстояние меньше d. Значит, обе точки находятся не дальше d от линии разбиения.

левая половинавсе пары целиком слева уже обработаны рекурсией
правая половинавсе пары целиком справа уже обработаны рекурсией
полосатолько здесь может скрываться лучшая пара через границу
sort by x

Даёт сбалансированное геометрическое разбиение.

sort by y

Позволяет просматривать кандидатов в полосе снизу вверх без новой сортировки.

следующие 15

Packing-аргумент делает проверку полосы линейной.

Почему достаточно пятнадцати следующих точек?

Зафиксируем точку p в полосе. Точка q может улучшить текущее расстояние d только если находится менее чем на d выше p. Все релевантные следующие кандидаты лежат в прямоугольнике ширины 2d и высоты d. Разделим этот прямоугольник на восемь квадратов d/2 × d/2. Две точки из одной и той же рекурсивной половины не могут попасть в один квадрат: диаметр такого квадрата равен d/√2 < d, что противоречит уже найденному расстоянию внутри этой половины. Поэтому в одном квадрате может быть не более двух точек — по одной из каждой половины. Всего в восьми квадратах находится не более шестнадцати точек вместе с p, то есть после p достаточно проверить не более пятнадцати кандидатов. Классический более тонкий packing-аргумент уменьшает эту константу до семи, но для той же сложности O(n log n) достаточно пятнадцати.

Алгоритм

1

Отсортировать дважды

Храним те же точки в порядке по x и в порядке по y.

2

Разделить по x

Делим x-порядок пополам и разбиваем y-порядок на те же два множества точек.

3

Рекурсивно решить половины

Берём меньшее из двух полученных расстояний как текущее d.

4

Проверить полосу

Оставляем точки полосы в y-порядке и для каждой проверяем максимум пятнадцать следующих.

I

Рекурсивный инвариант

Каждый вызов получает одно и то же множество точек в двух представлениях — отсортированном по x и по y — и возвращает настоящую ближайшую пару внутри этого множества.

Корректность и сложность

✓

У глобально ближайшей пары есть только три варианта

Обе точки слева, обе справа или точки лежат по разные стороны линии разбиения. Алгоритм покрывает все три случая.

1

Пары внутри половин

По индукции рекурсивные вызовы находят точные минимальные расстояния слева и справа.

2

Пары через границу

Если такая пара ближе d, обе её точки обязательно попадают в центральную полосу.

3

Полоса проверяется полностью

Packing-лемма гарантирует, что любой возможный партнёр ближе d находится среди следующих пятнадцати точек в y-порядке. Поэтому ни одна улучшающая пара не пропускается.

Начальная сортировкаO(n log n)

Один раз сортируем по x и по y.

РекурсияO(n log n)

На каждом уровне суммарно выполняется O(n) работы.

ПамятьO(n)

Разбиения y-порядка, множества идентификаторов и полосы дают линейный пик памяти.

Реализация

Внутри рекурсии сравниваются квадраты расстояний, поэтому дорогостоящий квадратный корень вычисляется только один раз — для финального ответа.

Python
from math import sqrt


def closest_pair(points):
    if len(points) < 2:
        raise ValueError("at least two points are required")

    pts = [(x, y, i) for i, (x, y) in enumerate(points)]
    px = sorted(pts, key=lambda p: (p[0], p[1], p[2]))
    py = sorted(pts, key=lambda p: (p[1], p[0], p[2]))

    def dist2(p, q):
        dx = p[0] - q[0]
        dy = p[1] - q[1]
        return dx * dx + dy * dy

    def solve(px, py):
        n = len(px)
        if n <= 3:
            best2 = float("inf")
            pair = None
            for i in range(n):
                for j in range(i + 1, n):
                    current = dist2(px[i], px[j])
                    if current < best2:
                        best2 = current
                        pair = (px[i], px[j])
            return best2, pair

        mid = n // 2
        left_x = px[:mid]
        right_x = px[mid:]
        split_x = (left_x[-1][0] + right_x[0][0]) / 2

        left_ids = {p[2] for p in left_x}
        left_y, right_y = [], []
        for p in py:
            if p[2] in left_ids:
                left_y.append(p)
            else:
                right_y.append(p)

        dl2, pair_l = solve(left_x, left_y)
        dr2, pair_r = solve(right_x, right_y)

        if dl2 <= dr2:
            best2, pair = dl2, pair_l
        else:
            best2, pair = dr2, pair_r

        strip = [
            p for p in py
            if (p[0] - split_x) ** 2 < best2
        ]

        for i in range(len(strip)):
            for j in range(i + 1, min(i + 16, len(strip))):
                dy = strip[j][1] - strip[i][1]
                if dy * dy >= best2:
                    break

                current = dist2(strip[i], strip[j])
                if current < best2:
                    best2 = current
                    pair = (strip[i], strip[j])

        return best2, pair

    best2, pair = solve(px, py)
    clean_pair = tuple((p[0], p[1]) for p in pair)
    return sqrt(best2), clean_pair


points = [
    (2, 3), (12, 30), (40, 50),
    (5, 1), (12, 10), (3, 4),
]
print(closest_pair(points))
Как читать код

Сохраняем оба порядка

left_ids

Разделяет y-отсортированный список на те же множества точек, что и x-разбиение, без повторной сортировки.

strip

Фильтруется из уже y-отсортированного списка, поэтому автоматически остаётся отсортированным по y.

min(i + 16, ...)

Проверяет не более пятнадцати следующих точек — именно такую простую и полностью общую границу доказывает packing-лемма на этой странице.
