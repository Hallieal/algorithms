Быстрая сортировка

Выбираем опорный элемент, разбиваем массив относительно него и рекурсивно сортируем две получившиеся части.

Опорный элемент и разбиение

Быстрая сортировка организует массив относительно одного выбранного элемента — опорного элемента. Все остальные элементы распределяются по нужную сторону от него, после чего две части сортируются рекурсивно.

p

Опорный элемент задаёт границу

После разбиения каждый элемент левой части не больше опорного, а каждый элемент правой части больше него. Значит, в итоговом отсортированном массиве опорный элемент должен стоять между этими двумя частями.

1

Выбрать опорный элемент

В учебной реализации в качестве опорного используется первый элемент массива.

2

Разбить

Каждый оставшийся элемент отправить в левую часть, если он не больше опорного, и в правую — иначе.

3

Отсортировать рекурсивно

Независимо применить быструю сортировку к левой и правой частям.

4

Объединить

Соединить отсортированную левую часть, опорный элемент и отсортированную правую часть.

Свойство разбиения

Разбиение создаёт ровно ту границу, которая нам нужна: каждое значение слева не больше опорного, а каждое значение справа больше него.

1

База рекурсии

Массив из нуля или одного элемента уже отсортирован. Быстрая сортировка сразу возвращает его.

2

Индукционное предположение

Предположим, что быстрая сортировка корректно сортирует любой массив, короче текущего. Обе части короче исходного массива, потому что опорный элемент в них не входит.

3

Рекурсивные вызовы

По индукционному предположению один рекурсивный вызов корректно сортирует левую часть, а другой — правую.

4

Объединение

Каждый элемент отсортированной левой части не больше опорного, а каждый элемент отсортированной правой части больше него. Поэтому три блока можно поставить подряд, не создавая инверсии на границах.

отсортированная левая часть + опорного элемента + отсортированная правая часть → отсортированный массив

Реализация

Эта версия буквально повторяет идею алгоритма: выбираем первый элемент как опорный, строим две части, рекурсивно сортируем каждую и соединяем результат.

1def quick_sort(a):
2 if len(a) < 2:
3 return a
4
5 pivot = a[0]
6 left = [x for x in a[1:] if x <= pivot]
7 right = [x for x in a[1:] if x > pivot]
8
9 sorted_left = quick_sort(left)
10 sorted_right = quick_sort(right)
11
12 return sorted_left + [pivot] + sorted_right

Комментарии к реализации

2–3

Строки 2–3. Пустой массив и массив из одного элемента уже отсортированы. Это база рекурсии.

5

Строка 5. Первый элемент выбирается опорным. Это просто, но такой выбор далеко не всегда удачен.

6–7

Строки 6–7. Каждый оставшийся элемент распределяется ровно один раз: значения не больше опорного идут влево, большие — вправо.

9–10

Строки 9–10. Две меньшие части сортируются рекурсивно.

12

Строка 12. Поскольку разбиение уже создало правильную границу, достаточно поставить опорный элемент между двумя отсортированными частями, чтобы получить итоговый массив.

Эта учебная реализация работает не на месте

Генераторы списков создают новые массивы left и right . В практических реализациях исходный массив часто разбивается на месте. Анализ времени ниже относится к самой структуре разбиения; расход памяти зависит от реализации.

Выбор опорного элемента

В отличие от сортировки слиянием, быстрая сортировка не гарантирует двух равных подзадач. Размеры рекурсивных вызовов определяются выбранным опорным элементом.

Почему случайный выбор опорного элемента помогает

В коде выше опорным всегда выбирается первый элемент, поэтому уже отсортированный массив порождает худший случай — длинную цепочку рекурсивных вызовов. Если выбирать опорный элемент равновероятно случайно, систематически неудачные разбиения становятся маловероятны. Для рандомизированной быстрой сортировки математическое ожидание времени работы равно Θ(n log n).

Сложность

Разбиение одного подмассива занимает линейное время

Каждый элемент, кроме опорного, просматривается один раз, чтобы определить, в какую часть он попадает. Поэтому разбиение массива длины n занимает Θ(n).

Память и устойчивость

Память

Показанная выше реализация создаёт новые массивы для двух частей, поэтому она работает не на месте.

Стандартная быстрая сортировка на месте переставляет элементы внутри исходного массива. Тогда основная дополнительная память — стек рекурсии: Θ(log n) при сбалансированной рекурсии и Θ(n) в худшем случае.

Устойчивость

Обычная быстрая сортировка неустойчива. Разбиение и обмены могут менять взаимный порядок элементов с одинаковыми ключами.

Даже простая реализация выше может перенести элемент, равный опорному, перед самим опорным элементом, хотя изначально тот стоял раньше.

Aliceбалл 2
Bobбалл 2
Caraбалл 1
→
Caraбалл 1
Bobбалл 2
Aliceбалл 2

Если Alice выбрана опорным элементом, Bob попадёт в левую часть, потому что его ключ равен ключу опорного элемента. После объединения Bob может оказаться перед Alice.

Сортировка слиянием и быстрая сортировка

Оба алгоритма используют принцип «разделяй и властвуй», но основная работа выполняется в разные моменты.

Сортировка слиянием

  • делит массив по позициям на две почти равные половины;
  • рекурсивно сортирует половины;
  • выполняет основную работу по объединению после рекурсии;
  • гарантирует Θ(n log n) времени;
  • стандартная реализация на массивах использует Θ(n) дополнительной памяти;
  • может быть устойчивой.

Быстрая сортировка

  • делит массив по значениям относительно опорного элемента;
  • размеры частей зависят от выбора опорного элемента;
  • выполняет основную работу по упорядочиванию до рекурсии;
  • имеет среднее / ожидаемое Θ(n log n) времени;
  • может разбивать массив на месте;
  • обычно неустойчива.

Можно ли сортировать сравнениями быстрее?

Сортировка слиянием работает за логлинейное время, а у рандомизированной быстрой сортировки логлинейно математическое ожидание времени. Возникает естественный вопрос: можно ли асимптотически сортировать сравнениями быстрее? В худшем случае — нет.

?

Алгоритм должен различать все возможные порядки

Если вход содержит n различных элементов, существует n! возможных взаимных порядков. Корректный алгоритм сортировки сравнениями должен получить достаточно информации, чтобы различить каждый из них.

1

Одно сравнение даёт два исхода

Сравнение вида a < b имеет два возможных исхода. Поэтому алгоритм сортировки сравнениями можно представить бинарным деревом решений.

2

Дереву нужно не менее n! листьев

Каждый возможный порядок входа должен приводить к соответствующему правильному ответу. Значит, в дереве решений должен быть хотя бы один лист для каждого возможного порядка.

3

Бинарное дерево высоты h имеет не более 2^h листьев

Следовательно,

2h ≥ n! ⇒ h ≥ log2(n!)
4

Нижняя граница — логлинейная

Поскольку log(n!) = Θ(n log n)каждый алгоритм сортировки сравнениями требует Ω(n log n) сравнений в худшем случае.

Ω

Для сортировок сравнениями достигнута асимптотическая граница

Сортировка слиянием уже достигает этой нижней границы в худшем случае. Чтобы сортировать асимптотически быстрее, нужно использовать информацию о ключах, выходящую за рамки попарных сравнений.

Следующая идея

Можно ли сортировать быстрее вообще?

Да, если использовать дополнительную структуру ключей. Первый пример — сортировка подсчётом: вместо того чтобы узнавать порядок только через сравнения, она использует тот факт, что ключи — целые числа из известного диапазона.

Задачи

1

Разбейте массив вручную

Используя первый элемент как опорный, разбейте [6, 2, 9, 1, 7, 4] на две группы так же, как это делает реализация выше.

Опорный элемент равен 6. Левая часть — [2, 1, 4] а правая часть — [9, 7].
2

Вход для худшего случая

Почему уже отсортированный по возрастанию массив является худшим входом для показанной реализации?

Первый элемент всегда оказывается минимальным среди оставшихся. Поэтому левая часть пуста, а размеры правой части последовательно равны n−1, n−2, .... Рекурсия превращается в цепочку, что даёт Θ(n²) работы.
3

Корректность

Почему после возврата из рекурсивных вызовов не нужно дополнительно сравнивать элементы левой и правой частей?

Разбиение уже гарантирует, что каждое значение слева не больше опорного, а каждое значение справа больше него. Значит, любой левый элемент автоматически не больше любого элемента, который окажется после опорного в итоговом объединении.
4

Выбор опорного элемента

Пусть каждое разбиение делит массив примерно в отношении 1:3, а не пополам. Сохранится ли та же асимптотика времени Θ(n log n)?

Да. Более крупная рекурсивная подзадача на каждом уровне уменьшается в постоянное число раз, поэтому глубина рекурсии по-прежнему равна Θ(log n). Суммарная работа по разбиениям на каждом уровне остаётся равной Θ(n).
