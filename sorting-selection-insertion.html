Selection and Insertion Sorts

Two elementary sorting algorithms and the basic ideas used to analyze them.

Prefix and suffix

We will repeatedly divide an array into a part on the left and a part on the right. The following two terms will be used throughout the chapter.

Prefix

A prefix is a consecutive initial part of a sequence: it always starts with the first element.

2 5 3 8 1

Here, 2, 5 is a prefix.

Suffix

A suffix is a consecutive final part of a sequence: it always ends with the last element.

2 5 3 8 1

Here, 3, 8, 1 is a suffix.

Selection Sort

Selection Sort fills the array from left to right. First, it finds the smallest element in the whole array and puts it in the first position. Then it finds the smallest element among those that remain and puts it in the second position. The same operation is repeated until the array is sorted.

At step i, all positions before i are already fixed. The algorithm searches for the smallest element among ai, ai+1, …, an−1 and moves it to position i.

1

Choose the remaining part

The positions already filled on the left will no longer change.

2

Find the minimum

Look through the remaining elements and keep track of the smallest value found.

3

Place the minimum

Move the smallest value found into the first free position.

4

Repeat

One more position is now correct; apply the same procedure to the remaining suffix.

Loop invariant

After the first i positions have been filled, they contain the i smallest elements of the array in sorted order. The next scan finds the smallest element that is still left and places it immediately after them.

1 3 7 4 8 5

The green prefix is finished. The next minimum is searched for in the remaining suffix.

Correctness

Initialization. At the beginning, no position has been filled yet.

Maintenance. At each step, the smallest element that has not yet been placed is moved into the first free position. Therefore the sorted part remains correct and grows by one element.

Termination. Once all but one positions have been filled, the only remaining element must belong in the last position. The whole array is then sorted.

Implementation

3

Line 3. The algorithm fills the array from left to right. During this iteration it determines which value belongs in position i.

4

Line 4. Before looking through the remaining elements, we temporarily assume that the value already in position i is the smallest one left.

5–7

Lines 5–7. We inspect every later element. Whenever a smaller value is found, we remember its position.

8

Line 8. After the scan, the smallest value found is moved into position i. One more position is now correct.

Number of comparisons

The first pass compares the current minimum with n − 1 later elements. The next pass uses n − 2 comparisons, and so on.

(n − 1) + (n − 2) + ··· + 2 + 1 = n(n − 1) / 2

Therefore Selection Sort performs Θ(n2) comparisons. This number does not depend on whether the input is already sorted or completely reversed.

Insertion Sort

Insertion Sort also processes the array from left to right, but it uses a different idea. The left part is kept sorted. The next element is taken from the unsorted part and inserted into the correct place among the elements that have already been processed.

Loop invariant

Before step i, the elements to the left of position i are already sorted. The current element is then inserted into the correct place inside this sorted prefix.

1 3 6 4 8 7

The value 4 must be inserted into the sorted prefix 1, 3, 6.

Correctness

Initialization. The first element alone is already sorted.

Maintenance. To insert the next element, every larger element immediately to its left is shifted one position to the right. The new element is placed in the gap that remains.

Termination. When every element has been inserted, the whole array is sorted.

1def insertion_sort(a):
2 for i in range(1, len(a)):
3 key = a[i]
4 j = i - 1
5 while j >= 0 and a[j] > key:
6 a[j + 1] = a[j]
7 j -= 1
8 a[j + 1] = key
9 return a

Implementation

2

Line 2. The first element is already sorted by itself, so the algorithm starts with the second element and moves from left to right.

3–4

Lines 3–4. We save the value that must be inserted and begin with the element immediately to its left.

5–7

Lines 5–7. While an element on the left is larger, it is shifted one position to the right. These shifts create an empty position for the saved value.

8

Line 8. Once no larger element remains on the left, the saved value is placed into the open position.

Best and worst cases

If the array is already sorted, the inner loop stops immediately on every pass. There are only linearly many checks and no shifts, so the running time is Θ(n).

If the array is in decreasing order, each new element must move through the entire sorted prefix.

1 + 2 + ··· + (n − 1) = n(n − 1) / 2

Therefore the worst-case running time is Θ(n2).

Inversions

An inversion is a pair of positions i < j for which the earlier element is larger than the later element. Each shift made by Insertion Sort removes one inversion.

If the input contains I inversions, the running time can be written more precisely as Θ(n + I). This explains why Insertion Sort is efficient on nearly sorted arrays.

Best caseΘ(n)already sorted
Average caseΘ(n²)quadratic number of shifts
Worst caseΘ(n²)decreasing order
Extra memoryΘ(1)in-place

Stability

The implementation above is stable because an element is shifted only when it is strictly larger than the value being inserted. Equal elements are therefore never moved past one another.

If equal elements were shifted as well, a later occurrence could move in front of an earlier one, and the sorting algorithm would no longer be stable.

Question

When can Selection Sort still be useful even though its best-case running time is quadratic?

Selection Sort performs at most n − 1 swaps. If writing or moving an element is much more expensive than comparing two elements, reducing the number of swaps can be useful even though the algorithm still performs Θ(n²) comparisons.

Exercises

1

Exact number of comparisons

How many element comparisons does Selection Sort perform on an array of length 8?

7 + 6 + 5 + 4 + 3 + 2 + 1 = 28 comparisons. The initial order of the elements does not change this number.
2

Nearly sorted input

An array of length n is already sorted except that one element has been moved a few positions to the left. Which of the two algorithms above is the more natural choice?

Insertion Sort. The number of inversions is small, so only a small number of shifts is required. Selection Sort still performs Θ(n²) comparisons.
3

Stability

Why would Insertion Sort become unstable if it also shifted elements equal to the value being inserted?

An earlier occurrence of an equal value could be shifted to the right, allowing a later occurrence to move in front of it. Their original relative order would then change.
4

Decreasing order

What changes are needed in the two algorithms to sort from largest to smallest?

Selection Sort should repeatedly choose the largest remaining value instead of the smallest. Insertion Sort should shift values that are smaller than the value being inserted.
