Восстановление решения

DP-таблица часто хранит только значение оптимума. Если задача просит сами выбранные предметы, путь или последовательность операций, нужно восстановить решения, которые привели к финальному состоянию.

Оптимальное значение и оптимальное решение — не одно и то же

В LCS таблица может сообщить, что максимальная длина равна 3; в knapsack — что максимальная ценность равна 12. Но эти числа сами по себе не говорят, какие символы или предметы были выбраны. Во время DP мы уже сравнивали допустимые предыдущие состояния. Восстановление просто повторяет эти решения в обратном порядке.

Значение

Максимальная ценность = 12. Длина LCS = 3. Минимальная стоимость = 7.

Решение

Предметы {0, 3}. Подпоследовательность «ABD». Конкретный путь по сетке.

Идти назад по переходам

Начинаем с конечного состояния. Проверяем, какой переход мог дать его значение, переходим в соответствующего предшественника и повторяем, пока не достигнем базового состояния. Поэтому reconstruction обычно идёт от ответа к началу.

Пример: какие предметы попали в knapsack

Для 0/1 knapsack сравним dp[i][w] с dp[i−1][w]. Если значения равны, существует оптимальное решение, в котором i-й предмет не нужен. Если они различаются, текущий предмет был взят: записываем его и уменьшаем capacity на его вес.

dp[i][w] = dp[i−1][w]   ⇒   можно пропустить предмет i
dp[i][w] ≠ dp[i−1][w]   ⇒   предмет i выбран
Python · value + chosen item indices
def chosen_items(weights, values, capacity):
    n = len(weights)
    dp = [[0] * (capacity + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        weight = weights[i - 1]
        value = values[i - 1]

        for w in range(capacity + 1):
            dp[i][w] = dp[i - 1][w]
            if weight <= w:
                dp[i][w] = max(
                    dp[i][w],
                    value + dp[i - 1][w - weight]
                )

    chosen = []
    w = capacity

    for i in range(n, 0, -1):
        if dp[i][w] != dp[i - 1][w]:
            chosen.append(i - 1)
            w -= weights[i - 1]

    chosen.reverse()
    return dp[n][capacity], chosen

Когда хранить parent pointers

Иногда по значениям таблицы легко понять, откуда пришёл оптимум, как в LCS или стандартном knapsack. В более сложных переходах удобнее при вычислении каждой клетки сохранить явного предшественника — parent pointer. Тогда числовая таблица отвечает «сколько?», а parent — «откуда пришли?».

Общая схема
parent[r][c] = previous_state

# After the DP table is complete:
state = goal
path = []

while state is not None:
    path.append(state)
    state = parent[state]

path.reverse()

Что делать при нескольких оптимальных решениях

Оптимальное решение не обязано быть единственным. Если два перехода дают одинаковое значение, обычный traceback выбирает один из них согласно правилу разрешения равенства. Чтобы перечислить все оптимальные решения, нужно исследовать все оптимальные ветви; их число может быть очень большим.

Tie-breaking не меняет оптимальное значение, но может менять конкретное возвращаемое решение. Поэтому условие вроде >= вместо > иногда влияет на результат reconstruction, хотя числовой DP остаётся тем же.

Сжатие памяти может стереть путь

Оптимизация памяти и восстановление решения преследуют разные цели. Если оставить только две последние строки или несколько скаляров, старые решения могут исчезнуть. Иногда путь можно восстановить дополнительными данными, иногда таблицу приходится сохранить, а для некоторых задач существуют более тонкие методы восстановления с малой памятью.

Поэтому вопрос «нужно ли вернуть только значение или само решение?» лучше задавать до оптимизации памяти, а не после неё.
