Memoization and Tabulation

Top-down and bottom-up are not two different ideas. They evaluate the same states under the same recurrence — in different orders.

One recurrence, two evaluation orders

Consider the climbing-stairs problem. From each step you may move by 1 or 2. Let dp[i] be the number of ways to reach exactly step i. The final move to i must come from either i−1 or i−2, so

dp[i] = dp[i − 1] + dp[i − 2]

The meaning of dp[i] does not depend on the implementation. Only one question changes: when do we compute it?

Top-down: store a result on its first visit

Top-down begins with the original question — for example, ways(6). The function recursively asks for smaller states. Before computing a state it checks the cache; after computing it, it stores the answer. Each state is therefore fully solved at most once.

Python · top-down
def ways(n, memo):
    if n <= 1:
        return 1

    if n in memo:
        return memo[n]

    memo[n] = ways(n - 1, memo) + ways(n - 2, memo)
    return memo[n]

Memoization = recursion plus a cache of results. The cache key must uniquely identify the state.

Bottom-up: compute dependencies first

Bottom-up begins with the base cases and visits states in an order in which every dependency of the current state is already known. Recursion disappears, but the state and recurrence remain unchanged.

Python · bottom-up
def ways(n):
    dp = [0] * (n + 1)
    dp[0] = 1

    if n >= 1:
        dp[1] = 1

    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]

    return dp[n]

What actually changes

Both implementations below compute the same sequence of values. The difference is not the mathematics of the problem; it is the order in which the dependency graph is traversed.

Top-downBottom-up
Starts fromthe target statebase states
Orderchosen by recursionchosen explicitly
States evaluatedonly reached statesusually the chosen range
Call stackusednot used
Cache/tabledictionary or arrayusually array/table

The whole table may be unnecessary

This recurrence needs only dp[i−1] and dp[i−2] to compute dp[i]. If earlier values are not needed later for reconstruction, an array of length n+1 stores more than necessary. Two variables are enough.

Python · O(1) extra space
def ways(n):
    if n <= 1:
        return 1

    two_back = 1
    one_back = 1

    for _ in range(2, n + 1):
        current = one_back + two_back
        two_back = one_back
        one_back = current

    return one_back

This is not a new recurrence or a new algorithmic principle. We have only identified which part of the computed table can still affect future states.

Which version should you write first?

In practice, top-down is often the easier first draft: the recurrence translates almost directly into a recursive function. Bottom-up requires a valid evaluation order up front, but avoids the recursion stack and is often easier to compress in memory.

Top-down

Useful when the recurrence is naturally recursive or only a small part of the state space is reachable.

Bottom-up

Useful when dependency order is simple, recursion would be deep, or memory can be compressed to a few recent layers.
