Введение в динамическое программирование

Динамическое программирование начинается не с таблицы. Оно начинается с вопроса: какие подзадачи мы решаем снова и снова?

Начнём с обычной рекурсии

Рассмотрим числа Фибоначчи. Определение почти дословно превращается в рекурсивную функцию: чтобы найти F(n), нужно найти F(n−1) и F(n−2). Код короткий и правильный. Проблема в том, сколько раз он выполняет одну и ту же работу.

Python
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

Вызов fib(5) запускает fib(4) и fib(3). Но внутри fib(4) снова появляется fib(3). Затем fib(2) вычисляется ещё несколько раз. Чем больше n, тем сильнее разрастается повторение.

Где теряется время

Ключевой признак DP — небольшое множество различных подзадач, которые обычная рекурсия посещает многократно.

Сохранить каждый ответ один раз

Вместо того чтобы снова вычислять уже известное F(k), можно сохранить результат первого вычисления. Тогда каждое k от 0 до n обрабатывается один раз. Дерево повторных вызовов превращается в последовательность сохранённых значений.

F(n) = F(n − 1) + F(n − 2)

Это и есть рекуррентный переход. Он говорит, из каких меньших состояний получается текущее состояние.

Состояние и переход

Состояние — это минимальная информация, которая однозначно задаёт подзадачу. В Fibonacci достаточно одного числа n, поэтому состояние можно обозначить dp[n]. В задаче на сетке состояние может быть парой (row, col). В рюкзаке часто нужны и номер рассматриваемого предмета, и оставшаяся вместимость.

Состояние

Какую именно меньшую задачу означает dp[i], dp[i][j] или другое выражение?

Переход

Как ответ для этого состояния выражается через уже определённые меньшие состояния?

Если смысл состояния сформулирован расплывчато, формула обычно тоже получается случайной. Поэтому в следующих главах мы сначала будем писать словами, что означает состояние, и только потом — код.

Как строить DP-решение

1

Определить подзадачу: что именно должен хранить один элемент dp?

2

Выбрать состояние: какая информация нужна, чтобы отличить одну подзадачу от другой?

3

Записать переход: какие меньшие состояния могут привести к текущему?

4

Задать базовые случаи и порядок вычисления.

5

Если нужен не только оптимум, сохранить достаточно информации, чтобы восстановить сделанные выборы.

Этот порядок важнее конкретного синтаксиса. Мемоизация и табуляция — два способа вычислить одну и ту же систему состояний и переходов.

Когда искать динамическое программирование

ПризнакЧто искать
Повторяющиеся подзадачиОдинаковые параметры рекурсивного вызова возникают снова.
Решение строится из меньшихОтвет для состояния можно выразить через несколько более простых состояний.
Последовательность решенийНа каждом шаге есть небольшой набор вариантов: взять/не взять, прийти сверху/слева, сопоставить/пропустить.
Нужно оптимизировать или посчитатьМинимум, максимум, число способов, достижимость или лучшая стоимость.

Ни один признак сам по себе не доказывает, что задача требует DP. Но вместе они подсказывают, что стоит попытаться определить состояние и рекуррентный переход.
