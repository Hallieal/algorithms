Knapsack and Subset DP

In this family of problems, a state answers two questions: which items are available and how much resource remains. Once that meaning is fixed, the take/skip recurrence follows almost automatically.

0/1 Knapsack

There are n items. Item i has weight weights[i] and value values[i]. A knapsack can carry total weight at most W, and each item may be chosen at most once. The goal is to maximize total value.

Define the subproblem first

Let dp[i][w] be the maximum value obtainable using only the first i items with capacity w. Both coordinates matter: one limits the available items, while the other limits the available weight.

dp[i][w] = maximum value from the first i items with capacity w.

The zero row is all zeros: with no items, no positive value can be obtained. The zero-capacity column is also zero: no positive-weight item can fit.

The last item: take it or skip it

For item i there are two cases. If we skip it, the answer comes from the previous row. If we take it, we add its value to the best answer using previous items and the remaining capacity. Both branches read row i−1 — this is exactly what enforces “each item at most once.”

if weight[i] ≤ w:
dp[i][w] = max(dp[i−1][w], value[i] + dp[i−1][w−weight[i]])
if the item does not fit:
dp[i][w] = dp[i−1][w]
Python · 2D table
def knapsack(weights, values, capacity):
    n = len(weights)
    dp = [[0] * (capacity + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        weight = weights[i - 1]
        value = values[i - 1]

        for w in range(capacity + 1):
            dp[i][w] = dp[i - 1][w]

            if weight <= w:
                dp[i][w] = max(
                    dp[i][w],
                    value + dp[i - 1][w - weight]
                )

    return dp[n][capacity]

Why capacity must run right to left

The two-dimensional table can be compressed to one array over capacity. But now loop direction becomes part of the algorithm's correctness. When capacities are processed right to left, dp[w − weight] still belongs to the state before the current item was processed. Left-to-right iteration could read a value that already contains the current item, allowing that item to be used again.

Python · O(W) space
def knapsack(weights, values, capacity):
    dp = [0] * (capacity + 1)

    for weight, value in zip(weights, values):
        for w in range(capacity, weight - 1, -1):
            dp[w] = max(
                dp[w],
                value + dp[w - weight]
            )

    return dp[capacity]

If capacities are processed left to right, the model changes: the current item can be reused. That corresponds to unbounded knapsack, not 0/1 knapsack.

Subset Sum uses the same structure

If item values do not matter and the question is only whether some subset sums to target, the numeric optimum becomes a Boolean state. dp[s] means: can sum s be formed from the items processed so far?

dp[s] = dp[s] OR dp[s − x]
Python · subset sum
def subset_sum(numbers, target):
    dp = [False] * (target + 1)
    dp[0] = True

    for x in numbers:
        for s in range(target, x - 1, -1):
            dp[s] = dp[s] or dp[s - x]

    return dp[target]

The initial dp[0] = True represents the empty subset. Every other sum starts unreachable. Right-to-left iteration is again necessary because each x may be used only once.

Why O(nW) is not polynomial in the input length

The standard knapsack algorithm takes O(nW) time. This can be practical when W is moderate, but W is a numeric value, not the length of its encoding. In binary, W itself occupies only O(log W) bits. Thus O(nW) is called pseudo-polynomial rather than polynomial in the input length.
