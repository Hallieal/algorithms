Мемоизация и табуляция

Top-down и bottom-up не являются двумя разными идеями. Они вычисляют одни и те же состояния по одной и той же рекуррентной формуле — но в разном порядке.

Одна рекуррентная формула — два порядка вычисления

Возьмём задачу о лестнице. На каждой ступени можно сделать шаг длины 1 или 2. Обозначим через dp[i] число способов добраться ровно до ступени i. Последний шаг на i пришёл либо с i−1, либо с i−2, поэтому

dp[i] = dp[i − 1] + dp[i − 2]

Смысл dp[i] не меняется от реализации. Меняется только вопрос: когда именно мы вычисляем это значение?

Top-down: сохранить результат при первом посещении

Top-down начинает с исходного вопроса — например, ways(6). Функция рекурсивно запрашивает меньшие состояния. Перед вычислением она проверяет кэш; после вычисления сохраняет ответ. Поэтому каждое состояние полностью решается не более одного раза.

Python · top-down
def ways(n, memo):
    if n <= 1:
        return 1

    if n in memo:
        return memo[n]

    memo[n] = ways(n - 1, memo) + ways(n - 2, memo)
    return memo[n]

Мемоизация = рекурсия + кэш результатов. Ключ кэша должен однозначно определять состояние.

Bottom-up: вычислить зависимости заранее

Bottom-up начинает с базовых случаев и идёт в таком порядке, чтобы все зависимости текущего состояния уже были известны. Рекурсия исчезает, но состояние и переход остаются прежними.

Python · bottom-up
def ways(n):
    dp = [0] * (n + 1)
    dp[0] = 1

    if n >= 1:
        dp[1] = 1

    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]

    return dp[n]

Что действительно различается

Обе реализации ниже вычисляют одну и ту же последовательность значений. Разница не в математике задачи, а в порядке обхода графа зависимостей.

Таблица иногда не нужна целиком

Для вычисления dp[i] в этой задаче нужны только dp[i−1] и dp[i−2]. Если сами предыдущие ответы потом не понадобятся для восстановления решения, массив длины n+1 избыточен. Достаточно двух переменных.

Python · O(1) extra space
def ways(n):
    if n <= 1:
        return 1

    two_back = 1
    one_back = 1

    for _ in range(2, n + 1):
        current = one_back + two_back
        two_back = one_back
        one_back = current

    return one_back

Это не новая рекуррентная формула и не новый алгоритмический принцип. Мы лишь заметили, какая часть уже вычисленной таблицы ещё может повлиять на будущее.

Какой вариант писать сначала

На практике top-down часто удобнее как первый черновик: рекуррентный переход почти напрямую превращается в функцию. Bottom-up требует заранее понять корректный порядок вычисления, зато не использует стек рекурсии и часто проще оптимизируется по памяти.

Top-down

Хороший выбор, когда переход естественно записывается рекурсивно или достижима лишь небольшая часть пространства состояний.

Bottom-up

Хороший выбор, когда порядок зависимостей прост, глубина рекурсии велика или память можно сжать до нескольких последних слоёв.
