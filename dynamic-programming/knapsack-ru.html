Knapsack и subset DP

В задачах этого семейства состояние отвечает на два вопроса: какие предметы уже разрешено использовать и какой ресурс ещё доступен. Из этого определения почти автоматически получается переход take/skip.

0/1 Knapsack

Есть n предметов. У предмета i вес weights[i] и ценность values[i]. Рюкзак выдерживает вес не больше W, а каждый предмет можно взять не более одного раза. Требуется максимизировать суммарную ценность.

Сначала определить подзадачу

Пусть dp[i][w] — максимальная ценность, которую можно получить, используя только первые i предметов при вместимости w. Здесь оба параметра существенны: один ограничивает доступные предметы, второй — доступный вес.

dp[i][w] = максимальная ценность из первых i предметов при вместимости w.

Нулевая строка состоит из нулей: без предметов нельзя получить положительную ценность. Нулевой столбец тоже равен нулю: при нулевой вместимости ничего положительного веса положить нельзя.

Последний предмет: взять или пропустить

Для i-го предмета есть два случая. Если мы его не берём, остаётся ответ из предыдущей строки. Если берём, получаем его ценность плюс лучший ответ для предыдущих предметов и уменьшенной вместимости. Обе ветви обращаются к строке i−1 — именно это кодирует правило «каждый предмет не более одного раза».

если weight[i] ≤ w:
dp[i][w] = max(dp[i−1][w], value[i] + dp[i−1][w−weight[i]])
если предмет не помещается:
dp[i][w] = dp[i−1][w]
Python · 2D table
def knapsack(weights, values, capacity):
    n = len(weights)
    dp = [[0] * (capacity + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        weight = weights[i - 1]
        value = values[i - 1]

        for w in range(capacity + 1):
            dp[i][w] = dp[i - 1][w]

            if weight <= w:
                dp[i][w] = max(
                    dp[i][w],
                    value + dp[i - 1][w - weight]
                )

    return dp[n][capacity]

Почему capacity нужно обходить справа налево

Двумерную таблицу можно сжать до одного массива по capacity. Но тогда направление цикла становится частью корректности алгоритма. При проходе справа налево dp[w − weight] всё ещё относится к состоянию до обработки текущего предмета. При проходе слева направо оно могло бы уже содержать текущий предмет, и тот же предмет использовался бы повторно.

Python · O(W) space
def knapsack(weights, values, capacity):
    dp = [0] * (capacity + 1)

    for weight, value in zip(weights, values):
        for w in range(capacity, weight - 1, -1):
            dp[w] = max(
                dp[w],
                value + dp[w - weight]
            )

    return dp[capacity]

Если пройти слева направо, получится уже другая модель: текущий предмет можно будет использовать несколько раз. Это соответствует unbounded knapsack, а не 0/1 knapsack.

Subset Sum — та же структура

Если ценности предметов не важны и нужно лишь узнать, существует ли подмножество с суммой target, числовой максимум превращается в Boolean-состояние. dp[s] означает: можно ли получить сумму s из уже обработанных элементов.

dp[s] = dp[s] OR dp[s − x]
Python · subset sum
def subset_sum(numbers, target):
    dp = [False] * (target + 1)
    dp[0] = True

    for x in numbers:
        for s in range(target, x - 1, -1):
            dp[s] = dp[s] or dp[s - x]

    return dp[target]

Начальное dp[0] = True выражает пустое подмножество. Остальные суммы изначально недостижимы. Обход справа налево снова нужен потому, что каждый x разрешено использовать только один раз.

Почему O(nW) не считается полиномиальным по размеру входа

Время стандартного алгоритма knapsack равно O(nW). Это быстро, когда W умеренно, но W — числовое значение, а не длина его записи. В двоичном представлении число W занимает только O(log W) бит. Поэтому O(nW) называют pseudo-polynomial, а не polynomial по размеру входа.

АлгоритмВремяПамять после сжатия
0/1 KnapsackO(nW)O(W)
Subset SumO(n · target)O(target)

Это также хороший пример того, почему при анализе алгоритма нужно различать величину числа и количество бит, которыми это число записано.
