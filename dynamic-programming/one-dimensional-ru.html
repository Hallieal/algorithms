Одномерное DP

Одномерное состояние часто возникает, когда задачу можно решать по префиксам: зная ответ для предыдущих позиций, понять, что меняется при добавлении следующей.

Состояния вдоль линии

Пусть в ряду домов лежат суммы [4, 7, 2, 9, 5]. Можно выбрать любые дома, но нельзя выбирать два соседних. Жадное правило вроде «сначала взять самый дорогой дом» ненадёжно: выбор одной позиции запрещает соседние и меняет дальнейшие возможности.

Определим dp[i] как максимальную сумму, которую можно получить из домов с 0-го по i-й. После этого для последнего дома остаются ровно два варианта.

Взять или пропустить

Пропустить i

Ничего нового не добавляется. Ответ остаётся dp[i − 1].

Взять i

Дом i − 1 брать нельзя, поэтому к houses[i] добавляется лучший ответ для i − 2.

dp[i] = max(dp[i − 1], houses[i] + dp[i − 2])
Python
def max_non_adjacent(houses):
    if not houses:
        return 0

    two_back = 0
    one_back = houses[0]

    for money in houses[1:]:
        current = max(one_back, money + two_back)
        two_back = one_back
        one_back = current

    return one_back

Состояний n, переход для каждого состояния занимает O(1), а для следующего шага нужны только два предыдущих значения. Поэтому время — O(n), дополнительная память — O(1).

Другой одномерный переход: минимум монет

Теперь пусть dp[x] означает минимальное число монет, которыми можно набрать сумму x. Если последняя монета имеет номинал c, то всё до неё должно составлять x − c. В отличие от предыдущей задачи, возможных предшественников здесь несколько — по одному для каждого допустимого номинала.

dp[x] = 1 + min dp[x − c]   для всех c ≤ x

Базовый случай: dp[0] = 0. Сумму, которую пока нельзя набрать, удобно считать равной бесконечности — тогда она не сможет дать ложный минимум.

Python
def min_coins(coins, target):
    dp = [float("inf")] * (target + 1)
    dp[0] = 0

    for amount in range(1, target + 1):
        for coin in coins:
            if coin <= amount:
                dp[amount] = min(
                    dp[amount],
                    1 + dp[amount - coin]
                )

    return -1 if dp[target] == float("inf") else dp[target]

Сначала посчитать состояния, затем работу на состояние

В задаче с домами есть n состояний и O(1) работы на каждое: итог O(n). В задаче о монетах есть target + 1 состояний, а каждое перебирает k номиналов. Поэтому время равно O(target · k), память — O(target).

Удобная оценка сложности DP: число достижимых состояний × работа внутри одного состояния. После мемоизации это обычно проще, чем анализировать исходное дерево рекурсии.

Общая схема одномерного DP

Главное не то, что входные данные записаны массивом. Главное, что для однозначного описания подзадачи хватает одного параметра. Это может быть индекс, сумма, время, длина префикса или другая скалярная величина.

1

Точно сформулировать смысл dp[i].

2

Перечислить все допустимые способы, которыми может заканчиваться решение для i.

3

Для каждого варианта указать предыдущее состояние.

4

Объединить варианты через max, min, сумму или логическую операцию.

5

Посмотреть, насколько далеко назад обращается переход, и только после этого решать, нужно ли хранить всю таблицу.
