One-Dimensional DP

A one-dimensional state often appears when the problem can be solved prefix by prefix: after solving positions 0 through i−1, decide what changes when position i is added.

States along a line

Suppose a row of houses contains the amounts [4, 7, 2, 9, 5]. You may take money from any houses, but never from two adjacent houses. A greedy rule such as “take the largest remaining house” is unreliable: choosing one position changes which neighboring positions remain available.

Instead, define dp[i] as the maximum amount obtainable from houses 0 through i. Once this meaning is fixed, the last decision has only two possibilities.

Take or skip

Skip house i

Nothing new is added. The best value is exactly dp[i − 1].

Take house i

House i − 1 is forbidden, so add houses[i] to the best value ending at i − 2.

dp[i] = max(dp[i − 1], houses[i] + dp[i − 2])
Python
def max_non_adjacent(houses):
    if not houses:
        return 0

    two_back = 0
    one_back = houses[0]

    for money in houses[1:]:
        current = max(one_back, money + two_back)
        two_back = one_back
        one_back = current

    return one_back

The state space contains n positions, each transition does constant work, and only the previous two values are needed. The result is O(n) time and O(1) extra space.

A different one-dimensional transition: minimum coins

Now let dp[x] mean the minimum number of coins needed to make amount x. If the last coin has value c, everything before it must form x − c. Unlike the previous problem, there may be many possible predecessors, one for every usable coin.

dp[x] = 1 + min dp[x − c]   for all c ≤ x

Set dp[0] = 0. An amount that cannot yet be formed is treated as infinity, so it cannot win the minimum.

Python
def min_coins(coins, target):
    dp = [float("inf")] * (target + 1)
    dp[0] = 0

    for amount in range(1, target + 1):
        for coin in coins:
            if coin <= amount:
                dp[amount] = min(
                    dp[amount],
                    1 + dp[amount - coin]
                )

    return -1 if dp[target] == float("inf") else dp[target]

Count states, then count work per state

For the house problem there are n states and O(1) work per state, giving O(n). For coin change there are target + 1 states and each tries every coin. With k coin denominations, the running time is O(target · k) and the table uses O(target) space.

A useful DP complexity rule is: number of reachable states × work performed by one state. This is often clearer than trying to analyze the recursion tree after memoization.

The one-dimensional pattern

The important feature is not that the input itself is an array. It is that one parameter is enough to identify a subproblem. That parameter may be an index, an amount, a time, a prefix length, or another scalar quantity.

1

Give dp[i] a precise meaning.

2

List every legal way the solution for state i can end.

3

Translate each ending into a predecessor state.

4

Combine the candidates with max, min, sum, or a Boolean operation.

5

Check how far back the recurrence looks before deciding how much of the table must be stored.
