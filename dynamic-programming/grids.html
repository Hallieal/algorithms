Grid and Path DP

When a position is described by a row and a column, a cell dp[r][c] becomes a natural state. The geometry of the grid reveals both the dependencies and a valid evaluation order.

The state is a position in the grid

A robot starts in the top-left corner of a rectangular grid and may move only right or down. We want the number of paths to the bottom-right corner. Let dp[r][c] be the number of ways to reach cell (r, c).

How many paths reach a cell?

Every interior cell can be entered only from above or from the left. Those two sets of paths have different final moves, so their counts add.

dp[r][c] = dp[r − 1][c] + dp[r][c − 1]

The table is a dependency graph

Every cell in the first row and first column has exactly one path to it: move only right or only down. After setting that boundary, fill the table left to right and top to bottom. By the time dp[r][c] is evaluated, both dependencies are already available.

Python
def count_paths(rows, cols):
    dp = [[1] * cols for _ in range(rows)]

    for r in range(1, rows):
        for c in range(1, cols):
            dp[r][c] = dp[r - 1][c] + dp[r][c - 1]

    return dp[rows - 1][cols - 1]

In a 4 × 4 table, 20 paths reach the bottom-right corner. Every interior entry is literally the sum of the entry above and the entry to its left.

Same geometry, different objective

Now suppose every cell has a visiting cost and we want a path of minimum total cost. The state coordinates and evaluation order stay the same. What changes is how predecessors are combined: instead of adding path counts, choose the cheaper predecessor.

dp[r][c] = cost[r][c] + min(dp[r − 1][c], dp[r][c − 1])
Python · minimum path cost
def min_path_cost(grid):
    rows, cols = len(grid), len(grid[0])
    dp = [[0] * cols for _ in range(rows)]
    dp[0][0] = grid[0][0]

    for r in range(1, rows):
        dp[r][0] = dp[r - 1][0] + grid[r][0]

    for c in range(1, cols):
        dp[0][c] = dp[0][c - 1] + grid[0][c]

    for r in range(1, rows):
        for c in range(1, cols):
            dp[r][c] = grid[r][c] + min(
                dp[r - 1][c],
                dp[r][c - 1]
            )

    return dp[-1][-1]

The dimension of a DP is determined by the information needed to identify a subproblem, not by whether we count paths, minimize, or maximize.

Obstacles change the boundary cases

If some cells are blocked, a blocked cell has value 0 in the path-counting problem. This small change matters on the boundary: after an obstacle in the first row or first column, later cells are no longer automatically equal to 1.

The whole grid is often unnecessary

While computing row r, we need only the previous row and the part of the current row already computed. In fact, one array is enough: before dp[c] is updated it stores the value from above, while dp[c−1] already stores the new value from the left.

Python · O(cols) space
def count_paths(rows, cols):
    dp = [1] * cols

    for _ in range(1, rows):
        for c in range(1, cols):
            dp[c] = dp[c] + dp[c - 1]

    return dp[-1]

Time remains O(rows · cols), because every cell is still processed. Space falls from O(rows · cols) to O(cols). If columns outnumber rows, the same idea can be oriented along the smaller dimension.
