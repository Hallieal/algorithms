Bubble Sort

Adjacent comparisons, local swaps, inversions, and early stopping.

Main idea

Bubble Sort repeatedly compares neighboring elements. If two adjacent elements are in the wrong order, they are swapped. A full left-to-right pass moves the largest element that is still out of place to the end of the unsorted part.

Why the name Bubble Sort?

During one pass, a large value can move several positions to the right through a sequence of adjacent swaps. In this sense, large values gradually rise toward the end of the array.

Correctness

Invariant of one pass

While scanning from left to right, after the comparison ending at position j, the largest element among the positions already visited is located at position j.

3 5 8 2 7

After comparing 8 with the values before it, 8 is the largest element seen so far and has moved to the right.

Why a pass fixes one element

Invariant. After the comparison of positions j−1 and j, the largest element among the first j+1 elements is located at position j.

Initialization. After the first comparison, the larger of the first two elements is in the second position. Hence the invariant holds for the first two elements.

Maintenance. Suppose the largest element among the elements examined so far is at position j. We compare it with the next element. After swapping them if necessary, the larger of the two is at position j+1. Therefore the largest element among the first j+2 elements is now at position j+1.

Termination. At the end of the pass, every element in the unsorted part has been examined. Therefore its largest element is at the rightmost position of that part, which is its final position.

From one pass to the whole algorithm

After the first pass, the largest element is fixed at the end. After the second pass, the second-largest element is fixed immediately before it. Repeating this argument eventually fixes every position.

Implementation

The version below includes an early-stopping optimization. If a complete pass performs no swaps, the array is already sorted and the algorithm can terminate immediately.

1def bubble_sort(a):
2 n = len(a)
3 for end in range(n - 1, 0, -1):
4 swapped = False
5 for j in range(end):
6 if a[j] > a[j + 1]:
7 a[j], a[j + 1] = a[j + 1], a[j]
8 swapped = True
9 if not swapped:
10 break
11 return a

Implementation notes

3

Line 3. After each full pass, one more element at the right end is fixed, so the next pass can stop earlier.

4

Line 4. The flag records whether the current pass changed the array at all.

5–8

Lines 5–8. Every adjacent pair in the unsorted part is checked. A pair in decreasing order is swapped.

9–10

Lines 9–10. If an entire pass makes no swaps, every adjacent pair is already ordered. Therefore the whole array is sorted and the algorithm stops.

Complexity

Without early stopping

The first pass compares n − 1 adjacent pairs, the next compares n − 2, and so on.

(n − 1) + (n − 2) + ··· + 2 + 1 = n(n − 1) / 2

Therefore the standard nested-loop structure performs Θ(n2) comparisons.

With early stopping

If the array is already sorted, the first pass makes no swaps and the algorithm terminates after n − 1 comparisons. The best-case time is therefore Θ(n).

Best caseΘ(n)already sorted
Average caseΘ(n²)many adjacent comparisons
Worst caseΘ(n²)decreasing order
Extra memoryΘ(1)in-place

Bubble Sort and inversions

Bubble Sort has a particularly clean connection with inversions. An inversion is a pair of positions i < j such that the earlier value is larger than the later value.

3 7 5 2

In this array, the pair 7 and 2 is an inversion because 7 appears earlier but is larger.

What does one adjacent swap do?

Bubble Sort swaps only adjacent elements that form an inversion. Such a swap removes exactly that inversion and does not change the relative order of any other pair.

number of swaps = number of inversions in the input

This does not make Bubble Sort asymptotically fast: it still performs many comparisons. But it gives an exact interpretation of its data movement.

Compare with Insertion Sort. Insertion Sort also becomes faster on nearly sorted data, and inversions give a useful way to describe that adaptivity. Revisit Selection & Insertion Sorts →

Stability

The implementation above is stable. Two equal elements are never swapped because the condition uses a strict comparison: the swap is performed only when the left value is larger than the right value.

Exercises

1

One full pass

What is the array after one complete left-to-right pass of Bubble Sort on [5, 1, 4, 2, 8]?

The array becomes [1, 4, 2, 5, 8]. The largest value, 8, is guaranteed to be in its final position.
2

Early stopping

Why is a pass with no swaps sufficient to conclude that the entire array is sorted?

If no adjacent pair is in decreasing order, then every neighboring pair satisfies the required order. By transitivity, the entire array is sorted.
3

Number of swaps

How many swaps will Bubble Sort perform on [3, 2, 1]?

There are three inversions: (3,2), (3,1), and (2,1). Therefore Bubble Sort performs exactly 3 swaps.
4

Stability

What change to the comparison condition would make this implementation potentially unstable?

Swapping when the two values are equal would allow equal elements to reverse their relative order.
