Inversion Count

Use the merge step to count many out-of-order pairs at once instead of examining every pair separately.

MediumMerge SortPython

Problem

An inversion measures how far an array is from being sorted: it is a pair that appears in the wrong relative order.

Task

Count all out-of-order pairs

For an array a, an inversion is a pair of indices i < j such that a[i] > a[j]. Count the total number of inversions.

inversion = (i, j) with i < j and a[i] > a[j]
Example
24135
out-of-order pairs
(2, 1)(4, 1)(4, 3)
There are exactly 3 inversions. Checking all pairs would find them, but costs quadratic time.

Core idea

Merge Sort already compares two sorted halves. Sortedness lets one comparison certify an entire block of inversions.

The counting moment

One right value can beat many left values

Suppose the remaining left half is [4, 7] and the next right value is 3. Since the left half is sorted and 3 < 4, the value 3 is also smaller than every later left value. It therefore creates two cross inversions immediately.

47
remaining left values
> 3
3
add 2 inversions at once
L ≤ R

Take the left value. It creates no new cross inversion with the remaining right half.

R < L

Take the right value and add the number of left values that remain.

recurse

Internal inversions are counted inside each half; the merge counts only cross inversions.

Why does sortedness matter?

If right[j] < left[i], then sorted order gives left[i] ≤ left[i+1] ≤ ···. So right[j] is smaller than every remaining left value. Without sorted halves, one comparison would tell us nothing about the rest.

Algorithm

1

Split the array

Divide exactly as in Merge Sort until subarrays have size at most one.

2

Count inside each half

Recursive calls return the number of inversions entirely on the left and entirely on the right.

3

Merge and count

When a right value is chosen before left[i], add all remaining left values to the counter.

4

Add the three parts

Total = left inversions + right inversions + cross inversions.

I

Merge invariant

The output prefix is sorted, and the counter already includes every cross inversion involving each right-half element that has been copied into that prefix.

Correctness & complexity

✓

Every inversion belongs to exactly one place

An inversion is either entirely in the left half, entirely in the right half, or crosses the midpoint. The recursive calls and merge step handle these three disjoint cases.

1

Internal inversions

By recursion, all inversions whose two positions lie in the same half are counted correctly.

2

Cross inversions

If right[j] < left[i], then right[j] forms an inversion with every remaining left value. We add exactly that number.

3

No double counting

Each right value is counted against the remaining left suffix exactly when it is moved ahead of that suffix, so every cross pair is counted once.

TimeO(n log n)

The recurrence is the same as Merge Sort.

Extra spaceO(n)

A temporary array supports the merge operations.

Naive methodO(n²)

Checking every pair ignores the structure exposed by sorting.

Implementation

The only change from ordinary Merge Sort is the line that adds mid - i whenever a right-half value jumps ahead.

Python
def count_inversions(values):
    a = list(values)
    temp = [0] * len(a)

    def sort_and_count(lo, hi):
        if hi - lo <= 1:
            return 0

        mid = (lo + hi) // 2
        count = sort_and_count(lo, mid)
        count += sort_and_count(mid, hi)

        i, j, out = lo, mid, lo

        while i < mid and j < hi:
            if a[i] <= a[j]:
                temp[out] = a[i]
                i += 1
            else:
                temp[out] = a[j]
                j += 1
                count += mid - i
            out += 1

        while i < mid:
            temp[out] = a[i]
            i += 1
            out += 1

        while j < hi:
            temp[out] = a[j]
            j += 1
            out += 1

        for p in range(lo, hi):
            a[p] = temp[p]

        return count

    return sort_and_count(0, len(a))


print(count_inversions([2, 4, 1, 3, 5]))
# 3
Reading the code

The crucial line is the count update

count += mid - i

Indices i, i+1, ..., mid-1 are all larger than the chosen right value, so all of them form inversions with it.

a[i] <= a[j]

Equal values are not inversions. Taking the left value on ties correctly adds nothing.

Temporary array

After each merge, the current range is sorted, which is exactly what the next recursion level needs.
