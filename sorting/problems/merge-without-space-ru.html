Слияние без дополнительной памяти

Сначала отделяем значения, которые должны остаться слева и справа, затем восстанавливаем порядок без merge-буфера.

HardIn-place mergePython

Условие

Обычное слияние работает за линейное время потому, что записывает результат в третий массив. Здесь такой буфер запрещён.

Задача

Слить два массива, сохранив их размеры

Массивы a и b изначально отсортированы. Нужно переставить только уже имеющиеся элементы так, чтобы a содержал наименьшие len(a) значений, b — остальные, а оба массива снова были отсортированы. Дополнительная память должна быть O(1).

max(a) ≤ min(b), и каждый массив отсортирован
Пример
a
159101520
b
23813
после слияния ↓
a
123589
b
10131520

Главная идея

Не будем одновременно поддерживать и правильный состав массивов, и внутреннюю сортировку. Сначала решим более простую задачу: отправим нужные значения на правильную сторону границы.

Разделение через границу

Сравниваем крупные кандидаты из a с маленькими кандидатами из b

Пусть r = min(n, m). Идём по последним r позициям a справа налево и по первым r позициям b слева направо. В каждой паре меньшее значение оставляем на стороне a, большее — на стороне b.

суффикс a · справа налево
2015109
↔
префикс b · слева направо
23813
20 ↔ 2

2 должен уйти в левый массив, 20 — в правый.

15 ↔ 3

Снова оставляем меньший элемент в a.

9 ↔ 13

Эта пара уже разделена правильно, обмен не нужен.

Важно: после этих обменов массивы обычно временно перестают быть отсортированными внутри. Но мы уже получили главное свойство: любое значение в a не превосходит любое значение в b. После этого стороны можно сортировать независимо.

Алгоритм

1

Сопоставить граничные элементы

Для t = 0, …, r−1 сравниваем a[n−1−t] и b[t].

2

Меньшее отправить влево

Если элемент из a больше, меняем пару местами.

3

Отсортировать a in-place

Используем heapsort, который не требует дополнительного массива.

4

Отсортировать b in-place

После этого правильная граница между массивами автоматически даёт глобально отсортированное слияние.

I

Что гарантирует первая фаза

После всех r compare-exchange операций множество значений в a состоит ровно из наименьших n элементов объединённого входа, а в b остаются остальные m.

Корректность и сложность

Почему первая фаза действительно разделяет значения

Сравниваемый суффикс a, если читать его справа налево, невозрастает. Сравниваемый префикс b, если читать его слева направо, неубывает. Поэтому разность элементов в соответствующих парах может сменить знак не более одного раза. До этой точки меньшими оказываются элементы из b, после неё — элементы из a. Значит, все минимумы, отправленные влево, лежат не выше границы пересечения, а все максимумы, отправленные вправо, — не ниже неё. Несопоставленный префикс a ещё меньше, а несопоставленный суффикс b ещё больше. Следовательно, после первой фазы любой элемент a не превосходит любого элемента b.

✓

Теперь достаточно отсортировать стороны независимо

После правильного разделения никакому элементу уже не нужно переходить через границу между массивами.

1

Элементы не теряются

Первая фаза использует только обмены, поэтому объединённое мультимножество значений не меняется.

2

Граница правильна

После compare-exchange фазы выполняется max(a) ≤ min(b), хотя порядок внутри каждого массива ещё может быть нарушен.

3

Heapsort завершает работу

Сортировка каждой стороны не меняет её состав, поэтому после двух heapsort весь массив a + b отсортирован.

РазделениеO(min(n,m))

По одному сравнению на каждую граничную пару.

СортировкаO(n log n + m log m)

Каждый массив сортируется heapsort.

ПамятьO(1)

Используются только индексы и временные переменные для обменов.

Реализация

Здесь намеренно реализован собственный heapsort: встроенный list.sort() великолепен на практике, но не удовлетворяет строгому требованию O(1) дополнительной памяти.

Python
def heap_sort(a):
    n = len(a)

    def sift_down(root, size):
        while True:
            child = 2 * root + 1
            if child >= size:
                return

            if (child + 1 < size and
                    a[child + 1] > a[child]):
                child += 1

            if a[root] >= a[child]:
                return

            a[root], a[child] = a[child], a[root]
            root = child

    for root in range(n // 2 - 1, -1, -1):
        sift_down(root, n)

    for end in range(n - 1, 0, -1):
        a[0], a[end] = a[end], a[0]
        sift_down(0, end)


def merge_without_extra_space(a, b):
    r = min(len(a), len(b))

    for t in range(r):
        i = len(a) - 1 - t
        j = t
        if a[i] > b[j]:
            a[i], b[j] = b[j], a[i]

    heap_sort(a)
    heap_sort(b)
    return a, b


a = [1, 5, 9, 10, 15, 20]
b = [2, 3, 8, 13]
print(merge_without_extra_space(a, b))
# ([1, 2, 3, 5, 8, 9], [10, 13, 15, 20])
Как читать код

Две независимые обязанности

Граничный compare-exchange

Оставляет меньший элемент пары в a, а больший — в b, формируя правильный состав сторон.

heap_sort(a)

Восстанавливает порядок слева без дополнительного массива.

heap_sort(b)

Делает то же справа; уже правильная граница превращает две сортировки в полное слияние.
