K наименьших элементов

Хранить только те значения, которые ещё могут попасть в ответ, вместо сортировки всего массива.

MediumКучаPython

Условие

Полная сортировка даёт гораздо больше информации, чем нужно. Нас интересуют только первые k элементов итогового порядка.

Задача

Вернуть k наименьших значений

Дан массив из n чисел и целое k. Верните k наименьших значений в возрастающем порядке. Повторяющиеся значения считаются отдельно.

ответ = первые k элементов полностью отсортированного массива
Пример · k = 3
710432015
оставляем только три лучших ↓
347
Ответ — [3, 4, 7]. Взаимный порядок 10, 15 и 20 вообще не требуется вычислять.

Главная идея

Поддерживаем ровно k кандидатов. Единственный кандидат, которого когда-либо понадобится удалить, — самый большой из них, поэтому он должен быть доступен мгновенно.

Порог

Максимальный кандидат — текущая граница

Пусть текущие кандидаты — {3, 7, 10}. Их максимум 10 — самый слабый элемент набора. Любое новое значение не меньше 10 можно игнорировать; любое значение меньше 10 должно заменить его.

3710
текущие кандидаты · порог = 10
+ 4 →
347
10 удалён; новый порог = 7
x ≥ M

Игнорируем x. Уже есть k обработанных значений, не превосходящих его.

x < M

Заменяем текущий максимум M на x: набор кандидатов становится лучше.

max-heap

Max-heap хранит порог в корне и обновляет его за O(log k).

Почему не min-heap?

Min-heap показывает наименьший кандидат, а его мы как раз хотим сохранить. Нам нужен быстрый доступ к крупнейшему кандидату, потому что именно он может быть вытеснен. В Python реализована min-heap, поэтому мы храним отрицания чисел и тем самым имитируем max-heap.

Алгоритм

1

Берём первые k значений

Строим из них max-heap текущих кандидатов.

2

Смотрим на порог

Корень кучи — крупнейший кандидат M.

3

Оставляем или отбрасываем

Если x < M, заменяем M на x; иначе игнорируем x.

4

Сортируем только k значений

В конце сортируем содержимое кучи, чтобы вернуть ответ в возрастающем порядке.

I

Инвариант цикла

После обработки любого префикса длины не меньше k куча содержит в точности k наименьших значений этого префикса с учётом повторений.

Корректность и сложность

✓

Почему одного порога достаточно

Максимум среди кандидатов отделяет значения, которые ещё могут попасть в ответ, от значений, которые уже точно не попадут.

1

Инициализация

После первых k элементов куча содержит все обработанные значения, а значит — ровно k наименьших.

2

Если x ≥ M

В куче уже есть k значений, не превосходящих M ≤ x. Следовательно, x не может входить в k наименьших обработанных значений.

3

Если x < M

Новое значение должно войти в набор кандидатов, а старый максимум становится лишним. Его замена восстанавливает инвариант.

ПросмотрO(n log k)

Каждый следующий элемент вызывает не более одной операции замены в куче.

Сортировка ответаO(k log k)

Сортируются только выбранные k значений.

Доп. памятьO(k)

Куча хранит ровно k кандидатов.

Реализация

Отрицание значений превращает стандартную min-heap Python в нужную нам max-heap.

Python
import heapq


def k_smallest(a, k):
    if not 0 <= k <= len(a):
        raise ValueError("k must satisfy 0 <= k <= len(a)")
    if k == 0:
        return []

    heap = [-x for x in a[:k]]
    heapq.heapify(heap)

    for x in a[k:]:
        largest = -heap[0]
        if x < largest:
            heapq.heapreplace(heap, -x)

    return sorted(-x for x in heap)


print(k_smallest([7, 10, 4, 3, 20, 15], 3))
# [3, 4, 7]
Как читать код

Куча буквально хранит инвариант

-heap[0]

Из-за отрицаний минимальное хранимое число соответствует максимальному настоящему кандидату.

heapreplace

Удаляет текущий порог и вставляет улучшившее набор значение одной операцией за O(log k).

Финальный sorted

Куча хранит правильное множество значений, но не выдаёт их в отсортированном порядке, поэтому сортируем только эти k чисел.
