Top K Frequent Elements

Turn raw occurrences into sortable records, then make the ranking rule explicit.

HardFrequency rankingPython

Problem

The array itself is not what we want to order. The answer depends on how often each distinct value appears.

Task

Return the k highest-priority values

Given an integer array and an integer k, return the k distinct values with highest frequency. If two values have the same frequency, the larger value ranks first.

priority(x) = (frequency(x), x), both in descending order
Example · k = 2
31445261
count first, rank second ↓
4
2 times
1
2 times
6
1 time
4 and 1 tie on frequency, so 4 comes first because it is larger. The answer is [4, 1].

Core idea

Compress the input into one record per distinct value. Once frequency is stored explicitly, the problem becomes an ordinary sorting problem on a two-component key.

Change the representation

Sort records, not occurrences

For each distinct value x, create the record (x, frequency[x]). The required global order is: larger frequency first; if frequencies tie, larger value first.

4 → (2, 4)frequency 2, value 4
1 → (2, 1)same frequency, smaller value
6 → (1, 6)lower frequency
1st key

Frequency is primary: more occurrences always mean higher rank.

2nd key

The value breaks ties: among equal frequencies, larger values come first.

Python

(-freq[x], -x) converts both descending rules into the default ascending tuple order.

Why this is a sorting problem. Counting alone gives the data needed for the answer, but not its order. The crucial modeling step is to identify the exact comparison key before sorting.

Algorithm

1

Count

Build a frequency table in one pass through the array.

2

Keep distinct values

There are only m records to rank, where m is the number of distinct values.

3

Sort by the rule

Sort with key (-frequency, -value).

4

Take the first k

The first k records are exactly the requested values.

I

Ordering invariant

In the ranked list, every earlier value either has larger frequency than a later value, or has the same frequency and a larger numeric value.

Correctness & complexity

✓

The sort key is the specification

There is no approximation: the comparison used by the algorithm is exactly the priority rule stated in the problem.

1

Counting preserves all relevant information

Each distinct value appears once in the frequency table together with its exact number of occurrences.

2

Sorting produces the required total order

Lexicographic order on (-frequency, -value) places higher frequencies first and resolves every tie by larger value.

3

The answer is a prefix

Therefore no value after position k can outrank any value inside the first k positions.

CountingO(n)

One pass over all observations.

RankingO(m log m)

Only the m distinct values are sorted.

Extra spaceO(m)

The frequency table stores one entry per distinct value.

If k is tiny. A min-heap of size k can reduce the ranking stage to O(m log k). Here we deliberately use sorting because the full ordering rule is the main idea of this chapter.

Implementation

The code is short because all of the reasoning is concentrated in the sort key.

Python
from collections import Counter


def top_k_frequent(a, k):
    freq = Counter(a)

    if not 0 <= k <= len(freq):
        raise ValueError(
            "k must not exceed the number of distinct values"
        )

    ranked = sorted(
        freq,
        key=lambda x: (-freq[x], -x),
    )
    return ranked[:k]


print(top_k_frequent(
    [3, 1, 4, 4, 5, 2, 6, 1], 2
))
# [4, 1]
Reading the code

The key contains the whole problem

Counter(a)

Compresses repeated observations into one exact frequency per value.

-freq[x]

Higher frequency must come first, so we negate it for ascending sort.

-x

Among ties, the larger value must come first, so the second component is negated too.
