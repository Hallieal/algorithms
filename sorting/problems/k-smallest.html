K Smallest Elements

Keep only the values that still have a chance to belong to the answer instead of sorting everything.

MediumHeapPython

Problem

Full sorting reveals much more information than we need. Here the goal is only to identify the smallest k values.

Task

Return the k smallest values

Given an array of n numbers and an integer k, return the k smallest values in increasing order. Equal values count separately.

answer = the first k elements of the fully sorted array
Example · k = 3
710432015
keep only the best three ↓
347
The required output is [3, 4, 7]. Values 10, 15, and 20 never need to be ordered relative to one another.

Core idea

Maintain exactly k candidates. The only candidate we ever need to remove is the largest one, so that value should be available immediately.

The threshold view

The largest candidate is the current cutoff

Suppose the current candidates are {3, 7, 10}. Their maximum, 10, is the weakest member of the set. Any new value at least 10 can be ignored; any value below 10 must replace it.

3710
current candidates · cutoff = 10
+ 4 →
347
10 is removed; new cutoff = 7
x ≥ M

Ignore x. The current set already contains k values no larger than it.

x < M

Replace the current maximum M by x; the candidate set improves.

max-heap

A max-heap keeps the cutoff at its root and updates it in O(log k).

Why not use a min-heap?

A min-heap exposes the smallest candidate, but that is the value we most want to keep. We need fast access to the largest current candidate because that is the one that may be evicted. Python only provides a min-heap, so we store negated values to simulate a max-heap.

Algorithm

1

Take the first k values

Use them to initialize a max-heap of current candidates.

2

Read the cutoff

The heap root gives the largest candidate M.

3

Keep or discard

If x < M, replace M by x; otherwise ignore x.

4

Sort only k values

At the end, sort the heap contents to return the answer in increasing order.

I

Loop invariant

After processing any prefix of at least k elements, the heap contains exactly the k smallest values of that prefix, with multiplicities.

Correctness & complexity

✓

Why one cutoff is enough

The candidate maximum separates values that can still enter the answer from values that definitely cannot.

1

Initialization

For the first k processed values, the heap obviously contains the k smallest values of that prefix: it contains all of them.

2

If x ≥ M

The heap already contains k values no larger than M ≤ x. Therefore x cannot belong to the k smallest processed values.

3

If x < M

The new value must enter the candidate set, while the old maximum is the only candidate that becomes unnecessary. Replacing it restores the invariant.

ScanO(n log k)

Each later element causes at most one heap replacement.

Final orderingO(k log k)

Only the selected k values are sorted.

Extra spaceO(k)

The heap stores exactly k candidates.

Implementation

Negating every value turns Python's min-heap into the max-heap required by the proof.

Python
import heapq


def k_smallest(a, k):
    if not 0 <= k <= len(a):
        raise ValueError("k must satisfy 0 <= k <= len(a)")
    if k == 0:
        return []

    heap = [-x for x in a[:k]]
    heapq.heapify(heap)

    for x in a[k:]:
        largest = -heap[0]
        if x < largest:
            heapq.heapreplace(heap, -x)

    return sorted(-x for x in heap)


print(k_smallest([7, 10, 4, 3, 20, 15], 3))
# [3, 4, 7]
Reading the code

The heap stores the invariant

-heap[0]

Because values are negated, the minimum stored number corresponds to the largest real candidate.

heapreplace

Removes the current cutoff and inserts the improving value in one O(log k) operation.

Final sorted

The heap gives the correct set, not sorted output, so only those k values are ordered at the end.
