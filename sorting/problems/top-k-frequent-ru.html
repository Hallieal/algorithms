K самых частых элементов

Преобразуем сырые вхождения в записи, которые уже можно честно ранжировать.

HardЧастоты и ранжированиеPython

Условие

Сортировать исходный массив здесь бессмысленно: ответ определяется не положением элементов, а частотой каждого различного значения.

Задача

Вернуть k значений с наибольшим приоритетом

Дан целочисленный массив и число k. Нужно вернуть k различных значений с наибольшей частотой. Если частоты совпадают, выше ставится большее значение.

priority(x) = (frequency(x), x), оба компонента по убыванию
Пример · k = 2
31445261
сначала считаем, затем ранжируем ↓
4
2 раза
1
2 раза
6
1 раз
У 4 и 1 одинаковая частота, поэтому первым идёт 4 как большее значение. Ответ: [4, 1].

Главная идея

Сожмём вход до одной записи на каждое различное значение. После этого задача превращается в обычную сортировку по составному ключу.

Меняем представление

Сортируем записи, а не отдельные вхождения

Для каждого значения x создаём запись (x, frequency[x]). Нужный порядок однозначен: сначала по убыванию частоты, а при равенстве — по убыванию самого значения.

4 → (2, 4)частота 2, значение 4
1 → (2, 1)та же частота, меньшее значение
6 → (1, 6)меньшая частота
1-й ключ

Частота главнее всего: больше вхождений — выше позиция.

2-й ключ

При равных частотах более крупное число должно стоять раньше.

Python

(-freq[x], -x) переводит оба правила по убыванию в обычную сортировку по возрастанию кортежей.

Почему это задача на сортировку. Подсчёт частот создаёт нужные данные, но ещё не задаёт ответ. Главный шаг — явно сформулировать ключ сравнения, который полностью совпадает с условием.

Алгоритм

1

Посчитать частоты

За один проход строим таблицу частот.

2

Оставить различные значения

Если различных значений m, ранжировать нужно только m записей.

3

Отсортировать

Используем ключ (-frequency, -value).

4

Взять префикс

Первые k значений и есть ответ.

I

Инвариант порядка

В отсортированном списке каждое более раннее значение либо имеет большую частоту, либо при равной частоте имеет большее числовое значение.

Корректность и сложность

✓

Ключ сортировки буквально повторяет условие

Алгоритм не использует эвристику: его правило сравнения — это в точности правило приоритета из задачи.

1

Подсчёт сохраняет всю существенную информацию

Для каждого различного значения хранится точное число его появлений.

2

Сортировка создаёт нужный полный порядок

Лексикографическая сортировка по (-frequency, -value) ставит выше большую частоту и корректно разрешает все ничьи.

3

Ответ — это префикс

Ни одно значение после позиции k не может иметь больший приоритет, чем значение внутри первых k позиций.

ПодсчётO(n)

Один проход по всем элементам.

РанжированиеO(m log m)

Сортируются только m различных значений.

ПамятьO(m)

Таблица частот хранит одну запись на различное значение.

Если k очень мало. Можно хранить min-heap размера k и снизить этап ранжирования до O(m log k). Здесь оставлена сортировка, потому что именно полный порядок является основной идеей главы.

Реализация

Код короткий, потому что всё содержательное рассуждение уже выражено в ключе сортировки.

Python
from collections import Counter


def top_k_frequent(a, k):
    freq = Counter(a)

    if not 0 <= k <= len(freq):
        raise ValueError(
            "k must not exceed the number of distinct values"
        )

    ranked = sorted(
        freq,
        key=lambda x: (-freq[x], -x),
    )
    return ranked[:k]


print(top_k_frequent(
    [3, 1, 4, 4, 5, 2, 6, 1], 2
))
# [4, 1]
Как читать код

Весь смысл находится в ключе

Counter(a)

Сжимает повторяющиеся элементы до одной точной частоты на значение.

-freq[x]

Большая частота должна стоять раньше, поэтому компонент берётся со знаком минус.

-x

При равных частотах более крупное значение тоже должно стоять раньше.
