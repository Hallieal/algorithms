Two Sum in a Sorted Array

Use sorted order to replace a quadratic pair search with one monotone scan.

EasySorting practicePython

Problem

A naive search tests every pair and needs quadratic time. Sorted order gives us enough information to discard many pairs at once.

Task

Find a pair with a prescribed sum

Given a non-decreasing array a and a target value, find two distinct elements whose sum equals the target. Return their 1-based indices, or [-1, -1] if no pair exists.

a[i] + a[j] = target,   i < j
Example · target = 18
leftright
2571115
2 + 15 = 17 < 18
The sum is too small, so the left pointer must move right. Keeping 2 can never help: every other partner is ≤ 15.

Core idea

Use the smallest and largest remaining values. Their sum tells us which endpoint is impossible and can be removed from consideration permanently.

Monotonicity

One comparison eliminates an entire family of pairs

If a[left] + a[right] is too small, then a[left] is too small even with the largest available partner. If the sum is too large, then a[right] is too large even with the smallest available partner.

sum < targetdiscard left
sum = targetsolution found
sum > targetdiscard right
too small

Move left right to increase the sum.

exact

Return the current pair immediately.

too large

Move right left to decrease the sum.

Algorithm

1

Place two pointers

Start with left = 0 and right = n - 1.

2

Inspect the sum

Compute a[left] + a[right].

3

Discard one endpoint

Move the left pointer if the sum is small, otherwise move the right pointer if it is large.

4

Stop

Return when the sum matches. If the pointers meet, no valid pair remains.

I

Loop invariant

If a solution exists among the pairs not yet ruled out, at least one solution lies entirely inside the current interval [left, right].

Correctness & complexity

↔

Why moving a pointer is safe

The sorted order makes the sum monotone: increasing the left endpoint can only increase the sum, while decreasing the right endpoint can only decrease it.

1

Sum too small

If a[left] + a[right] < target, then for every j ≤ right, a[left] + a[j] ≤ a[left] + a[right] < target. So left cannot belong to a solution.

2

Sum too large

If a[left] + a[right] > target, then for every i ≥ left, a[i] + a[right] ≥ a[left] + a[right] > target. So right cannot belong to a solution.

3

Termination

Each step shrinks the interval. We either find an exact sum or eliminate all possible pairs.

TimeO(n)

Each pointer moves at most n positions.

Extra spaceO(1)

Only two indices and the current sum are stored.

Key propertySorted order

Without monotonicity, the endpoint eliminations are invalid.

Implementation

The code is a direct transcription of the three-way decision: equal, too small, or too large.

Python
def two_sum_sorted(a, target):
    left, right = 0, len(a) - 1

    while left < right:
        current = a[left] + a[right]

        if current == target:
            return [left + 1, right + 1]
        if current < target:
            left += 1
        else:
            right -= 1

    return [-1, -1]
Reading the code

The pointers never move backward

left += 1

Used only when the current smallest value is provably too small to participate in any solution.

right -= 1

Used only when the current largest value is provably too large.

1-based indices

The algorithm works internally with Python's 0-based indices and adds one only in the returned answer.
