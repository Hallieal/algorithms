Сортировка слиянием

Разделим массив, рекурсивно отсортируем меньшие части и сольём их обратно.

Разделяй и властвуй

Сортировка слиянием — первый алгоритм в этой главе, построенный по принципу «разделяй и властвуй». Вместо непосредственного выбора очередного элемента мы сводим одну большую задачу сортировки к нескольким меньшим.

1

Разделить

Разбить массив на две меньшие половины.

2

Решить рекурсивно

Отсортировать каждую половину тем же алгоритмом.

3

Объединить

Слить две отсортированные половины в один отсортированный массив.

База рекурсии

Массив из нуля или одного элемента уже отсортирован. Рекурсия останавливается, когда подмассив достигает такого размера.

Разбить легко; основная работа происходит при слиянии

Разделить массив на половины несложно. Ключевой шаг — объединить две половины после того, как каждая из них уже отсортирована. Эта операция называется слиянием.

Операция слияния

Пусть у нас уже есть две отсортированные последовательности. Чтобы слить их, сравним первые ещё не использованные элементы. Меньший из них обязан быть следующим элементом итоговой отсортированной последовательности.

Поскольку каждая входная последовательность уже отсортирована, её первый неиспользованный элемент — минимальный среди оставшихся в этой последовательности. Значит, следующим в результат должен попасть меньший из двух первых неиспользованных элементов.

Время работы слияния

Пусть левая последовательность содержит p элементов, а правая последовательность — q элементов. Тогда результат слияния содержит ровно p + q элементов.

На каждом шаге алгоритм сравнивает первые неиспользованные элементы двух последовательностей и окончательно переносит один из них в результат. Назад элементы не возвращаются. Поэтому каждый входной элемент обрабатывается ровно один раз.

p элементов + q элементов → p + q позиций в результате
Общий объём работы Θ(p + q)

Всего p + q элементов, и каждый из них ровно один раз копируется в результат.

Максимальное число сравнений p + q − 1

Сравнения продолжаются, пока обе последовательности непусты. В худшем случае одна из них опустеет только после того, как уже выбраны p + q − 1 элементов. Последний оставшийся элемент добавляется без дополнительного сравнения.

Почему слияние корректно

!

Ключевое наблюдение

Каждая входная последовательность уже отсортирована. Поэтому её первый неиспользованный элемент — минимальный среди всех оставшихся в этой последовательности.

Если текущие кандидаты — x из левой последовательности и y из правой, то минимальный элемент среди всех оставшихся в двух последовательностях равен min(x, y).

1

Инвариант

Перед каждым шагом результат содержит в точности те наименьшие элементы, которые уже были извлечены из двух входных последовательностей, причём они записаны в отсортированном порядке.

2

Инициализация

До первого шага результат пуст. Пустая последовательность отсортирована, поэтому инвариант выполняется.

3

Сохранение инварианта

Пусть x и y — первые неиспользованные элементы левой и правой последовательностей. Так как обе последовательности отсортированы, ни один более поздний элемент слева не меньше xи ни один более поздний элемент справа не меньше y.

Следовательно, меньший из x и y — минимальный среди всех элементов, ещё оставшихся во входных последовательностях. Добавляя его в результат, мы сохраняем отсортированный порядок и записываем ровно тот элемент, который должен идти следующим.

4

Завершение

В какой-то момент одна из входных последовательностей опустеет. Оставшиеся элементы другой уже отсортированы и не меньше последнего элемента, записанного в результат.

Поэтому можно целиком дописать оставшийся хвост. В результате каждый входной элемент встречается ровно один раз, а вся последовательность отсортирована. Значит, операция слияния корректна.

Сортировка слиянием

Сортировка слиянием рекурсивно использует операцию слияния. Сначала обе половины сортируются отдельно, и только затем сливаются.

Сортировка слиянием = разделить + отсортировать левую половину + отсортировать правую половину + слиянием

Реализация

Реализацию удобно разделить на две функции: одна сливает две отсортированные последовательности, другая выполняет рекурсивное разбиение.

1

Слияние двух отсортированных последовательностей

Шаг объединения: превратить две отсортированные последовательности в одну.

1def merge(left, right):
2 result = []

6 if left[i] <= right[j]:

8 i += 1

14 result.extend(right[j:])

Сложность

log₂ n

Сколько уровней слияния получается?

Сортировка слиянием делит массив пополам, пока каждый подмассив не будет состоять из одного элемента. При возврате из рекурсии одноэлементные массивы сливаются обратно уровень за уровнем.

Чтобы из одноэлементных массивов получить массив длины 8, нужны три уровня слияния: 1 → 2 → 4 → 8. Поскольку 2³ = 8получаем 3 = log₂ 8.

В общем случае

Если смотреть в сторону разбиения, рекурсия порождает подзадачи размеров

n → n / 2 → n / 4 → n / 8 → ··· → 1

После k делений пополам размер подзадачи равен n / 2k. До одного элемента мы доходим, когда

n / 2k = 1
2k = n
k = log₂ n

Следовательно, уровней слияния log₂ n при условии, что n — степень двойки. Для произвольного n, число отличается не более чем на один уровень, поэтому асимптотически равно Θ(log n).

Σ

Сколько работы выполняется на одном уровне слияния?

На любом фиксированном уровне слияния подмассивы не пересекаются и вместе содержат все n элементов исходного массива.

Например, на одном уровне могут сливаться четыре блока размера n / 4, на другом — два блока размера n / 2а на последнем уровне получается один блок размера n. Размеры блоков меняются, но их суммарный размер на каждом уровне остаётся равен n.

Поскольку слияние работает линейно по числу сливаемых элементов, суммарная работа на каждом уровне равна Θ(n).

Устойчивость и память

Устойчивость

Сортировка слиянием может быть устойчивой. В приведённой функции merge при равенстве значений сначала выбирается элемент из левой последовательности, потому что условие использует <=.

Левая последовательность содержит элементы, которые в исходном массиве стояли раньше. Поэтому выбор слева при равенстве сохраняет их взаимный порядок.

Дополнительная память

Реализация на массивах создаёт временные последовательности при слиянии. Максимальный объём дополнительной памяти в один момент равен Θ(n).

Глубина стека рекурсии равна Θ(log n), что меньше, чем Θ(n) памяти для слияния.

⇄

Важный компромисс

В отличие от простых квадратичных сортировок из предыдущих разделов, сортировка слиянием гарантирует Θ(n log n) времени работы. Цена этой гарантии — дополнительная память для слияния.

Задачи

1

Слейте две последовательности

Слейте [1, 4, 7] и [2, 3, 8] вручную.

Получится последовательность [1, 2, 3, 4, 7, 8]. Элементы выбираются в порядке 1, 2, 3, 4, 7 и затем 8.
2

Глубина рекурсии

Если вход содержит 16 элементов, сколько раз можно делить размер задачи пополам, прежде чем получатся подмассивы длины 1?

Четыре деления пополам: 16 → 8 → 4 → 2 → 1. Значит, дерево рекурсии имеет Θ(log₂ 16) = Θ(4) нетривиальных уровней разбиения.
3

Устойчивость

Почему замена left[i] <= right[j] на left[i] < right[j] может сделать реализацию неустойчивой?

При равных значениях строгое сравнение сначала выбирает элемент из правой последовательности. В исходном массиве он стоял позже, поэтому равные элементы могут поменять взаимный порядок.
4

Максимальное число сравнений при одном слиянии

Две отсортированные последовательности имеют длины p и q. Каково максимальное число сравнений, необходимое для их слияния?

Не более p + q − 1. В худшем случае ни одна последовательность не опустеет, пока суммарно не останется один элемент; его можно дописать без дополнительного сравнения.
