Chapter 1

Introduction to Algorithms

Before comparing algorithms, we need a language for saying what they cost. This chapter introduces the basic model: input size, elementary operations, running time, memory, and asymptotic growth.

Time

Count how the amount of work grows with the size of the input, rather than timing one particular computer.

Space

Track how much additional memory an algorithm needs, including temporary arrays and recursion stacks.

Growth

Use asymptotic notation to separate the essential growth rate from machine-dependent constants and lower-order terms.

What do we analyze?

An algorithm is a finite procedure that transforms an input into an output. Correctness answers whether the output is right; complexity asks how many resources the procedure needs as the input becomes larger.

Input size

We describe the size of an instance by one or more parameters. For an array this is usually its length n. For a graph we often use both the number of vertices n and edges m. For an integer problem, the relevant size may be the number of bits needed to encode the integer rather than the numeric value itself.

Resource functions

T(n) denotes the amount of work for inputs of size n; S(n) denotes memory consumption. These are mathematical functions that summarize algorithmic behavior.

The exact function may depend on the particular input, which is why we later distinguish best, average, and worst cases.

A simple computation model

To compare algorithms independently of hardware, we agree on a simplified machine model. In the usual RAM-style model, elementary operations on machine-sized values take constant time.

Typical constant-time operations

We count a small set of basic operations as one unit of work. This abstraction is not a claim that every CPU instruction literally takes the same number of nanoseconds; it is a mathematical model for comparing growth rates.

The model matters

An operation that is constant-time for a fixed-width integer may not be constant-time for an arbitrarily large integer. Complexity statements are meaningful only together with the model and the input-size convention being used.

Running time: best, average, and worst case

Two inputs of the same size can make the same algorithm do different amounts of work. We therefore specify which case we are analyzing.

Best case

The minimum work among all inputs of size n. It describes the most favorable input, but it is rarely enough to guarantee performance.

Average case

The expected work under an explicit probability distribution on inputs. Without a distribution, “average” is not mathematically defined.

Worst case

The maximum work over all inputs of size n. It gives a guarantee that no input of that size can force more work than the bound.

Worst-case analysis is especially common because it gives a robust upper guarantee and does not require assumptions about how inputs are distributed. Average-case and randomized analyses are equally important when their probabilistic assumptions are clear.

Asymptotic notation

Asymptotic notation describes how functions grow for sufficiently large inputs. It deliberately ignores constant factors and lower-order terms so that the main rate of growth becomes visible.

O

Upper bound

f = O(g) means that eventually f is at most a constant multiple of g.

Ω

Lower bound

f = Ω(g) means that eventually f is at least a positive constant multiple of g.

Θ

Tight bound

f = Θ(g) means that f is bounded above and below by constant multiples of g.

o

Strictly smaller order

f = o(g) means that f/g → 0: f grows asymptotically strictly slower.

ω

Strictly larger order

f = ω(g) means that f/g → ∞: f grows asymptotically strictly faster.

O

Formal definition. There exist constants c > 0 and n₀ such that for all n ≥ n₀, 0 ≤ f(n) ≤ c·g(n)

Ω

Formal definition. There exist constants c > 0 and n₀ such that for all n ≥ n₀, 0 ≤ c·g(n) ≤ f(n)

Θ

Formal definition. There exist constants c₁,c₂ > 0 and n₀ such that for all n ≥ n₀, 0 ≤ c₁g(n) ≤ f(n) ≤ c₂g(n)

o

Equivalent limit test. For positive g(n), f(n) = o(g(n)) ⇔ lim f(n)/g(n) = 0

ω

Equivalent limit test. For positive g(n), f(n) = ω(g(n)) ⇔ lim f(n)/g(n) = ∞

Example

Let f(n)=7n³+100n²−20n+6. Then f(n)=Θ(n³). It is also true that f(n)=O(n⁴), but that upper bound is looser and therefore less informative.

The base of the logarithm usually does not matter asymptotically

Because logₐn = log_b n / log_b a, changing the base multiplies the logarithm by a constant. Therefore all constant logarithm bases belong to the same Θ(log n) class.

Practical rules for asymptotic analysis

Most hand analyses reduce to a small set of operations on growth rates.

3n² + 20n + 7 → Θ(n²)

Ignore constant factors and lower-order terms when identifying a tight asymptotic class.

Θ(f) + Θ(g) = Θ(max(f,g))

Sequential phases add. The asymptotically dominant phase determines the total when all terms are nonnegative.

n repetitions × Θ(f(n))

Nested or repeated work multiplies when each iteration performs the inner cost.

n → n/2 → n/4 → … → 1

Repeated halving produces Θ(log n) levels, the pattern behind binary search and many divide-and-conquer recurrences.

Be precise about the symbol

If an algorithm takes exactly quadratic order in the worst case, Θ(n²) is more informative than O(n²). Big O alone states an upper bound; it does not automatically mean “the exact complexity.”

Space complexity

Asymptotic notation applies to memory just as it applies to time. The important distinction is between the input itself and memory allocated in addition to that input.

Total space

All memory occupied during execution, including the representation of the input. If an array of n numbers is already part of the input, storing that array contributes Θ(n) to total space.

Auxiliary space

Additional working memory beyond the input: temporary arrays, hash tables, heaps, recursion stacks, and other scratch storage. An in-place algorithm aims for O(1) or very small auxiliary space.

Recursion counts too

A recursive algorithm that creates no explicit arrays can still consume memory through its call stack. A recursion depth of d generally contributes O(d) stack frames.

Time–space trade-offs

More memory can make an algorithm faster: a hash table may replace repeated searching; a memoization table can avoid recomputation. Conversely, an in-place method may save memory at the cost of more complicated or slower operations.

Common pitfalls

×

“O means exact complexity.” No. O is an upper bound and may be loose. Θ is the usual notation for a tight asymptotic bound.

×

“Worst case and Big O are the same thing.” They are different concepts. Worst case chooses a function over inputs; O then describes an asymptotic upper bound on that function.

×

“Constants never matter.” They absolutely matter in real programs and for small inputs. Asymptotic analysis intentionally answers a different question: how performance scales as the input grows.

×

“Only time matters.” Memory, I/O, communication, cache behavior, and other resources can dominate in practice. This handbook will track auxiliary space alongside running time whenever it matters.
